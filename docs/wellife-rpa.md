# 웰라이프 전용 RPA — 진행 방식과 구현

관문: `docs/superpowers/specs/2026-10-07-wellife-gate-design.md` - 섹션은 에이전트가 쓴다, 업체코드에 wellife 또는 관리 화면에서 연 업체만.

작성 2026-10-07 · 고침 2026-10-13 · 상태: **리허설 / 1건 / 실행 모드** (설정 `SalesMode`·`Mode`·`SapMode`·`WmsMode`·`InvoiceMode` 로 모듈마다 정한다. 빠지면 리허설)

## 1. 요약

- 오토파일럿(여러 업체가 함께 쓰는 제품, 예전 이름 AFTER MARKET RPA)에 **웰라이프 업체 전용 업무를 덧붙인다.** 이미 있는 루틴과 다른 업체의 동작은 바꾸지 않는다.
- 갈래는 **설정 파일 한 곳**에서 정한다. 웰라이프 PC 의 `RPA_UserConfig.json` 에만 `"Wellife"` 섹션을 둔다. PROCESS 오토파일럿(`ERPia_RPA.exe`, 예전 이름 루틴 RPA)은 시작할 때 업체 정책(관리 화면에서 웰라이프로 연 업체)과 이 섹션이 함께 있으면 웰라이프 실행으로, 둘 다 없으면 지금 PROCESS 그대로 돈다. 둘이 어긋나면 아무것도 하지 않고 멈춘다 (관문).
- 데이터를 바꾸는 단추는 설정의 **모드**로 정한다 (사용자 10-08). 모듈마다 키가 따로다 (10-13).

  | 키 | 모듈 | 누르는 것 |
  |---|---|---|
  | `SalesMode` | ② 주문매핑 | 엑셀 업로드 |
  | `Mode` | ③ 물류대기 | 저장 |
  | `SapMode` | ④ SAP 연동 | [지정]·화살표 |
  | `WmsMode` | ⑤ WMS 이관 | 화살표 |
  | `InvoiceMode` | ⑥ 운송장번호 전송 | [전송요청(S)] (택배사로 나가 되돌릴 수 없다) |

  키가 빠지면 리허설이다. 다른 키를 따르지 않는다 - 10-13 전에는 `Mode` 가 ③④⑤ 를 함께 정했으므로, 옛 설정의 `"Mode": "실행"` 은 이제 ③ 만 실행이다.
  - **리허설**(기본): 누르지 않고 마우스만 올린다. [지정] 은 옆 ▼ 로 내림 메뉴만 열고 '선택 항목만' 에 마우스를 올린다.
  - **실행**: 실제로 누르고, 뜨는 팝업은 [예](없으면 [확인])를 누른다. [아니오] 가 함께 있어도 [예] 다. 팝업 문구는 모두 로그와 모듈 사유에 남긴다.
  - **1건** (실데이터 시험용, 10-13): 실행과 같되, 전체 체크하는 자리에서 맨 위 첫 줄 하나만 체크해서 넘긴다. 전체를 넘기면 다음 시험까지 데이터가 다시 쌓이기를 오래 기다려야 하기 때문이다.
    - 그 자리: ③ 물류대기 저장, 4-1 지정, 4-3, 5-1~5-3, ⑥ 전송요청.
    - 4-2 는 검토 칸이 빈 줄 중 위에서 처음 만난 한 줄만 넘긴다.
    - 체크 칸이 없는 4-4 SO생성·5-4 API대기 는 실행처럼 누른다. 그 단계의 건이 모두 넘어간다 (사용자 10-13).
    - 체크하기 전에 보이는 줄에 이미 체크된 것이 있으면 누르지 않는다. 누른 뒤에는 그 한 줄만 '선택' 인지 다시 본다.
    - ② `SalesMode` 는 줄이 없어 '1건' 을 쓸 수 없다 (설정 오류).
  - 모드는 대시보드·웹의 단계 이름 앞 `[리허설]`/`[1건]`/`[실행]`, 모듈 사유 앞, 시작 로그의 별표 줄로 보인다. 웹 환경설정의 '실행 모듈' 카드에도 다섯 모드가 보인다 - **보기만** 한다 (시험 기간용, 10-13. 바꾸기는 PC 설정 파일).
- ② 주문 수집: 미리 둔 엑셀이 있을 때만 올린다. 자동 수집 [가져오기] 는 모드와 상관없이 누르지 않는다. 선택주문 매출처리는 하지 않는다.
- ③ 물류대기: 일반 탭 조회 → 전체선택 → 저장 (보류는 하지 않는다).

## 3. 실행 순서

### 3.1 시작 — 고치지 않은 지금 경로

```
웹 [PROCESS]·[전체 실행] / 예약 줄·반복 시간대     PC 에서 직접
  → 이 PC 의 에이전트가 명령을 받음              Run_All.bat 또는 ERPia_RPA.exe
  → rpa_dashboard.launch
       1PC 1프로그램 잠금 확인
       남은 토큰 확인 (0 이하면 거절)
  → ERPia_RPA.exe  ([전체 실행]·'전체' 예약 줄이면 Run_All.bat: 옵저버 → PROCESS)
  → run_routine.main
       정책 켬 + "Wellife" 섹션 → wellife.run_main   (아래 3.2)
       정책 끔 + 섹션 없음      → 지금 PROCESS 그대로
       어긋남                   → 멈춤 (관문)
```

- 갈래를 `main` 안에서 고르므로 예약·웹 단추·`Run_All.bat`·에이전트는 고치지 않는다.
- 실행 기록은 지금처럼 program `"routine"` 으로 남는다. 그래서 1PC 1프로그램 잠금, 웹 현황, 토큰이 지금 규칙대로 동작한다.
- 모듈별 실행 (10-08 사용자): 예약 줄이 모듈을 고르면(`RPA_RUN_MODULES`) 웰라이프 실행도 `Wellife` 섹션의 켬·끔 대신 그 모듈만 돈다 - 기존 루틴과 같은 규칙. 그래서 ② 주문매핑·③ 물류대기·④ SAP 연동·⑤ WMS 이관을 줄마다 따로 띄울 수 있다. 모드(`SalesMode`·`Mode`·`SapMode`·`WmsMode`·`InvoiceMode`)는 늘 섹션에서 읽는다. '전체' 줄과 웹 [PROCESS] 는 지금처럼 섹션에서 켠 모듈을 돈다.
- ① 웰라이프 사이트 엑셀 받기는 아직 없다. 전체 실행이면 옵저버가 먼저 돌지만, 웰라이프 사이트는 붙이지 않았다.
- ⑤ 는 반복 시간대로 돌린다 (7절).

### 3.2 `wellife.run_main`

1. 실행 기록을 연다: 제목 '웰라이프 실행 [주문매핑 … / 물류대기 … / SAP 연동 … / WMS 이관 … / 운송장 전송 …]' (모듈마다 모드), 단계 16개, 모듈 6개 (웹 현황에 이 단계들이 보인다).
2. 업체코드·아이디를 현황에 적는다 (비밀번호는 읽지 않는다).
3. `"Wellife"` 스위치를 읽는다. 값이 잘못됐으면 '설정 파일 오류'로 끝낸다. 예약 줄이 모듈을 골랐으면(`RPA_RUN_MODULES`) 켬·끔은 그 값을 쓴다 (모드는 섹션).
4. 윈도우 화면이 잠겨 있거나 ERPia 가 둘 이상 떠 있으면 아무것도 누르지 않고 끝낸다.
5. 기존 `run_modules` 에 웰라이프 모듈 표를 넘겨 모듈을 차례로 돌린다. 규칙은 기존 그대로다.
   - 끈 모듈은 '설정에서 끔'으로 표시하고 건너뛴다. 모듈을 고른 예약 줄이 띄운 실행이면 섹션 대신 줄이 고른 모듈만 돌고, 나머지는 '이번 실행에서 안 고름' 으로 보인다 (7절).
   - 로그인을 끄면 이미 떠 있는 ERPia 에 붙는다.
   - `failed`·`stopped` 가 나오면 뒤 모듈을 돌리지 않는다. `done`·`no_target`·`skipped` 는 계속 간다.
6. 실행 기록을 닫는다 (전체 결과와 사유).

### 3.3 모듈 차례

| 순서 | 모듈 | 하는 일 (지금) | 멈추는 경우 |
|---|---|---|---|
| 1 | 로그인 | ERPia 를 띄운다(떠 있으면 그대로) → 로그인 창이면 업체코드·아이디·비밀번호 입력 → 좌측 메뉴가 보이는 메인 창을 잡는다 (기존 `module_login`) | 로그인 실패, 메인 창을 못 잡음 |
| 2 | ② 주문매핑 | 화면 이동 → 엑셀: `ERPIA_AI_EXCEL` 에 `(사이트코드)~.xlsx` 가 있으면 기존 `run_excel_upload_step` 으로 올린다 (리허설은 업로드 칸에 마우스만) → 자동 수집 [가져오기] 는 마우스만 | 이동 실패, 사이트 그리드 없음 |
| 3 | ③ 물류대기 | 화면 이동 → 일반 탭 '조회(F)' → 머리글로 전체선택 → '저장(S)' (리허설은 마우스만). 0건이면 저장하지 않는다 | 아이콘 없음, 이동 실패, 조회가 안 끝남, 팝업 |
| 4 | ④ SAP 연동관리 | 화면을 연다 (이미 열려 있으면 그 탭, 아니면 메뉴 검색) → 4-1 → 4-2 → 4-3 → 4-4 (3.4) | 화면을 못 엶, 조회가 안 끝남, 팝업, 잠김 |
| 5 | ⑤ WMS 이관관리 | 화면을 연다 (같음) → 5-1 → 5-2 → 5-3 → 5-4 (3.4) | 같음 |
| 6 | ⑥ 운송장번호 전송 | 화면을 연다 (열린 탭, 아니면 좌측 아이콘) → 조회 → 전체 체크 → [전송요청(S)] (9.2) | 아이콘 없음, 이동 실패, 조회가 안 끝남, 팝업, 잠김 |

### 3.4 단계 안의 순서 (④⑤)

**4-1 매출전표 지정 → 4-2 넘기기**
1. [매출전표] 단계를 조회한다 (4.4절). 0건이면 다음 단계로 간다.
2. 머리글 체크 칸으로 전체 체크한다.
3. [지정] 옆 ▼ 를 눌러 내림 메뉴를 열고 '선택 항목만' 을 누른다 (리허설은 마우스만 올리고 ESC 로 닫는다. 메뉴 창이 사라지지 않거나 확인할 수 없으면 멈춘다). 실행은 전체 체크가 안 됐으면 누르지 않고 이 단계를 끝낸다.
4. 그리드를 위에서부터 한 번만 내려가며, 줄마다 검토 칸을 읽는 대로 체크를 맞춘다 - 빈 칸이면 체크, 아니면 풀기. 다 읽고 다시 올라가 체크하지 않는다. 시작할 때 보이는 줄이 모두 체크돼 있으면 머리글을 한 번 눌러 전체를 풀고, 넘길 줄만 하나씩 누른다.
5. 화살표 `btn_FirstSend` (리허설은 마우스만). 실행은 넘길 줄이 있고, 모든 줄의 체크를 맞췄을 때만 누른다 - 못 맞춘 줄이 있으면 검토에 문제가 있는 전표가 넘어갈 수 있다.

**4-3·4-4, 5-1~5-4** (같은 틀)
1. 단계를 조회한다.
2. 건수가 있고 체크 칸이 있는 단계면 머리글로 전체 체크한다.
3. 리허설은 화살표에 마우스만 올린다. 실행은 대상이 있고(체크 칸이 있는 단계는 전체 체크가 됐고) 단추가 켜져 있을 때만 누르고, 팝업을 [예]/[확인] 으로 넘긴다.

체크는 되돌리지 않는다. 다음 단계를 조회하면 풀린다.

단계 단추·체크 칸·▼·탭·메뉴 항목을 누르기 직전마다 화면 잠김·ERPia 포커스와, 누를 자리를 다른 창이 덮고 있지 않은지 확인한다. 팝업은 단계 단추·체크 칸·▼ 앞과 조회 뒤에 본다 (4.5절). 그리드 스크롤 단추와 머리글 전체 체크는 기존 도우미가 누르므로, 넘기기 전에 잠김·포커스만 한 번 본다.

### 3.5 끝

- 모듈마다 결과와 사유가 남는다. 리허설이나 할 것이 없으면 `skipped`(토큰 0), 실행 모드에서 실제로 누른 것이 있으면 `done` 이다.
- 사유 예 (10-07 실행을 지금 형식으로): `[리허설] 누르지 않음: 매출전표 201건 / 넘길 줄 0 / 4-3 선분할 배송정보 0건 / 4-4 SO생성 0건`
- 실행 모드에서는 '마우스만 올리는 자리'를 누르고, 뜨는 팝업을 [예]/[확인] 으로 넘긴다 (4.5절 '실행의 팝업').

### 3.6 실행 방법

**설치한 프로그램·웹 (운영)**
1. 이 변경을 upstream `develop` 에 병합한 뒤 저장소 관리자에게 버전 업데이트를 요청한다 (README '버전 업데이트' - 버전 빌드 → 내보내기 → 관리 화면 [업데이트] 는 저장소 관리자만 한다). 빌드는 전체 빌드다 (`tools\build_release.py`). `perform_login` 이 바뀌어 `Prepare_RPA.exe` 도 바뀌므로 `--exes-from` 은 쓰지 않는다. `wellife.py` 는 `run_routine` 이 import 하므로 `ERPia_RPA.exe` 에 저절로 들어간다.
2. 관리 화면 [업데이트] 로 웰라이프 PC 에 새 버전을 보낸다 (자동 업데이트가 없던 옛 버전 PC 는 처음 한 번 새 설치 파일로 덮어 설치한다). 설정 파일은 그대로 남는다. 웹에서 그 PC 의 버전이 새 버전인지 확인한다.
3. 관리 화면에서 그 업체를 웰라이프로 연다 (업체코드에 `wellife` 가 있으면 저절로). 에이전트가 정책을 PC 에 적고 `RPA_UserConfig.json` 에 `"Wellife"` 섹션(4.2절 - 로그인·주문매핑만 켬, 모드는 모두 리허설)을 만든다. 업체를 닫으면 섹션도 지운다.
   - 섹션을 손으로 넣지 않는다. 정책이 없는 PC 에 넣으면 PROCESS 가 '이 업체는 웰라이프 실행이 열려 있지 않습니다' 로 멈춘다. 모드를 바꿀 때만 섹션 안의 값을 고친다 (관리자 권한 메모장, UTF-8).
   - 이름은 대소문자까지 `Wellife` 로 쓴다. 나머지 값(잠긴 비밀번호 포함)은 건드리지 않고, 다른 PC 의 파일을 복사해 오지 않는다.
   - `Routine` 은 `Login` 만 `Y`, 나머지는 `N` 으로 두고, 웹의 '실행 모듈' 스위치로도 켜지 않는다. 갈래가 빗나가도(옛 exe, 이름 오타, 설정 파일을 세 번 다 못 읽음) 기존 루틴이 데이터를 바꾸지 않게 하는 안전망이다 (`Routine` 에 없는 키는 켬으로 읽힌다).
   - 이 안전망은 모듈을 고른 예약 줄과 반복 시간대에는 듣지 않는다. 그 실행에서 루틴은 `Routine` 대신 줄이 고른 모듈(`RPA_RUN_MODULES`)을 돌린다. 그래서 줄 고르기·반복 시간대는 웰라이프 PC 가 이 버전으로 업데이트된 뒤에 넣는다 - 웰라이프 갈래가 없는 옛 exe 는 주문매핑·물류대기를 고른 줄에서 기존 루틴의 매출처리·물류대기를 돈다 (SAP 연동·WMS 이관만 고른 줄은 '이번 실행 모듈이 비었습니다' 로 멈춘다). 총괄이 업체 모듈 정책에서 주문매핑·물류대기를 꺼 두면, 그 모듈은 예약 줄과 웹 '실행 모듈' 에서 빠진다.
   - 새 버전이 깔리기 전에 섹션만 넣으면, 옛 exe 는 섹션을 무시하고 기존 루틴을 돈다. 순서를 지킨다. 업데이트가 되돌려지거나 [이전 버전으로 되돌리기] 를 눌러도 옛 exe 가 된다 - 그래서 위 안전망을 늘 둔다.
4. 웹에서 [PROCESS] 를 누른다. [전체 실행]과 '전체' 예약 줄은 옵저버가 먼저 돈다. `Run_All.bat` 이나 `ERPia_RPA.exe` 를 직접 실행해도 웰라이프로 간다.
5. 확인: `%ProgramData%\AFTER MARKET\RPA\data\run_routine_result.txt` 첫머리에 `=== 웰라이프 실행 시작` 이 있다. 웹에는 'PROCESS 오토파일럿' 으로 보이고, 단계 목록은 웰라이프 단계다.

**소스로 시험 (빌드 전)**

```
set RPA_PROGRAMDATA=<시험 폴더>\pd
set RPA_USER_CONFIG=<시험 폴더>\pd\config\RPA_UserConfig.json
set RPA_STATUS_DIR=<시험 폴더>\status
.venv\Scripts\python.exe run_routine.py
```

- 시험 설정에는 `LogIn`(개발기 계정), `ERPia`(ExePath), `Routine`(모두 `N`), `Wellife` 섹션을 둔다. `<시험 폴더>\pd\config` 폴더가 있어야 한다.
- 환경변수 없이 돌리면 이 PC 에 설치한 프로그램의 설정·기록을 쓴다. 웹과 8765 대시보드는 소스를 띄우지 못한다.

**지킬 것**
- 화면을 잠그지 않는다. ERPia 는 하나만 띄우거나 띄우지 않는다.
- 로그인 계정의 ERPia 에 '웰라이프 SAP 연동관리'·'웰라이프 WMS 이관관리' 메뉴가 있어야 한다. 없으면 ④⑤ 가 화면을 못 열어 멈춘다.
- ERPia 와 RPA 의 권한을 맞춘다. 관리자 권한으로 띄운 ERPia 는 일반 권한 RPA 가 화면을 읽지 못한다 (10-07 실측).
- 도는 동안 마우스와 키보드를 쓰지 않는다.
- 웰라이프 업체의 웹 '실행 모듈' 스위치는 `Wellife` 섹션에 쓴다(에이전트). 예약 줄의 모듈 단추는 사이트 수집·주문매핑·물류대기·SAP 연동·WMS 이관·운송장 전송이다 (물류관리·운송장 출력 없음). 토큰 예상은 웰라이프 업체면 `Wellife` 섹션·줄의 모듈을 이력 키(`wellife_sales`·`wellife_sap` 등, 로그인은 `login`, 모든 업체용 운송장번호 전송은 `invoicesend`)로 센다 - 업체 배율이 같은 키에 걸린다 (`agent.history_key`).
- `ERPia_RPA.exe --check` 는 갈래 전에 끝나서 웰라이프 설정을 보여 주지 않는다.
- 설정 창의 '기존 설정값 가져오기' 와, 제거할 때 '설정과 기록도 지울까요?' 에 [예] 를 누르는 것은 `Wellife` 섹션을 지운다.

## 4. 구현

### 4.1 파일

| 파일 | 내용 |
|---|---|
| `wellife.py` (새) | 웰라이프 실행 전부: 갈래 판정, 스위치, 모듈 6개, 메뉴 검색 이동, SAP·WMS 단계 처리, 안전장치 |
| `run_routine.py` | `import wellife`, `main` 갈래 (4줄), `run_modules` 의 표 인자(없으면 지금 표), 비트 주석, `wait_login_or_main` 버그 수정 (5절) |
| `erpia_common.py` | 새 함수 `literal_keys`(키 입력 글자 그대로), `screen_locked`(윈도우 화면 잠김), `erpia_pids`(떠 있는 ERPia 목록) |
| `perform_login.py` | 로그인 버그 3건 수정 (5절: 입력 글자 그대로, 로그인 뒤 메인 창 판별, 숨은 로그인 창) |
| `tests/test_wellife.py` (새) | ERPia 없이 도는 시험 |

`wellife.py` 는 `run_routine` 을 import 하지 않는다. exe 에서 `run_routine` 은 `__main__` 이라, 다시 import 하면 사본이 생겨 결과 로그를 지운다. 그래서 `run_routine` 이 자기 모듈을 넘겨준다.

### 4.2 설정

```json
"Wellife": {"Login": "Y", "Sales": "Y", "Hold": "Y", "Sap": "Y", "Wms": "Y", "InvoiceSend": "Y",
            "SalesMode": "리허설", "Mode": "리허설", "SapMode": "리허설", "WmsMode": "리허설", "InvoiceMode": "리허설"}
```

- 모드 값: `"리허설"`·`"1건"`·`"실행"` (`SalesMode` 는 `"리허설"`·`"실행"` 만). 빠지면 리허설이다. 다른 값이면 설정 오류로 멈추고 아무것도 하지 않는다.
- 모드는 기본 리허설이다 (사용자 10-13): 에이전트가 섹션을 만들거나 웹 '실행 모듈' 로 바꿔 쓸 때 빠진 모드 키를 `"리허설"` 로 적어 둔다 (`rpa_status._merge_routine_section`). 적혀 있던 값은 바꾸지 않는다.
- 바꾸는 곳은 그 PC 의 `%ProgramData%\AFTER MARKET\RPA\config\RPA_UserConfig.json` 뿐이다 (관리자 권한 메모장, UTF-8 로 저장). 웹은 보기만 한다. 다음 실행부터 적용된다.
- 대시보드 단계 이름 앞에 그 모듈의 모드 표시(`[리허설]`/`[1건]`/`[실행]`)가 붙는다. 로그인 단계는 `Mode` 를 따른다 (표시만).

- **적힌 `Y` 만 켬, 빠진 키는 끔** (`Routine` 섹션과 반대). 잘못 들어간 빈 섹션이 매출처리·저장을 켜지 않게 한다.
- Y/N 이 아닌 값이면 설정 오류로 멈추고 아무것도 하지 않는다.

### 4.3 모듈

| 모듈 키 | 설정 키 | 단계 | 비트 | 지금 하는 일 |
|---|---|---|---|---|

| `wellife_sales` | Sales | ② | 32 | 주문매핑 이동, 엑셀 업로드 |
| `wellife_hold` | Hold | ③ | 64 | 물류대기 조회·전체선택·저장 (아이콘이 없으면 건너뛰지 않고 실패) |
| `wellife_sap` | Sap | ④ 4-1~4-4 | 128 | 지정·화살표 |
| `wellife_wms` | Wms | ⑤ 5-1~5-4 | 256 | 화살표 (반복 시간대 대상) |

리허설이나 할 것이 없으면 모듈 결과는 `skipped`(건너뜀, 토큰 0)다. 실행 모드에서 실제로 누른 것이 있으면 `done` 이다.

### 4.4 화면을 다루는 방식 (개발기 실측 근거)

**이미 열린 화면** — 메뉴를 눌러도 그 탭으로 가지 않는다 (실측: 60초 기다리다 사람이 탭을 닫고 다시 열었다). 창 안에 보이는 같은 이름의 메인 탭이 있으면 그 탭을 누르고, 활성 메인 탭이 바뀌었는지 확인한다 (실측: 6초).

**메뉴 검색으로 화면 열기** — 업체전용 화면은 좌측 아이콘이 없다.
1. `sch_Menus` 를 클릭하고, 키보드 포커스가 검색 칸 안에 있는지 확인한다. 아니면 키를 보내지 않는다.
2. 메뉴명을 입력한다. 글자는 유니코드로 보내므로 한/영 상태와 상관없다.
3. 걸러진 `acd_Nav` 트리에서 **트리 안에 보이고 자리가 멈춘** `TreeItem` 을 누른다.
4. 같은 이름의 메인 탭이 활성인지 확인하고, 검색 칸을 비운다.

**컨트롤 찾기**
- 두 화면이 같은 auto_id(`btn_FirstSend`·`cbo_stage`·`gridCtrl_List` …)를 쓴다. 그래서 늘 그 화면의 폼(`Frm_Wellife_GetSend_*`) 안에서 찾는다.
- 숨은 화면은 창 밖 좌표에 있다. 창이 왼쪽 모니터에 있으면 좌표가 음수이므로, 늘 '지금의 창 사각형' 과 비교한다.

**단계 조회**
1. 대시보드 단추를 누른다.
2. `cbo_stage` 의 단계가 누른 단추의 단계가 될 때까지 기다린다. 0건 단계는 그리드 변화로 끝을 알 수 없어서 이 방식을 쓴다. 콤보는 줄인 이름일 수 있다 (실측: 단추 '선분할 배송정보' → 콤보 `단계 : 선분할`). 띄어쓰기·`/` 를 빼고 한쪽이 다른 쪽으로 시작하면 같은 단계로 본다. 이미 그 단계면 값이 그대로라 스피너가 뜨는지 2초 본다.
3. 그리드 스피너가 사라질 때까지 기다린다. 기준은 조회 전에 잰 '쉬고 있을 때의 오버레이 수'다 (SAP 화면은 2).
4. 팝업이 떠 있으면 멈춘다.
5. 단추 이름의 `(n)` 으로 건수를 읽는다.

**그리드**
- 셀 이름은 `<컬럼> 행 N` 이다. **N 은 스크롤해도 이어지는 절대 행 번호**다 (1~24 → 페이지 아래로 → 24~47).
- 끝까지 읽을 때는 스크롤바의 '페이지 아래로' 단추로 넘긴다. 키보드는 쓰지 않는다 (행이 선택되면 아래 그리드가 다시 조회된다).
- 넘긴 직후에는 앞 페이지가 그대로 읽혀 한 페이지를 건너뛸 수 있다 (실측: 201건 중 140~161행을 못 읽음). 첫 행 번호가 바뀌고 두 번 연속 같은 행들이 읽힐 때까지 기다린다. 내렸는데 첫 행이 그대로면 끝이다.
- 단추 건수와 그리드 줄 수는 다를 수 있다 (실측: 매출전표 단추 201건, 그리드는 198행에서 끝 - '아래로 선' 을 눌러도 더 내려가지 않는다). 이 차이는 무시하고 그리드 기준으로 한다 (10-07 결정). 중간 행을 못 읽었을 때만 '확인할 것' 으로 남긴다.
- 체크 칸은 `row Check Box` 이고 값은 `선택` / `선택안됨` 이다 (SAP·WMS 같음). 칸 전체가 그리드 안에 보일 때만 누르고, 값이 바뀌었는지 다시 읽어 확인한다.

**대상 고르기**
- 4-1: 머리글 체크 칸으로 전체 체크.
- 4-2: 검토 칸이 빈 줄 (`/` 로 나눈 토큰이 없는 줄).
- 4-3, 5-1~5-3: 머리글 체크 칸으로 전체 체크.
- 4-4, 5-4: 체크 칸이 없다.

[지정] 은 SplitButton `btn_CopyInsert` 이고, 내림 단추는 그 안의 `'오픈'` 이다 (실측: 본체 폭 73, '오픈' 폭 18 오른쪽 끝). 본체를 누르면 지정이 실행되므로 `'오픈'` 이 없거나, 크기가 없거나, 본체만큼 넓거나, 단추 오른쪽 절반 안에 있지 않으면 누르지 않는다. 내림 메뉴는 ERPia 의 별도 최상위 창이고 항목 '선택 항목만'(띄어쓰기 있음)은 Button 이다. 기존 `run_routine._find_menu_item` 으로 찾고, ESC 로 닫힌다 (실측).

### 4.5 안전장치

| 장치 | 내용 |
|---|---|
| 모드 | 리허설은 엑셀 업로드·저장·화살표에 마우스만 올리고(`hover`), [지정] 은 ▼ 로 내림 메뉴만 열고 항목에 마우스만 올린 뒤 ESC 로 닫는다 (`hover_menu_item`). 실행은 누른다 (`click`·`press_menu_item`). '1건' 은 실행과 같되 첫 줄 하나만 체크한다 (`check_one_row` - 이미 체크된 줄이 보이면 누르지 않고, 누른 뒤 한 줄만 체크됐는지 본다. 4-2 는 `mark_rows(limit=1)`). 자동 수집 [가져오기] 는 어느 모드에서도 누르지 않는다 |
| 실행의 팝업 | 누른 뒤 팝업을 [예](없으면 [확인]) 로 넘기고 문구를 로그·사유에 남긴다 (`confirm_popups`). 팝업도 스피너도 5초 없으면 끝이다. [예]/[확인] 이 없는 팝업, 10개를 넘는 팝업, 10분 안에 안 끝나는 처리는 멈춘다. 문구에 실패·오류·에러가 있으면 팝업은 넘기되 그 모듈을 멈춘다 (지정이 실패했는데 4-2 화살표를 누르지 않게). 팝업 단추도 다른 클릭처럼 잠김·포커스와, 그 자리의 맨 위 창이 ERPia 메인 창이나 그 팝업인지 본 뒤 누른다. 기존 루틴의 팝업 도우미([아니오] 를 고르는 것)는 쓰지 않는다 |
| 팝업 | 팝업이 뜨면 누르지 않고 멈춘다 (`no_popup`). 단계 단추·체크 칸·▼ 를 누르기 직전과 조회 뒤에 본다. ESC 는 ▼ 를 누르기 직전에 팝업을 본 뒤 보낸다 (항목을 못 찾은 경로는 ESC 직전에 한 번 더 본다). 실행 모드에서 누른 뒤 뜨는 팝업은 '실행의 팝업' 줄대로 넘긴다 |
| 누르기 직전 (`front`) | 윈도우 화면이 잠겼으면 멈춘다. ERPia 를 앞으로 가져오지 못하면 멈춘다. 좌표 클릭이 잠금 화면이나 다른 프로그램에 떨어지지 않게 한다 |
| 누를 자리 (`click`) | 누르기 전에 그 자리가 창 안에 보이고, 맨 위 창이 ERPia 메인 창인지 본다. 열린 내림 메뉴나 다른 프로그램 창이 덮고 있으면 누르지 않고 멈춘다. 확인한 그 점을 누른다 |
| 이미 열린 탭 | 탭 머리 전체가 창 안에 있고, 가운데를 히트테스트해서 그 탭이 맞을 때만 누른다 (탭바가 넘치면 가운데가 × 단추일 수 있다). 탭이 잘려 있으면 멈춘다 |
| 못 읽은 값 | 검토 칸을 못 읽은 줄(None)은 4-2 대상이 아니다 (빈 칸으로 보면 문제 있는 전표가 넘어간다) |
| 4-2 줄 맞추기 | 본 줄 중 체크를 못 맞춘 줄(잘린 칸·안 바뀜·중간에 빠진 번호)이 하나라도 있으면 화살표를 누르지 않는다. 페이지를 내렸는데 그리드가 움직이지 않거나 끝까지 못 가면 멈춘다 - 뒤 줄이 전체 체크된 채 넘어가지 않게 |
| 내림 메뉴 닫힘 | ESC 는 맨 앞 창이 ERPia 일 때만 보내고, 메뉴 창이 사라졌는지 창 핸들로 확인한다. 확인할 수 없으면 열린 것으로 보고 멈춘다 |
| 실행 첫머리 | 화면이 잠겨 있거나 ERPia 가 둘 이상 떠 있으면 실행하지 않는다 (어느 세션에 붙을지 모른다 - 10-07 에 다른 계정 ERPia 가 함께 떠 있었다). 설정은 세 번까지 읽어 본다 - 잠깐 못 읽은 웰라이프 PC 가 기존 루틴으로 새지 않게 |
| 화면 이동 전 | 앞 화면(③ 등)에서 뜬 팝업이 남아 있으면 탭·메뉴를 누르지 않고 멈춘다 |
| UI 오류 | Stop 이 아닌 예외(UIA 오류 등)도 그 화면의 실패로 남기고, 뒤 모듈을 돌리지 않는다 |
| 키 입력 | 포커스가 검색 칸 안일 때만 보낸다. `+ ^ % ~ ( ) { }` 는 글자 그대로 입력한다 |
| 사람이 보는 화면 | 단계 표에 넣지 않아 누를 길이 없다 |

**시험 격리**
- 시험은 소스로 돌린다. `RPA_PROGRAMDATA`·`RPA_USER_CONFIG`·`RPA_STATUS_DIR` 를 시험 폴더로 돌려, 설치한 프로그램의 설정·이력·토큰을 건드리지 않는다.
- 관문이 생긴 뒤로는 시험 상태 폴더(`RPA_STATUS_DIR`)의 `settings.json` 에도 업체 정책 `schedule.policy.wellife: true` 가 있어야 한다. 격리된 폴더에는 에이전트가 정책을 적지 않으므로, 없으면 "이 업체는 웰라이프 실행이 열려 있지 않습니다" 로 바로 멈춘다. 에이전트와 같은 모양으로 넣으려면 같은 환경 변수를 잡고 `rpa_dashboard.set_policy(한도, [], True)` 를 한 번 부른다.
- 시험 설정의 `Routine` 은 모두 `N` 으로 둔다. 갈래가 빗나가도 기존 루틴이 돌지 않게 하려는 것이다.
- 시험하는 동안에는 웹의 실행·종료 단추를 쓰지 않고, 자동 실행(예약 줄·반복 시간대)도 꺼 둔다. 설치한 프로그램의 에이전트는 격리된 시험 실행을 보지 못해, 예약 때가 되면 설치한 RPA 를 함께 띄운다.
- 시험이 끝나면 ERPia 를 닫는다.

## 7. 모듈별 실행과 ⑤ 반복 실행 (10-08)

SAP 에서 넘어온 건은 WMS 이관관리에 한꺼번에 들어오지 않고 하나씩 들어온다. 그래서 ⑤ 는 본 실행에 이어 한 번 돌리는 것으로는 부족하고, 시간대 동안 쉬는 시간을 두고 되풀이한다.

- 웹 환경설정의 예약 줄에서 모듈을 고른다. 웰라이프 업체의 단추는 사이트 수집·주문매핑·물류대기·SAP 연동·WMS 이관·운송장 전송이다. ⑥ 운송장 전송도 ⑤ 와 같이 반복 시간대로 돌릴 수 있다 (`RPA_RUN_MODULES=Login,InvoiceSend`).
  - 예: `09:00 주문매핑·물류대기·SAP 연동` (본 실행) + `09:30~18:00 반복 WMS 이관, 5분 쉬고 다시`
- 반복 시간대는 develop 의 시간대 반복을 그대로 쓴다. 회차가 끝날 때마다 쉬는 시간 뒤 다음 회차를 `ERPia_RPA.exe` 로 띄운다 (`rpa_dashboard.tick_repeat` → `launch_slot(trigger="repeat")`, `RPA_RUN_MODULES=Login,Wms`). 회차는 `run_routine.main` 의 갈래로 웰라이프에 온다.
- 회차 규칙도 develop 그대로다: 실패·중단이면 그 시간대 반복을 멈추고 [반복 다시 시작] 으로 잇는다 (화면이 잠긴 회차는 예외 - 아래). 처리한 것이 없는 성공 회차(⑤ 0건, 리허설)는 이력에 남기지 않는다 (`wellife.run_main` 끝맺음이 `main` 과 같다). 토큰은 `done` 모듈만 쓴다.
- 한 회차는 5-1~5-4 를 한 번씩 돈다. 앞 회차가 끝난 뒤에야 다음 회차가 뜨므로 회차가 겹치지 않는다.
- 막는 곳: PC(`rpa_dashboard.slot_off`)는 웰라이프 업체 줄에서 물류관리·운송장을, 그 밖의 업체 줄에서 SAP 연동·WMS 이관·운송장 전송(지금은 웰라이프만)을 뺀다. 에이전트(`set_schedule`)는 그런 줄을 거절하고, 웹은 그 단추를 보이지 않는다.
- 화면이 잠긴 회차는 아무것도 누르지 않고 끝나며, 그 회차만 건너뛴다. 반복은 쉬는 시간 뒤 다음 회차로 이어 가고, 이력에 남지 않는다. 웹 자동 실행 칸에 '화면 잠김으로 건너뜀 N회' 로 보인다 (`rpa_dashboard.locked_round` - 까닭 글의 '화면이 잠겨' 로 가린다). 사람이 띄운 실행·반복이 아닌 예약은 지금처럼 '중단' 으로 이력에 남는다.
- 시간대·쉬는 시간은 운영에서 정해 웹에서 넣는다.

1. 실행 모드 첫 실측 (승인 뒤, 먼저 '1건' 으로): 엑셀 업로드·물류대기 저장·지정·화살표·운송장 [전송요청(S)] 의 팝업 문구와 결과. 실행 모드는 아직 실제 ERPia 에서 돌려 보지 않았다. 운송장 전송은 택배사로 나가 되돌릴 수 없다 - 담당자와 정한 뒤에만.
2. ② 선택주문 매출처리는 범위 밖으로 두었다 (10-08). 필요해지면 정한다.
3. ⑤ 반복 실행의 실측 (7절 - 실행 모드에서 회차마다 들어온 건이 넘어가는지), 웹 카드·사용량·색인.
4. 버전 업데이트: PR 이 병합되면 저장소 관리자에게 요청한다 (버전 빌드 → 내보내기 → 관리 화면 [업데이트]). PR #4(모듈별 실행·반복)와 ⑥ 운송장번호 전송(10-13)은 웹 환경설정(`rpa-settings.js`·`rpa-common.js`)과 관리 화면(토큰 배율 표)도 바꿨으므로 웹 배포도 함께 한다. DB 규칙은 바뀌지 않았다.
5. 웹의 모드 보기는 시험 기간용이다 - 시험이 끝나면 걷어낸다 (9.3).

**정할 것**
- ⑥ 운송장 전송: 처리결과가 '배송장삭제' 인 줄도 함께 보내도 되는지 (지금은 전체 체크라 함께 간다). 조회 기간은 화면 기본값(10일 전~당일)을 그대로 쓴다 - 그보다 오래된 미전송 운송장은 보내지 않는다. 바꿀지 정한다.
- '확인할 것'(검토가 남은 줄, `[n]` 불일치, 넘어가지 않는 [확인] 팝업)을 어떻게 남기고, 뒤 단계를 계속할지.
- ②의 엑셀 업로드·가져오기 팝업에도 웰라이프 팝업 규칙을 적용할지.
- 반복 실행의 시간대·쉬는 시간, 본 실행 시각 (웹에서 넣는다).

### 9.2 동작 (`wellife.module_invoice_send`)

1. 화면 열기: '운송장번호 전송' 메인 탭이 이미 열려 있으면 그 탭을 누르고(SAP·WMS 와 같은 확인), 없으면 좌측 아이콘 `lcg_InvoiceSend` 를 누른다 (기존 `goto_screen_by_icon`). 아이콘이 없으면 건너뛰지 않고 실패다.
2. [조회(F)] (`btn_Search`). 조회 조건은 화면 기본값 그대로 둔다 (배송일 기간·미전송). 스피너가 사라질 때까지 기다리고, 팝업이 떠 있으면 멈춘다.
3. 줄 수를 센다 - 세로 스크롤바가 있으면 맨 위에서부터 '페이지 아래로' 로 넘기며 행 번호로 (키보드는 쓰지 않는다). 0줄이면 `no_target`.
4. 머리글 `row Check Box` 로 전체 체크 (기존 `check_all_rows`).
5. [전송요청(S)] (`btn_SendRequest`) - 기존 `press_arrow` 를 그대로 쓴다.
   - 리허설: 마우스만 올리고 단추가 켜져 있는지(누를 수 있는지) 로그에 남긴다. 결과 `skipped`.
   - 실행: 전체 체크가 됐고 단추가 켜져 있을 때만 누르고, 팝업은 [예](없으면 [확인]) 로 넘긴다. 실패·오류 문구가 있으면 멈춘다 (4.5절 '실행의 팝업'). 누르면 `done`.
   - 누르기 직전에 보이는 줄의 체크를 다시 읽어, 모두 '선택' 일 때만 누른다. 스피너가 늦게 떠 조회가 그제야 끝나면 그리드가 새로 그려져 체크가 풀리기 때문이다 (조회하면 체크가 모두 풀린다).
6. [미전송 완료처리]·[선택주문 알림톡대기 추가] 등 나머지 단추는 누르지 않는다. 체크는 되돌리지 않는다 (다음 조회로 풀린다).

사유 예: `[리허설] 운송장 3건 - 전송요청은 누르지 않음`, `[실행] 운송장 0건 - 전송할 것 없음`.

### 9.3 '모든 업체용' 분류와 여는 곳

- 화면 코드(`module_invoice_send`·`invoice_send`·`count_rows`)는 웰라이프 고유 값을 쓰지 않는다. `wellife.py` 의 안전장치(잠김·앞 창·덮인 자리·팝업)를 함께 쓰려고 거기 둔다.
- 모듈 키는 `invoicesend` (설정 키 `InvoiceSend` 의 소문자, `wellife_` 없음). `rpa_status.SHARED_MODULES` 에 있는 키는 `agent.history_key` 가 업체와 상관없이 같은 이력·토큰 키로 센다 - 나중에 모든 업체로 열어도 토큰 배율 키가 같다.
- **2026-10-13 모든 업체로 열었다** (사용자): 보통 PROCESS 의 `run_routine.ROUTINE_MODULES` 맨 뒤에 같은 키·비트(`invoicesend`, 512)로, `MODULE_FUNCS["invoicesend"]` 는 `run_routine.module_invoice_send` → `wellife.module_invoice_send`. 보통 PROCESS 도 모드가 있다 - `Routine` 섹션의 `InvoiceMode` (`"리허설"`·`"1건"`·`"실행"`, **빠지면 리허설**, 사용자 10-13. 그 전 빌드 2026.10.13-6 은 모드 없이 늘 실제로 [전송요청(S)] 을 눌렀다). 설치 틀(`RPA_UserConfig.template.json`)과 웹 '실행 모듈' 로 쓸 때 `"InvoiceMode": "리허설"` 을 적어 둔다. `rpa_status.ROUTINE_CONFIG_MODULES` 에 `InvoiceSend`, `rpa_dashboard.WELLIFE_ONLY_KEYS` 에서 뺌, 웹 `MODULES`·`RUN_CHIPS`, 관리 화면 토큰 배율의 PROCESS 묶음에도 같은 키 (로그인처럼 두 묶음에 같이). 웰라이프 업체는 그대로 `Wellife` 섹션·`InvoiceMode`.
- **칸이 없으면 끔** (`rpa_status.ROUTINE_OFF_BY_DEFAULT`, `perform_login.load_routine_modules(off_by_default=)`): Routine 섹션의 다른 모듈은 칸이 없으면 켬이지만, 운송장번호 전송은 택배사로 나가 되돌릴 수 없어 업데이트를 받자마자 모든 업체가 보내지 않게 했다. 업체 웹 환경설정 '실행 모듈' 에서 켠 PC 만 돈다.
- 모드 보기 (시험 기간용): 에이전트가 `Wellife` 섹션의 `SalesMode`·`Mode`·`SapMode`·`WmsMode`·`InvoiceMode` 를 `live.modes` 로 올리고(`rpa_status.read_wellife_modes`), 웹 '실행 모듈' 카드가 보여 준다. 실행이 하나라도 있으면 경고 색. 바꾸는 길은 없다 (PC 설정 파일). 옛 에이전트는 값을 안 올려 줄이 숨는다. 걷어낼 때는 `read_wellife_modes`·`WELLIFE_MODES`, 에이전트의 `snap["modes"]`, 웹의 `mod-modes` 를 지운다.
