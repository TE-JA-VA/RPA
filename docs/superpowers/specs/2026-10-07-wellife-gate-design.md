# 웰라이프 실행 관문 - 설계

**상태:** 2026-10-07 설계 (사용자와 문답으로 정함). PR #2 (`wellife.py`, 작업자 erpiaChang) 병합 뒤.

## 1. 목적

PR #2 의 웰라이프 실행(로그인 → 주문매핑 → 물류대기 → 웰라이프 SAP 연동관리 → 웰라이프 WMS 이관관리)은 지금 PC 의 `RPA_UserConfig.json` 에 `"Wellife"` 섹션이 있는지만 본다. 그래서

- 누구든 메모장으로 섹션을 넣으면 어느 업체에서나 웰라이프 순서로 돈다.
- 웰라이프 PC 에서 섹션이 지워지면 보통 루틴(물류관리·운송장 출력까지)이 웰라이프 ERPia 에서 돈다.

이 기능을 **특정 업체에만** 열고, 관리 화면 → 업체 웹 → 에이전트 → 루틴 실행까지 같은 규칙으로 막는다.

## 2. 정한 것 (사용자)

| 항목 | 결정 |
|---|---|
| 열리는 업체 | 업체코드(관리 화면의 cid)에 `wellife` 가 들어간 업체 - **대소문자 구분 없음** (`Wellife`·`wellife2`·`WELLIFE_seoul`) + 관리 화면에서 연 업체 |
| 웰라이프 업체가 쓰는 모듈 | 로그인 · 주문매핑 매출처리 · 물류대기 관리 · 웰라이프 SAP 연동관리 · 웰라이프 WMS 이관관리 |
| 웰라이프 업체가 못 쓰는 모듈 | 물류관리 · 운송장 출력 / 엑셀 생성 |
| 웰라이프의 물류대기 관리 | 다른 업체와 다르게 **보류처리 단계 없이 '전체 선택 → 저장' 만** (`wellife.py` ③ - 작업자 몫) |
| 일 나누기 | 관문·화면·에이전트·갈래는 우리, `wellife.py` 안은 작업자 (5절) |

## 3. 규칙 하나

```
웰라이프 업체 = ("wellife" in 업체코드.lower())  또는  meta/companies/{cid}/apps/rpa/features/wellife == true
```

- 새 자리 `features/wellife` (true 만 뜻이 있다, 없거나 false 면 업체코드 규칙만). 기존 모듈 정책 `modules` 는 "false = 끔, 없으면 켬" 이라 방향이 반대라 따로 둔다.
- 업체코드에 wellife 가 든 업체는 관리 화면에서 끌 수 없다 (늘 열림).
- 쓰는 곳 셋이 같은 규칙: 관리 화면(ops.js), 업체 웹(rpa-settings.js), 에이전트(agent.py). **실제로 막는 곳은 업체 PC** (에이전트·루틴) - 화면은 보이기만 바꾼다.

## 4. 고치는 곳

### 4.1 관리 화면 (AFTERMARKET_SETUP)
- 업체 상세 → 모듈 정책 상자에 체크 **"웰라이프 실행"**.
  - 업체코드에 wellife 포함: 체크된 채 잠김, 옆에 "업체코드에 wellife 포함 - 늘 열림".
  - 그 밖: 체크하고 [적용] (모듈 체크와 같은 [적용]).
  - 웰라이프 업체이면 물류관리·운송장 출력 체크는 잠그고 "웰라이프 업체는 쓰지 않음".
- `ops.companyDetail` 이 `features`·`wellife`(규칙 결과)를 돌려주고, `ops.setFeature(cid, "wellife", bool)` 이 쓴다 (기록 글 `웰라이프 실행 {cid} = 켬/끔`).

### 4.2 에이전트 (업체 PC)
- `company_policy` 가 규칙 결과도 돌려준다. 웰라이프면 안 쓰는 모듈에 `Logistics`·`Output` 을 더한다.
- PC 의 `settings.json` `schedule.policy` 에 `wellife: true/false` 를 함께 적는다 (껐다 켜도 마지막 값).
- 업체 웹에서 실행 모듈을 바꾸면 (`set_modules`): 웰라이프 업체는 `"Wellife"` 섹션(Login·Sales·Hold·Sap·Wms)을 쓰고, 아니면 지금처럼 `Routine`. 메모장 편집이 필요 없어진다.
- 웰라이프 업체가 처음 열렸는데 섹션이 없으면 **로그인·주문매핑 매출처리만 켬, 나머지(물류대기·SAP·WMS)는 끔** 으로 섹션을 만든다 (사용자: 아직 배포판을 주지 않아 그럴 일이 적다).
- 하트비트의 실행 모듈 값(`live.modules`)도 웰라이프 업체는 `Wellife` 섹션을 보낸다.
- 막힌 모듈(Logistics·Output)이 명령으로 와도 거절한다 (지금 모듈 정책과 같은 길).

### 4.3 루틴 갈래 (`run_routine.main`)
| PC 의 정책 `wellife` | `Wellife` 섹션 | 실행 |
|---|---|---|
| true | 있음 | 웰라이프 순서 |
| true | 없음 | 멈춤 - "웰라이프 설정이 없습니다 (에이전트가 다시 씁니다)" (보통 루틴으로 새지 않는다) |
| false | 있음 | 멈춤 - "이 업체는 웰라이프 실행이 열려 있지 않습니다 (관리 화면)" |
| false | 없음 | 지금 루틴 그대로 |

정책 값은 `rpa_status.read_settings()["schedule"]["policy"]["wellife"]` (에이전트가 적는다). 에이전트를 한 번도 안 돌린 PC 는 false.

### 4.4 업체 웹 (RPA 환경설정)
- 웰라이프 업체: 실행 모듈 상자에 다섯 모듈만 (로그인 · 주문매핑 매출처리 · 물류대기 관리 · 웰라이프 SAP 연동관리 · 웰라이프 WMS 이관관리). 물류관리·운송장 출력은 안 보인다. 시각별 모듈 고르기도 같은 다섯.
- 그 밖 업체: 지금 그대로 (웰라이프 모듈은 안 보인다).

### 4.5 시험
- 관리 화면 (check_admin): 잠긴 체크·[적용] 으로 켜기·끄기, DB 값.
- 에이전트 (test_agent): 규칙(대소문자·features), 정책에 Logistics·Output 더함, set_modules 가 Wellife 섹션에 씀, 막힌 모듈 거절.
- 루틴 갈래 (test_wellife 또는 새 시험): 위 표 네 칸.
- 업체 웹 (check_web): 웰라이프 업체의 모듈 다섯·숨김.
- 로그인 수정 두 갈래 (PR 검토에서 시험 없음): 재시도 때 숨은 창 제외, 메인 창이 먼저 뜨면 성공 - 가짜 창으로.
- 빌드 → 샌드박스 (기존 46줄).

## 5. 작업자 몫 (`wellife.py` 안 - 우리는 안 고친다)
- ③ 물류대기: 보류처리 없이 '전체 선택 → 저장'.
- 실제로 누르기 전에: 누를 줄의 전표번호 대조, 누르기 직전 그리드 전체 체크 상태 확인 (2026-09-16 엉뚱한 행 사고 부류).
- 시각별로 고른 모듈(`RPA_RUN_MODULES`) 따르기, 반복 실행의 빈 회차 기록 규칙, 토큰 모듈 이름과 웹의 비용 예상.
- 섹션 키(Login·Sales·Hold·Sap·Wms)를 바꾸면 우리 쪽(4.2·4.4)도 같이 바꿔야 한다 - 약속으로 문서에 남긴다.

## 6. 배포
- 업체 PC 코드(에이전트·루틴)가 바뀌므로 새 버전 빌드 → 샌드박스 → 내보내기·[업데이트] (저장소 관리자).
- 업체 웹이 바뀌므로 웹 배포. DB 규칙은 안 바뀐다 (`meta/companies/{cid}` 는 그 업체가 읽을 수 있고, 쓰기는 관리 도구만).
- 웰라이프 업체가 아직 옛 버전이면 관문이 없다 → 웰라이프 PC 에는 이 버전부터 깐다.

## 7. 하지 않는 것
- 웰라이프 순서 안의 화면 처리 (5절, 작업자).
- 다른 업체 전용 실행을 위한 일반 '업체 전용 기능' 틀 - 필요해지면 그때 (`features` 자리만 열어 둔다).
