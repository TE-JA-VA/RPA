# ACTOR 재생: 실패하기 직전에 AI가 막힌 단계를 풀어 기록으로 돌려놓기 (2026-11-16)

## 왜

- 기록(1, 2, 3… 단계)대로 재생하다 2단계에서 막히면 지금은 실패한다. 창 고쳐 잡기(`2026-11-16-replay-window-relocate-design.md`)까지 해도 대상을 못 찾으면 끝이다.
- 이 기능은 그 순간 AI가 2단계를 풀고 3단계부터 다시 기록대로 가게 한다.
- 사용자(2026-11-16): "'최후의 방어 옵션으로 AI를 쓸 수 있다'와 '여러 안전장치가 있지만 결국 화면을 못 찾으면 실패한다'는 큰 차이다."
- 바라는 결과:
  - 사이트가 바뀐 날에도 업체 수집이 멈추지 않는다.
  - 멈추더라도 무엇이 막았는지 사람 말로 알려 준다.
- 사업 면 (사용자): AI 기능을 부가 옵션으로 팔아 수익을 낸다. 업체에는 "쓰면 좋고, 안 쓰면 아쉬운 것"으로 가볍게 권한다.

## 정한 것 (사용자 결정 2026-11-16)

1. **ACTOR만.** PROCESS(ERPia)는 AI에 맡기지 않는다.
2. **화면은 Playwright로 읽는다.** agent-desktop은 쓰지 않는다.
3. **AI는 우리 회사의 Anthropic API 키로 부른다.**
   - 우리 코드가 Anthropic API를 바로 부른다. Claude Code 프로그램은 쓰지 않는다.
   - 업체는 Claude에 가입하거나 무엇을 깔 필요가 없다.
   - 약관: 우리 제품의 기능으로 우리 API 키를 쓰는 정상적인 개발자 방식이다. 업체 구독을 빌려 쓰는 방식은 Claude Code 약관상 회색 지대라 하지 않는다.
4. **AI를 쓸지는 우리가 정한다.**
   - 관리 화면의 '업체 관리'와 '신규 업체 등록'에 "AI 도움 사용" 단계를 둔다.
   - 업체 웹은 사용 여부와 안내만 보여 준다.
5. **과금은 월정액 부가 옵션 + 일정량을 넘으면 누진 구간별 추가 과금** (사용자 '나.' + 누진).
6. **AI가 하는 일은 두 가지다.**
   - **가. 대상이 바뀐 날** (단추 글·배치가 바뀜): 2단계 대신 누를(넣을·고를) 것을 고른다.
   - **나. 화면이 끼어든 날** (안내·공지·비밀번호 변경 안내 등): 그 화면을 **미루는 것만** 누른다. 예: [닫기], [다음에], [나중에], [90일 후에 보기], [오늘 하루 보지 않기], [건너뛰기]. 닫은 뒤 2단계를 기록대로 다시 찾는다.
7. **[확인] 하나뿐인 끼어든 화면은 안내문일 때만 누른다.**
   - 화면 글에 위험 낱말(아래 목록)이 없고, AI도 단순 안내라고 판단해야 한다.
   - 둘 중 하나라도 걸리면 누르지 않고, 사유를 남기고 실패한다.
8. **약관 동의·결제·신청처럼 업체가 원하지 않을 수 있는 것은 누르지 않는다.**
   - 미룰 수단이 없으면 실패한다.
   - 실패 사유에 무엇이 막았는지 남긴다. 예: "로그인 뒤 '약관 동의' 화면이 새로 생겼습니다. 미루기 단추가 없어 사람이 처리해야 합니다."
9. **소비자 개인정보는 가려서 보내고, AI가 처리한다고 업체에 알린다.**

## 안전장치

### AI는 고르기만 하고, 누르는 것은 재생기가 한다

- 재생기가 지금 열린 창들(안쪽 틀 포함)에서 누를 수 있는 요소를 모아 번호를 붙인다. AI는 그 번호 하나나 "없음"을 답한다.
- 답은 정해진 모양으로만 받는다 (API의 도구 호출 하나로 강제). 모양이 틀리면 "없음"으로 본다.
- AI에게는 화면을 바꿀 수단이 없다. 고른 번호를 재생기가 받아 아래 거르기를 지난 것만 누른다.

### 우리 코드가 AI의 고름을 다시 거른다

- **가.인지 나.인지는 우리 코드가 정한다.** AI가 무엇이라 답하든 아래처럼 정한다.
  - 고른 요소의 글이 미루기 낱말 목록에 있으면 미루기(나.)로 본다.
  - [확인]은 언제나 7번 조건으로 본다. 기록의 대상이 [확인]이었어도 같다.
  - 그 밖에는 대신 누르기(가.)로 본다.
- **고른 요소가 레이어·대화상자·기록에 없던 창 안에 있으면 그 안의 글도 본다.**
  - 그 안의 글에 위험 낱말이 있고 기록의 대상 글에는 그 낱말이 없으면 누르지 않는다. 대신 누르기·미루기 모두 같다.
  - "신청하시겠습니까?" 레이어의 단추를 어느 쪽으로 답해도 눌리지 않게 하려는 것이다.
- **미루기(나.)**: 고른 요소의 글이 미루기 낱말 목록에 있어야 한다. 없으면 누르지 않는다. AI가 [동의]를 골라도 눌리지 않는다.
- **대신 누르기(가.)**: 고른 요소의 글에 위험 낱말이 있는데 기록의 대상 글에는 없으면 누르지 않는다.
  - 예: 기록은 [주문조회]인데 AI가 [주문취소]를 고른 경우.
- **위험 낱말 (시작 목록)**: 동의, 결제, 구매, 주문하기, 삭제, 변경, 신청, 전송, 발송, 등록, 저장, 승인, 해지, 탈퇴, 취소, 출고, 확정.
  - 대신 누르기는 기록의 대상 글에 같은 낱말이 있으면 허용한다. 예: 기록이 [저장]이었으면 [저장하기]는 된다.
- **파일 받기 단계**: 지금의 '오늘 새로 생긴 것' 기준이 있으면, 그 기준 뒤에 새로 생긴 요소만 후보로 준다. 옛 파일을 받지 않게 하기 위해서다.
- **맡기지 않는 단계**:
  - 아이디·비밀번호(`credential`·`secret`)·인증번호(`otp`·`copyCode`·`copy`)
  - 메일 단계(`mailOpen`·`mailLink`·`mailSend`·`otpSend`·`pick`·`loose`)
  - 파일 올리기(`file`), 주소 이동·뒤로·새 탭
  - `optional`(없으면 건너뛰는 단계)과 마우스 올리기(`hover`)

### 헤매지 않는다

- **한 단계에 AI가 누르는 것은 3번까지다.** 미루기와 대신 누르기를 합친 수다. 그 안에 기록으로 돌아오지 못하면 실패한다.
- **사이트 한 번 재생에 AI를 부르는 것은 5번까지다.**
- **누른 뒤 이어졌는지 본다.**
  - 새 창을 여는 단계면 새 창이 뜬다.
  - 파일 받기면 파일이 온다 (지금 규칙 그대로).
  - 그 밖에는 다음 중 하나가 일어나야 한다:
    - 다음 단계의 대상이 보인다
    - 주소가 바뀐다
    - 새 창이 뜬다
    - 고른 요소가 든 레이어가 사라진다
  - 안 일어나면 `AI가 고른 것을 눌렀지만 이어지지 않음`으로 실패한다. 이미 누른 것은 되돌리지 않는다.
- **사이트 개편으로 여러 단계가 연달아 바뀐 날도 이어 간다.**
  - 다음 단계의 대상이 옛 글이라 안 보여도, 주소·창이 바뀌었으면 넘어간다.
  - 그 다음 단계는 다시 보통 찾기 → 창 고쳐 잡기 → AI 순서를 밟는다. 사이트 한 번에 5번 상한 안에서다.

### 고객 정보

- **AI에게 보내는 것** (사용자 '가.'):
  - 단계 설명: 종류, 기록의 대상 글, 기록 때 주소 경로, 앞뒤 단계의 대상 글
  - 후보 목록: 번호, 종류, 글, 이름표, 어느 창·틀인지
  - 창마다 제목과 주소 경로
  - 제목·레이어·대화상자의 글 (끼어든 화면 판단용)
- **보내지 않는 것**:
  - 표 본문
  - 입력 칸에 들어 있는 값
  - 화면 사진
- **가리는 것**: 보내는 글 안의 전화번호·이메일·긴 숫자(주문번호·카드번호 모양), 사이트 계정의 아이디·비밀번호 값. 모두 `***` 로 바꾼다.
- **알리는 곳**:
  - 관리 화면에서 켤 때: "막힌 단계의 화면 글을 개인정보를 가린 뒤 AI(Anthropic)가 처리합니다."
  - 업체 웹 환경설정: 같은 안내와 "AI 도움 사용 중" 표시.
- API로 보낸 내용은 Anthropic이 기본적으로 학습에 쓰지 않는다. 업체에 설명할 때 쓸 수 있다.

## 언제 부르나

- **창 고쳐 잡기까지 하고도 첫 회차(`step_timeout`, 20초) 안에 못 찾았을 때 한 번 부른다.**
  - `_find` 에서 `elsewhere()` 가 아무것도 못 찾은 첫 회차 끝이다.
  - AI가 "없음"이면 지금처럼 남은 회차를 찾고 실패한다.
  - 2분을 다 기다린 뒤 부르지 않는 까닭: 끼어든 화면은 기다려도 사라지지 않는다.
- **창이 없을 때** (`창 N이(가) 없습니다` 직전, `_wait_elsewhere` 도 못 찾음): 열린 창들을 후보로 한 번 부른다.
- **가려서 누르기가 막힐 때는 이번에 넣지 않는다.**
  - 지금 `_click` 은 가린 것을 같은 닫기 글로 네 번까지 닫아 보고, 끝내 스크립트로 눌러서 오늘도 실패하지 않는다.
  - 그 앞에 AI를 끼우면 오늘 성공하던 날의 동작이 달라진다.
- **브라우저 자체 알림창(alert·confirm)은 지금처럼 둔다.** 지금 재생기는 모두 [확인]한다. 7·8번은 웹 화면 안의 레이어·창 이야기다.
- **꺼져 있거나 AI를 쓸 수 없으면 지금과 똑같이 돈다.**
  - 쓸 수 없는 경우: 키 없음, 키가 끊김, 인터넷 오류, 사용 한도, 시간 초과, 답 모양 틀림.
  - 이 경우 실패 사유 끝에 `(AI 도움을 쓰지 못함: 시간 초과)` 같은 한 줄을 붙인다.
  - **AI 때문에 지금보다 나빠지는 일은 없어야 한다.**

## 키 관리

- **키 하나를 프로그램에 넣어 배포하지 않는다.** PC 프로그램은 뜯어볼 수 있어서, 새면 누구나 우리 비용으로 AI를 쓴다.
- **업체마다 키를 따로 만든다.**
  - 우리가 Anthropic 콘솔에서 업체별 키를 만들어, 관리 화면에서 그 업체에 넣는다.
  - 그 업체의 에이전트 계정만 읽을 수 있는 자리에 둔다 (데이터베이스 규칙).
  - PC는 받아서 비밀번호처럼 암호화(DPAPI)해 둔다.
  - 새면 그 업체 키만 끊는다.
  - 업체별 월 사용 한도를 콘솔에서 걸 수 있는지는 만들 때 확인한다 (제3자 자료에만 있음).
- **나중**: 회사 서버(또는 Firebase Blaze)가 생기면 서버를 거쳐 부르게 바꾼다. 그때는 키가 PC에 가지 않는다.

## 과금

- **월정액**: AI 도움을 켠 업체는 매달 정해진 금액을 낸다.
- **포함 횟수**: 월정액 안에 한 달 N회가 들어 있다.
- **넘으면 누진 구간**: 넘은 만큼을 구간별 단가로 더 받는다. 예: 101~300회 a원/회, 301~600회 b원/회, 601회~ c원/회.
- **값은 관리 화면에서 정한다.**
  - 기본값 한 벌을 두고, 업체마다 바꿀 수 있다. 업체별 토큰 배율과 같은 방식이다.
  - 실제 금액은 사용자가 정한다. 이 문서는 숫자를 정하지 않는다.
- **세는 단위 (내 제안)**: 'AI가 살린 단계' 수.
  - 불렀는데 못 살린 것은 세지 않는다. 업체가 납득하기 쉽다.
  - 못 살린 호출의 비용은 사이트당 5번 상한이 묶는다.
  - 관리 화면에는 부른 횟수·살린 횟수·Anthropic 사용량을 함께 보여 준다.
- **세는 곳**:
  - PC가 AI를 부를 때마다 업체·사이트·단계·살렸는지를 기록에 남긴다. 토큰 사용 기록과 같은 방식이다.
  - 실제 비용은 Anthropic 사용량 보고서의 키별 사용량으로 맞춰 본다. PC 기록은 고쳐질 수 있어서다.
- **보이는 곳**:
  - 관리 화면 업체 관리: 이번 달 살린 횟수, 포함 횟수, 구간별로 계산한 추가 금액(미리보기).
  - 업체 웹: 이번 달 AI가 살린 횟수 / 포함 횟수.
- **청구서 만들기는 이 기능에 넣지 않는다.** 사람이 관리 화면의 숫자를 보고 청구한다.

## 남기는 것

- 단계 결과 글에 붙인다:
  - `AI가 고름: '엑셀 다운로드' (기록: '엑셀받기')`
  - `AI가 닫음: '오늘 하루 보지 않기'`
- 로그에 AI가 준 한 줄 까닭을 남긴다.
- 실패할 때는 AI가 본 막힌 화면의 한 줄 설명을 실패 사유에 넣는다. AI를 불렀는데 고를 것이 없었던 경우다.
- 기록(프리셋)은 고치지 않는다. AI가 자주 고르는 단계는 사람이 다시 기록한다.

## 고른 방법

- **화면 읽기**
  - 가. Playwright가 읽어 AI에게 준다 (선택). 이미 열린 창·틀을 다 보고 빠르며, 새로 까는 것이 없다.
  - 나. agent-desktop으로 Edge를 읽는다. 느리고, 서명 없는 프로그램을 더 깔아야 하고, 안쪽 틀·주소가 덜 정확하다.
- **AI 부르기**
  - 가. 업체 PC의 Claude Code (업체 구독). 약관상 회색 지대이고, 막히면 업체 계정이 막힌다. 하지 않는다.
  - 나. 업체가 발급한 API 키. 약관은 분명하지만 업체가 가입·발급해야 한다.
  - 다. 우리 회사 API 키, 업체별로 나눔 (선택). 약관이 분명하고, 업체가 할 일이 없고, 관리·과금을 우리가 한다.
- **과금**
  - 토큰에서 차감: 지금 체계에 바로 붙지만, 사용자는 월정액을 골랐다.
  - 월정액 + 누진 추가 과금 (선택).
  - 기본 포함: 비용이 모두 우리 몫이다.
- **무료 AI**: 학습 사용·중단 위험이 있어 하지 않는다.

## 하지 않는 것

- PROCESS(ERPia)에 AI.
- 옵저버 미리보기에서 AI 쓰기 (아래).
- 기록 고치기·기록 버전 올리기.
- 약관 동의·결제·신청 같은 '실행' 단추 누르기.
- Codex·Gemini·업체 키·업체 구독.
- 청구서 자동 발행.

## 만드는 사람이 정할 것 (내 판단으로 정해 둔 것)

- **옵저버 미리보기에서는 끈다.** 미리보기는 기록이 맞는지 보는 곳이라, AI가 살려 주면 고쳐야 할 기록이 가려진다.
- **업체가 웹에서 직접 끄지는 못한다.** 끄려면 우리에게 요청한다.
- 모델(빠른 모델 하나), 시간 제한, 후보 수 상한, 보내는 글 길이, 미루기 낱말 목록의 영어 낱말(close, later, skip 등)은 상수 한 곳에 둔다.
- 키·켬끔·과금 값의 저장 자리와 데이터베이스 규칙. 업체 설정이 PC로 내려오는 기존 방식(예: `HoldSaveOnly`)과 토큰 사용 기록 방식을 따른다.
- API 부르기는 Anthropic 공식 Python SDK(`anthropic`)로 한다. Anthropic 지침의 기본이고, 오류 종류·재시도·인증서 묶음(certifi)을 SDK가 맡는다. 빌드의 라이브러리 목록에 더해야 해서 업데이트가 몇 MB 늘어난다 (계획 ① Task 0).
- 모델은 `claude-haiku-5-5` (사용자 결정 2026-11-16: Opus는 지나치다). 손 시험에서 Sonnet 5.5와 비교해, 틀리면 올린다.

## 시험

- 자동 시험은 실제 API를 부르지 않는다. 'AI에게 묻기'를 정해진 답을 돌려주는 가짜로 바꿔 끼운다.
- 가짜 쇼핑몰 경우:
  - 단추 글이 바뀜 → 대신 누름, 성공
  - 공지 레이어 [오늘 하루 보지 않기] → 닫고 성공
  - 약관 동의 [동의]만 → AI가 [동의]를 골라도 안 누르고 실패, 사유 확인
  - 안내문 [확인] → 누름
  - "신청하시겠습니까 [확인]" → 어느 쪽으로 답해도 안 누름
  - AI가 [주문취소]를 고름 → 안 누름
  - AI가 3번 넘게 누르려 함 → 실패
  - 누른 뒤 안 이어짐 → 실패
  - 두 단계가 연달아 바뀜 → 둘 다 살리고 성공
  - 키 없음·시간 초과·답 모양 틀림 → 지금과 같은 실패 + 한 줄
  - 파일 받기 단계에서 옛 줄을 고름 → 후보에 없음
  - 보내는 글에 비밀번호 값·입력 값·전화·이메일·표 본문이 없음
  - 살린 단계만 과금 횟수로 남음
- 관리 화면·업체 웹: 켬끔·키 넣기·안내 표시·누진 금액 미리보기를 화면 시험에 더한다.
- 실제 API로 돌리는 시험은 손으로 한 번 한다. 우리 키를 쓰므로 비용이 든다.
- 기존 재생 시험과 `tests/test_popup_relocate.py` 는 꺼진 상태(기본)에서 그대로 통과해야 한다.
