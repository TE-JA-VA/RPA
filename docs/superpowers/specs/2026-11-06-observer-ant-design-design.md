# 옵저버 디자인 교체 · 프리셋 한도 50 설계

2026-11-06. 시안은 사용자가 실제 창으로 확인했다 ("상당히 좋아졌어").

## 1. 왜

옵저버 창이 투박하다는 의견이 있었다. 사용자 판단으로 원인은 Tkinter 기본 부품을 그대로 쓴 20년 전 모습이다. 설정과 단계를 한눈에 보는 구성은 좋으므로 유지하고, 생김새만 바꾼다. 기준은 Ant Design 이다 (Figma 커뮤니티 파일 `9Q8VHH2SsiIG97PAjIsJVX`).

프리셋은 50개까지 쓸 예정이라 한도도 50으로 올린다.

## 2. 목표와 하지 않는 것

**목표**
- 옵저버 창 전체를 Ant Design 모양으로 바꾼다.
- 프리셋 50개를 무리 없이 고르고 찾을 수 있다.
- 프리셋 한도를 일반 업체·웰라이프 모두 50으로 올린다.

**하지 않는 것**
- 기록·미리보기·저장의 동작, 화면 문구, 저장 파일 모양은 바꾸지 않는다.
- 위쪽 설정, 가운데 상태 줄, 아래 단계 목록, 맨 아래 단추라는 배치는 바꾸지 않는다.
- 단계 표시줄(① 프리셋 설정 → ② 기록 …)은 넣지 않는다. 2026-10-14 사용자가 거절했다.
- 윈도우 기본 알림창(`messagebox`)과 파일 선택 창은 그대로 둔다.
- 설정 창(`rpa_settings`), 대시보드, ACTOR 화면은 범위 밖이다.

**실패로 보는 경우**
- 모양은 좋아졌는데 기록이나 저장 동작이 달라진 경우.
- 설치본 exe 에서만 이미지가 안 나오거나 켜지지 않는 경우.

## 3. 시안에서 정해진 모양

시안 코드: 세션 임시 폴더의 `observer_ant_mock.py` (버리는 파일). 값은 아래에 옮겨 적었다.

| 항목 | 값 |
|---|---|
| 기본 파랑 / 올림 / 누름 / 연한 바탕 | `#1677ff` / `#4096ff` / `#0958d9` / `#e6f4ff` |
| 위험 빨강 / 올림 / 누름 / 연한 바탕 | `#ff4d4f` / `#ff7875` / `#d9363e` / `#fff2f0` |
| 글자 (본문·보조·흐림·더 흐림) | `#1f1f1f` / `#595959` / `#8c8c8c` / `#bfbfbf` |
| 테두리 / 구분선 / 창 바탕 / 카드 / 줄 올림 | `#d9d9d9` / `#f0f0f0` / `#f5f5f5` / `#ffffff` / `#fafafa` |
| 글자 크기 (px) | 제목 20, 본문 14, 보조 13, 작은 글 12 |
| 높이 | 단추·입력칸 32, 단계 줄 대기 칸 24, 체크·라디오 16 |
| 모서리 | 단추·입력칸 6, 카드 8, 체크 4 |

- 입력칸: 평소 회색 테두리, 마우스 올리면 파란 테두리, 누르면 파란 테두리에 연한 파란 빛.
- 단추 종류: 파란 주 단추, 흰 일반 단추, 빨간 위험 단추, 흰 바탕 빨간 테두리 단추. 올림·누름 색이 있다. 꺼진 상태는 회색이다.
- 단계 줄: 체크, 연한 파란 동그라미 번호, 글, (있으면 인증번호 칸 글자 단추), 대기 체크, 대기 칸, '초 대기', ✕ 순서. 줄 사이 구분선, 마우스 올리면 바탕이 옅게 바뀐다. 긴 글은 줄바꿈한다.
- 프리셋 삭제는 흰 바탕 빨간 테두리 단추 하나만 둔다 (제목 줄의 [−] 는 없앤다, 시안대로).
- 여백: 창 가장자리 가로 20·세로 16, 프리셋 카드 안쪽 20, 단계 카드 안쪽 16, 탭 사이 26, 입력 줄 사이 6, 단계 줄 위아래 7 (620 폭 기준).
- 글자는 지금 화면 그대로다. 시안의 표현 가운데 문구가 다른 것은 따르지 않는다: 목록 제목은 지금의 `① 이름 - 기록한 단계`, 상태 줄 글도 지금 것, `N단계` 는 넣지 않는다. 모양만 시안을 따른다: 상태 줄의 빨간 점과 굵은 글, 파일 불러오기·내보내기의 파란 글자 단추.

## 4. 프리셋 탭 (50개)

지금의 번호 단추 격자를 가로 탭 줄로 바꾼다.

- 탭 글자는 `① 이름` 이다. 이름이 비어 있으면 지금처럼 `프리셋 n` 이다. 긴 이름은 줄임표로 줄인다 (길이는 만드는 쪽이 정한다). 번호는 지금의 `circled` 를 쓴다.
- 탭이 넘치면 가로로 스크롤한다. 탭 줄 아래에 얇은 스크롤바를 두고, 탭 위에서 마우스 휠로도 움직인다. 고른 탭은 자동으로 보이는 자리로 온다.
- 넘치지 않으면 스크롤바는 숨긴다.
- `n/최대`, `+`, 프리셋 삭제는 스크롤에 휩쓸리지 않게 오른쪽에 고정한다.
- 좁은 창에서는 탭이 3~4개만 보이므로, 탭 줄 오른쪽에 `⋯` 단추를 둔다. 누르면 전체 프리셋이 번호·이름 목록으로 뜨고 골라서 바로 간다 (Ant Tabs 의 넘침 목록과 같다). 프리셋이 넘칠 때만 보인다.
- 네 가지 상태를 지금처럼 구분한다.
  - 선택됨: 파란 글자와 파란 밑줄.
  - 기록 있음: 본문색 글자와 작은 파란 점.
  - 비어 있음: 흐린 글자.
  - 기록 중: 빨간 글자와 빨간 밑줄.
- 기록·미리보기 중에는 지금처럼 다른 탭을 누를 수 없다.

단계 목록의 세로 스크롤바도 같은 모양의 얇은 스크롤바로 바꾼다. 메일 서버 등 프리셋 영역에서 쓰는 추가 입력도 같은 부품을 쓴다.

## 5. 만드는 방법

- 부품은 새 파일 `observer_widgets.py` 에 모은다: 단추, 입력칸, 선택 상자, 체크, 라디오, 카드, 탭 줄, 스크롤바.
- 부품은 **지금 Tkinter 부품과 같은 사용법**을 지킨다. `rpa_observer.py` 의 로직 코드와 시험이 쓰는 `config`·`cget`·`invoke`, `textvariable`·`variable`, 선택 상자의 `get`·`set`·`current`·`<<ComboboxSelected>>`, `validate` 를 그대로 받는다. 그래야 로직을 건드리지 않고 화면 코드만 바뀐다.
- `button`·`enable`·`skin`·`_entry` 같은 기존 도우미는 이름을 유지하고 속만 바꾼다.
- 둥근 모양은 Pillow 로 네 배 크기로 그려 줄인 뒤 PNG 로 만들어 `tk.PhotoImage(data=...)` 로 넣는다. `PIL.ImageTk` 는 쓰지 않는다. 설치본의 Tcl/Tk 9 는 DLL 안 zipfs 구조라 `_imagingtk` 가 위험하다. 같은 모양은 캐시한다.
- 크기는 지금 창의 `self.scale` 로 맞춘다. 창 크기와 자리 계산(`panel_w`, 브라우저 옆 배치)은 바꾸지 않는다.
- 글꼴은 지금과 같은 맑은 고딕이다.
- 단추 색은 시안을 따른다. 저장은 파란 주 단추, 미리보기는 흰 일반 단추, 기록 완료는 빨간 위험 단추다. 초록은 쓰지 않는다. 기록 시작은 파란 주 단추다.
- 시안에 없는 미리보기 중 단추는 다음과 같이 한다. 일시정지와 수정은 흰 일반 단추, 중단은 빨간 위험 단추.
- 좁은 창: 창 폭은 지금처럼 `max(화면의 30%, 460 * scale)` 이다. 시안은 620 폭이라 460 폭에서는 여백을 먼저 줄인다 (카드 안쪽, 단계 줄 사이, 번호 동그라미 옆). 단계 글은 줄바꿈으로 받고 칸 크기는 줄이지 않는다. 460 폭 사진으로 확인한다.

**빌드**: Pillow 를 옵저버 exe 에 넣는다 (`build_release.py`, 옵저버 exe 에만). 지금까지 제품 코드에서 Pillow 를 쓰지 않아 새로 들어간다. Pillow 는 `.venv` 에 이미 있다.

## 6. 프리셋 한도 50

| 곳 | 지금 | 바꾼 뒤 |
|---|---|---|
| `rpa_status.PRESET_MAX` | 40 | 50 |
| `rpa_status.PRESET_WELLIFE` | 40 | 50 |
| `ops.PRESET_LIMIT_MAX` (관리 화면 범위) | 10 | 50 |
| `ops.PRESET_SLOT_MAX` | 40 | 50 |
| `rpa-settings.js` `SLOT_MAX` | 40 | 50 |
| `AFTERMARKET_SETUP.html` 칸 번호 최대, 안내 글 (2~10, 40개) | 40 / 10 | 50 |
| `firebase/functions/shared/ops.js` | 사본 | `functions/sync.mjs` 로 같이 맞춘다 |
| 에이전트 시험 등 40·41 을 적은 시험 | | 50·51 로 |

`circled` 는 ㊿ 까지 이미 된다. 관리 화면 기본값은 2 그대로다. 그 밖에 40·10 을 숫자로 적어 둔 곳은 만드는 쪽이 찾아 맞춘다.

**옛 버전 PC 위험 (검토자가 임시 폴더에서 실행해 확인)**: 옛 PC 가 41 이상을 받으면 프리셋 수 값만 버려(`agent.py:741-743`) 10분 안에 한도가 기본값 2가 된다. 그러면 `switch_off_over_limit(2)` 가 3번 이후의 켠 프리셋을 끈다(`rpa_status.py:1359-1365`). 기록은 지워지지 않지만, 값을 되돌리거나 업데이트해도 **자동으로 다시 켜지지 않는다**. 사람이 웹에서 하나씩 켜야 하고, 그동안 그 사이트 수집이 빠진다. 11~40 은 옛 PC 에서도 안전하다. 위험한 구간은 41~50 뿐이다.

업체코드에 wellife 가 든 업체는 PC 쪽 고정값이라 이 위험이 없다. 옛 PC 는 40, 업데이트하면 50이다. `features.wellife` 로만 연 업체는 고정값 대상이 아니라 일반 업체처럼 다룬다.

**막는 방법 (사용자 2026-11-06: 모든 업체 50까지, 관리 화면에서 수동으로 열어 준다, B안)**: 에이전트가 현황에 자기가 받는 최대값 `live.preset_max` 를 올린다. 관리 화면은 41 이상을 줄 때 그 업체의 모든 PC 의 값을 보고, 값이 없거나 모자란 PC 가 있으면 PC 이름을 알리며 거절한다. 한 번도 안 켠 PC 도 옛 설치본일 수 있어 거절한다. 40 이하는 보지 않는다. 버전 번호를 비교하지 않으므로 상수를 관리할 일이 없다.

`live` 규칙은 모르는 칸을 거절하므로 **DB 규칙을 PC 업데이트보다 먼저 배포**해야 한다.

**되돌리기**: 41개 이상 저장한 PC 가 옛 버전으로 되돌아가면 옛 `read_presets` 가 거절해 옵저버가 켜지지 않는다 (`rpa_status.py:1121-1122`). 옛 코드는 고칠 수 없으므로 받아들인다. 41개 이상을 처음 쓰는 업체는 PC 한 대에서 먼저 확인한다.

## 7. 확인

- 부품 단위: `observer_widgets.py` 의 사용법 호환을 창을 띄워 확인한다 (`cget`, `invoke`, 변수 연결, 꺼진 상태).
- 탭: 프리셋 2개, 10개, 50개에서 스크롤, 고른 탭 따라가기, 상태 네 가지를 확인한다.
- 기존 시험: `test_presets`, `test_observer_edit`, `test_step_wait`, `test_imap_preset`, `test_typed_nav`, `test_preset_transfer`, `check_observer_ui` (3~4분 마우스·키보드를 쓴다. 사용자에게 먼저 알린다).
- 사진을 볼 때는 창만 찍는 PrintWindow 를 쓴다. 화면 전체 사진은 뒤의 다른 창을 담을 수 있다.
- 한도: 에이전트, 관리 화면, 칸 번호 시험을 50·51 로.
- 빌드: 설치본 exe 의 `--check` 가 통과하고, 실제 exe 창에서 이미지가 나오는지 본다. 샌드박스 전체 시험.
- 릴리스 순서는 평소대로다: 빌드 → 샌드박스 → 내보내기. 웹 변경이 있으므로 hosting 배포도 함께.

## 8. 사용자가 정한 것 / 제가 정한 것

**사용자가 정함**: Ant Design 기준, 로직 유지, 시안 모양, 프리셋 스크롤바 허용, 모든 업체 한도 50, 옛 PC 는 관리 화면이 막는다.

**제가 정함 (검토 대상)**
- 웰라이프 고정값도 50으로 올린다.
- 탭에 번호와 이름을 함께 쓴다.
- 좁은 창용 `⋯` 전체 목록을 둔다.
- 기록 시작을 파란 주 단추로 한다 (전에는 빨강).
- 파란 점으로 '기록 있음' 을 표시한다.
- 제목 줄 [−] 를 없앤다.
- Pillow 를 옵저버 exe 에 넣는다.
