# 토큰 (사용량 선불) 설계

**상태:** 2026-10-06 1부(저장하고 빼기)·2부(막기와 알림)·3부(넣기와 보기) 구현·시험 끝. 4부 예상 소모량은 설계 전. 2026-10-07: '대상 없음' 은 안 뺀다 - 시간대 반복 설계(2026-10-06-settings-schedule-design.md) 6-5.
**출발:** 팀원 RPA(`RPA_Base`) 흡수 ① 카운터. 그분은 서버(Supabase)가 10분마다 `usage_daily` 를 다시 센다 - 우리는 서버 코드가 없다.

## 1. 목적 (사용자)

- 업체가 토큰을 결제하면 우리가 그만큼 넣는다. 모듈을 쓸 때마다 빠지고, 다 떨어지면 실행을 막는다.
- 요금 받는 근거, 우리만 보는 통계, 업체 화면 표시에 쓴다. 환경설정에서 모듈을 고르면 예상 소모량을 보여 준다.

가정 (사용자에게 보였고 고치지 않음): 토큰은 업체 단위 (PC 여러 대가 한 통장). 결제는 프로그램 밖에서 하고 우리가 확인한 뒤
`setup.js` 로 넣는다. 온라인 결제 연동은 범위 밖.

## 2. 정한 것

| 질문 | 답 (2026-10-06) |
|---|---|
| 누가 세나 | 에이전트 (사용자 의견 - 기록이 처음 생기는 곳, 웹이 세면 볼 때마다 이력을 다 읽는다, 서버 함수 없음) |
| 언제 빠지나 | 모듈이 돌아서 **완료**했으면 (2026-10-07 바꿈 - 전엔 대상 없음도. 시간대 반복의 빈 회차가 토큰을 먹지 않게). 대상 없음·실패·건너뜀·중단은 안 빠진다 |
| 얼마나 | **값표** (우리가 정함, 모든 업체 같음). 처음엔 모두 1, 로그인 0. 값을 바꿔도 지난 기록은 그때 값 그대로 |
| 무엇이 | 루틴 모듈 넷 + 프리페어 쇼핑몰 받기 (사이트·프리셋 하나 = 1회) + **앞으로 추가되는 루틴 모듈** (값표에 없으면 default). 옵저버 미리보기는 시험이라 안 쓴다 |
| 막기 | 남은 토큰이 **1 이상이면 시작**하고 도중에 떨어져도 그 실행은 끝까지 (마이너스 가능). 0 이하면 시작하지 않는다. 실행 전에 이번 실행에 드는 토큰이 남은 것보다 많으면 "토큰이 마이너스로 떨어질 수 있습니다" 라고 알린다 |
| 방법 | **A: 기록 한 장에 쓴 토큰을 적는다.** (B: PC 이력 파일로 하루치를 다시 세서 덮어쓰기 - PC 를 새로 깔면 틀어지고 빼기는 따로 필요해서 버림) |

## 3. 나눠 만들기

1. **저장하고 빼기** - 끝 (아래 4절)
2. **막기와 알림** - 에이전트가 실행을 띄우기 전 남은 토큰 확인, 화면 알림
3. **넣기와 보기** - `setup.js` 로 넣기·값표, 업체 화면(남은 토큰·이번 달 모듈별), 우리 통계
4. **예상 소모량** - 환경설정에서. 시각별 모듈·시간대 반복(흡수 ②③)이 예약 모양을 바꾸므로 그 뒤

## 4. 1부 - 저장하고 빼기 (구현)

통장처럼: 넣은 기록(우리) - 쓴 기록(실행 기록) = 남은 토큰.

- **실행 기록** `runs/{cid}/items/{runId}` 에 두 칸 (`agent.run_doc`):
  - `used` 쓴 것 {키: 횟수} - Firestore map (`fb.fs_fields` 가 dict 를 map 으로). `agent.usage`:
    루틴은 `modules[].state` 가 `done` 인 키 (2026-10-07 전 기록은 대상 없음도 세어 올라갔다 - 기록은 고치지 않는다) (`login`·`sales`·`hold`·`logistics`·`output`, 새 모듈도 그대로),
    프리페어는 단계 키 `사이트:동작` 을 사이트로 묶어 단계가 모두 `done` 인 사이트 수 `sites`, 옵저버(HISTORY_ONLY)는 `{}`.
  - `cost` 쓴 토큰 = Σ 횟수 × 값표 (`agent.run_cost`).
- **값표** `meta/prices` = `{default: 1, login: 0}` (없거나 못 읽으면 `agent.PRICES`). 에이전트가 올릴 기록이 있을 때만,
  10분마다 다시 읽는다 (`agent.Prices`). 0 이상 정수가 아닌 값은 버린다.
- **통장** `wallet/{cid}` = `{granted}` + `grants/{id}` 넣은 내역. **남은 토큰 = granted - 그 회사 기록들의 cost 합** -
  Firestore 가 서버에서 더한다 (`fb.fs_sum` = runAggregationQuery sum, 1000건에 읽기 1번, `agent.balance`).
  통장이 없는 업체는 `None` = 아직 토큰 제도 밖 (세기만 하고 막지 않는다).
- **규칙** (`firebase/rules/firestore.rules`): 기록의 `cost` 는 0 이상 정수, `used` 는 map (없으면 옛 에이전트라 받는다),
  기록은 만들기만 (고치기·지우기 안 됨 - 한 번 적힌 쓴 토큰은 안 바뀐다). 값표·통장은 아무도 못 쓴다 (Admin SDK 만).
  같은 run_id 는 이미 있어 거절되니 다시 보내도 두 번 안 빠진다.
- **함께 고친 것:** 프리페어에서 앞 사이트가 실패하고 마지막 사이트가 성공하면 실행 끝(`finish('stopped')`)이 마지막 사이트의
  단계를 '중단' 으로 덮었다 - 기록 탭에 실패로 보였고 토큰 셈에서도 빠졌다. 사이트가 성공하면 바로 `rpa_status.done_step()`.
- 이 기능 전의 기록은 `cost` 가 없어 합에서 빠진다 (0) - 토큰은 새 판을 깐 뒤부터 빠진다.

시험: 에이전트 단위 156 (토큰 19), 규칙 29 (토큰 4 - 자기 회사 cost 합 포함), 통합 36 (서버 값표로 센 cost, 남은 토큰 84 =
100 - 16, 통장 없음 null), 프리셋 69 (앞 실패·마지막 성공).

## 4-2. 2부 - 막기와 알림 (구현)

사용자 결정 (2026-10-06): 모자라면 **실행 단추 아래 늘 보이는 글** (누를 때 따로 묻지 않음 - 확인 창 추천은 안 고름),
남은 토큰을 못 확인하면 **마지막으로 확인한 값으로** (한 번도 못 했으면 실행).

- **막는 자리 하나:** 실행 단추(명령 `launch`)와 예약은 모두 `rpa_dashboard.launch` 를 지난다. 에이전트가 켤 때
  `dash.TOKEN_GATE = agent.Tokens.gate` 를 달고, launch 가 띄우기 직전에 `TOKEN_GATE(target)` 를 부른다 (기존 거절 '이미 돌고 있음'·
  '옵저버가 켜져 있음' 바로 뒤). 남은 토큰이 0 이하면 `RuntimeError("토큰이 없습니다 (남은 N개). 충전한 뒤 실행하세요")`.
  - 실행 명령은 그 글로 `failed` (화면에 결과 글).
  - 예약은 `Scheduler.tick_safe` 가 그 글을 그대로 `last_error` 에 남기고 다음 예약으로 넘긴다 (RuntimeError 는 사람에게 보일
    거절이라 'RuntimeError:' 를 붙이지 않는다). 다음에 띄우면 지워진다.
- **확인 (`agent.Tokens`):** 띄우기 직전·기록을 올린 뒤에는 바로, 그 밖에는 10분마다 `agent.balance` (우리가 넣은 것은 10분 안에
  보인다). 실패하면 마지막 값, 한 번도 못 했으면 None = 막지 않음. 통장이 없어도 None.
- **실행 1번에 드는 토큰 (`Tokens.costs`):** 켠 루틴 모듈(설정 키 소문자 = 기록의 모듈 키) × 값표 + Stts 0 인 사이트·프리셋 수 ×
  값표 `sites`. 전체 = 둘의 합. 실패한 것은 안 빠지니 많아야 이만큼.
- **현황 `live.tokens`** = `{balance, cost: {routine, prepare, all}}` (통장이 없으면 없음).
- **화면 (`rpa.js paintTokens`):** 실행 단추 아래 `#token-line` - 평소 회색 "남은 토큰 120개 · 전체 실행 1번에 6개", 모자라면
  노랑 "… - 마이너스로 떨어질 수 있습니다", 0 이하면 빨강 "토큰이 없습니다 (남은 0개) - 충전한 뒤 실행하세요" + 실행 단추 셋 잠김
  (ERPia 종료는 그대로). 예약이 켜져 있으면 예약 칸에도 노랑 "다음 예약 실행에 6개 · 남은 3개 - 마이너스로 떨어질 수 있습니다" /
  빨강 "토큰이 없어 예약 실행을 건너뜁니다". 노란 글은 `.msg.warn` (`--warn`, 글자용 대비 4.5:1).
- 손으로 켠 exe 는 에이전트를 안 거쳐 못 막는다 - 기록이 올라갈 때 똑같이 빠진다.

시험: 에이전트 단위 165 (막기 9), 자동 실행 72 (3), 통합 39 (3 - 남은 -6 이면 실행 명령이 그 글로 실패, 현황 tokens), 화면 258 (7).

## 4-3. 3부 - 넣기와 보기 (구현)

사용자 결정 (2026-10-06): 업체 화면에는 **이번 달 사용량만** (충전 내역은 안 보임), **관리자만** (오른쪽 열), 토큰
**유효기간 없음**, 처음 통장을 만들 때 **자동 체험분 없음** (주려면 첫 넣기에 메모 '체험').

- **넣기 (`setup.js`, 우리 PC, Admin SDK):** `tokens <cid> [+N|-N] [메모]` - 트랜잭션으로 `wallet/{cid}.granted` 를 바꾸고
  `grants` 에 {amount, at, memo} 한 줄. 통장이 없으면 만들며 `since` = 지금 한국 시각 (PC 기록의 started_at 과 같은 꼴) - 그때부터
  그 업체는 0 이하에서 막힌다. 금액 없으면 넣은 합계·쓴 합계·남은 토큰·최근 넣은 내역 10줄. `price [키 값]`, `usage [cid]`
  (업체마다 남은 토큰·이번 달 쓴 토큰 - 통장이 없어도 쓴 것은 센다).
- **남은 토큰 = granted - since 뒤에 시작한 기록의 cost 합** (`agent.balance` → `fb.fs_sum(..., since)`, setup.js `spentSince`).
- **이번 달 사용량 카드 (`rpa.js paintUsage`):** 통장이 있을 때만, 이달 1일과 since 중 늦은 때부터 (`(10월 1일부터)` /
  `(10월 6일 통장 시작부터)`), 업체 전체(PC 모두). 모듈별 횟수(0회·로그인 숨김) + "합계 N개 · 오늘 M개". 남은 토큰이 바뀔 때만
  다시 읽고, 늦게 온 결과는 버린다. **칸마다 질의 하나** - 한 질의에 여러 칸을 같이 더하면 그 칸이 모두 있는 기록만 센다
  (Firestore, 시험에서 실측). 거르기+합은 복합 색인 started_at·cost, started_at·used.<모듈> (`rules/firestore.indexes.json` -
  에뮬레이터는 색인을 안 따진다. **새 모듈은 색인과 USAGE_KEYS 에 더한다**).

시험: 관리 도구 40 (토큰 17), 에이전트 166, 통합 40 (since), 화면 260 (사용량 2 - 통장 없음 숨김·모듈별·합계·늦은 결과 버림).

## 5. 한계 (사용자에게 알림)

- 서버 코드가 없어 **막기는 PC(에이전트)에서** 한다. 규칙은 '넣기는 우리만, 기록은 만들기만' 을 지키지만, 일부러 고친 PC 는
  cost 를 적게 적거나 막기를 피할 수 있다. 단단히 하려면 서버 함수 (Firebase 유료 요금제).
- 1부 전 판의 에이전트는 cost 를 안 적는다 - 판을 올려야 빠진다.
- PC 여러 대가 거의 동시에 시작하면 잔액 확인이 겹친다 - 어차피 끝까지 도는 규칙이라 조금 더 마이너스가 될 뿐.
- 인터넷이 끊긴 동안 돈 실행은 기록이 올라갈 때 빠진다 (남은 토큰이 늦게 준다).
