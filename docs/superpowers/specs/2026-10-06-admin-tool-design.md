# 관리 화면 (AFTERMARKET_SETUP) 설계

**상태:** 2026-10-06 사용자 승인 (설계 1~3부를 대화로), 구현 전.
**출발:** 사용자 "터미널에서 setup.js 로 하는 일이 솔직히 매번 헷갈려 - 대시보드만큼은 아니어도 HTML 로 유저친화적으로, (신규)업체
셋팅 + 토큰 입력도". 함께 받은 요청 '대시보드 환경설정 메뉴' 는 따로 설계한다 (사용자가 이것을 먼저 고름).

## 1. 목적과 범위

- **목적:** 우리(대표님)가 명령을 외우지 않고 신규 업체를 처음부터 끝까지 셋팅하고, 토큰을 넣고 확인한다.
- **첫 판 범위 (사용자 선택, 넷 다):** 신규 업체 셋팅 + 토큰, 업체·계정 목록, 계정 관리, 업체 정책·토큰 배율.
- 터미널 명령(`setup.js`)은 그대로 남는다 - 화면과 같은 코드를 쓴다.
- **범위 밖:** 다른 PC·밖에서 쓰기, 온라인 결제, 업체용 대시보드 바꾸기 (환경설정 메뉴는 따로).

가정 (사용자에게 보였고 고치지 않음): 관리 키가 있는 우리 PC 에서만 켠다, 비밀번호는 만들 때 한 번만 보여 준다, 신규 업체 셋팅은 한
흐름 (업체 → PC → 관리자 → 기계 계정 → 물류대기 사용 여부 → 첫 토큰) 이고 끝에 고객에게 보낼 정보를 한 번에 복사한다.

## 2. 방식 - A (사용자 선택)

우리 PC 의 작은 로컬 서버(Node + firebase-admin - setup.js 와 같은 서비스 계정 키 `firebase/admin/serviceAccountKey.json`) + HTML 한 장.

- 버린 것 B: 파이썬으로 새로 - Firebase 관리 도구를 파이썬용으로 또 깔고 setup.js 의 일을 다시 짜야 해 같은 일이 두 벌.
- 버린 것 C: 웹 대시보드 안 총괄 페이지 - 계정·claim 만들기는 서버 함수(Firebase 유료 요금제)가 있어야 한다. 지금은 서버 코드가 없다.

## 3. 켜기와 보안 (설계 1부)

- 바탕화면 바로 가기 **"AFTER MARKET 관리"** → `firebase/admin/AFTERMARKET_SETUP.bat` → `node admin.js`. bat 안에는 **영문만**
  쓴다 (한글이 있으면 CP949 여야 하는 함정을 아예 피한다 - 한글 안내는 화면과 Node 가 낸다). 서버는 `127.0.0.1` 의 빈 포트에서
  듣고 기본 브라우저로 화면을 연다. 끄기는 화면의 [끄기] 단추 또는 검은 창 닫기. 바로 가기는 `node admin.js --shortcut` 이 한 번
  만든다 (바탕화면 .lnk → 이 bat, 아이콘은 release/AFTER_MARKET.ico).
- 맨 위 띠: **실제 서버 (rpa-test-f02e0)** 주황 / **에뮬레이터 (시험)** 회색 (`FIREBASE_*_EMULATOR_HOST` 가 있으면 에뮬레이터).
- **127.0.0.1 에서만** 듣는다 - 다른 PC·인터넷에서 닿지 않는다.
- **켤 때마다 새 비밀 값** (무작위 32바이트) - 서버가 연 주소 `?k=…` 에만 있고, 화면이 모든 `/api` 요청에 `X-Admin-Key` 머리글로
  보낸다. 다른 사이트는 이 값을 모르고 다른 출처에서는 맞춤 머리글을 못 보낸다 (서버는 CORS 를 열지 않는다). `Host` 머리글이
  `127.0.0.1:<포트>` 가 아니면 거절 (주소 이름 위조). 화면 파일(`/`) 은 비밀 값 없이 내려준다 - 안에 비밀이 없다.
- **비밀번호**는 만든 응답에 한 번만 실어 화면 결과 칸에 보여 주고 [복사] 단추. 서버 콘솔·기록·파일에 안 남긴다.
- 되돌리기 어려운 일: **업체 삭제는 업체코드를 쳐야** 진행, 비밀번호 재발급·계정 막기는 확인 창.
- **`관리_기록.txt`** (firebase/admin, gitignore): 한 일마다 "언제 · 무엇을 · 업체 · 대상" 한 줄. 비밀번호는 안 적는다.

## 4. 화면 (설계 2부)

맨 위: 서버 띠, 메뉴 **업체 · 신규 업체 · 토큰 배율·통계**, [끄기]. 대시보드와 같은 색 (토큰 복사).

### 4-1. 업체 (처음 화면)
- 표: 업체코드 · 이름 · 상태(사용/삭제) · PC 수 · 계정 수 · 남은 토큰 · 이번 달 쓴 토큰 · 마지막 로그인
- 줄을 누르면 아래에 상세:
  - **PC:** 목록 + [PC 더하기] (기계 계정도 같이 만들기 - 비밀번호 한 번 보여 줌)
  - **계정:** 아이디 · 역할(관리자/열람자/기계) · 막힘 · 마지막 로그인 · [비밀번호 재발급] [막기/열기], [사용자 더하기]
  - **토큰:** 넣은 합계 · 쓴 · 남은 · [넣기/빼기] (수·메모) · 넣은 내역
  - **모듈 정책:** 물류대기 관리 등 스위치 (끄면 그 업체 화면에서 숨고 PC 가 끈다 - setup.js modules 와 같다)
  - **업체 삭제 / 되살림** (업체코드를 쳐야)

### 4-2. 신규 업체 (한 화면 위에서 아래로, 마지막에 한 번에 만들기)
1. 업체: 업체코드 (영문 소문자·숫자·밑줄) · 이름
2. PC: PC코드 · 이름 ([한 대 더])
3. 관리자 계정: 아이디 · 이름 ([열람자 더하기])
4. **물류대기 관리를 쓰나요?** 예/아니요 - 업체마다 달라 꼭 묻는다 (메모리 company-module-policy) + 다른 모듈 정책
5. 첫 토큰: 지금 넣기 (수·메모) / 나중에 (통장 없이 시작 = 막지 않고 세기만)
6. [만들기] → 한 일 목록(✓) + **"고객에게 보낼 정보"** 복사 칸:
   ```
   [대시보드]  https://rpa-test-f02e0.web.app
   업체코드: net   아이디: admin   비밀번호: ••••••
   [PC 설정 창에 넣을 값]
   사무실 PC → 업체코드: net   PC 이름: test   비밀번호: ••••••
   ```
   중간에 실패하면 어디까지 됐는지와 그때까지 만든 비밀번호를 보여 준다. 다시 누르면 남은 것만 한다 (이미 있는 업체·PC 는 그대로,
   이미 있는 계정은 건너뛰고 '비밀번호를 모르면 재발급' 안내).

### 4-3. 토큰 배율·통계
- **토큰 배율** (전 이름 '값표' - 사용자가 바꿈): 모듈마다 실행 1회에 빠지는 토큰. 처음 모두 1·로그인 0, 바꿔도 지난 기록은 그때 값.
- **통계:** 업체마다 남은 토큰 · 이번 달 쓴 토큰 (setup.js usage 와 같다).

## 5. 코드 구조 (설계 3부)

| 파일 (`firebase/admin/`) | 하는 일 |
|---|---|
| `ops.js` (새로) | setup.js 의 일을 함수로 - 결과를 값으로 돌려준다 (찍지 않음, process.exit 없음). 업체·PC·사용자·기계 계정, 비밀번호 재발급, 막기/열기, 목록·상세, 모듈 정책, 삭제/되살림, 토큰·내역, 토큰 배율, 통계, 신규 업체 한 흐름 |
| `setup.js` | 터미널 명령·나오는 글은 그대로, 안에서 ops.js 를 부른다 |
| `admin.js` (새로) | `node:http` 서버 (새 의존성 없음): 3절 보안, `/api/*` → ops.js, 화면 파일 내려주기, 브라우저 열기, 관리_기록.txt |
| `AFTERMARKET_SETUP.html` (새로) | 화면 한 장 (HTML·CSS·JS), 밖에서 불러오는 것 없음 |
| `AFTERMARKET_SETUP.bat` (새로) | 영문만: `node admin.js` |

사용자에게 보이는 글은 모두 '토큰 배율' (setup.js price 의 글도). 명령 이름 `price` 는 그대로 (바꾸면 옛 메모·습관이 깨진다).

## 6. 시험 (모두 에뮬레이터)

- `tests/check_setup.py` 40건이 그대로 통과 - setup.js 를 ops.js 로 옮겨도 같다.
- `tests/check_admin.py` (새로, Playwright headless):
  - 보안: 비밀 값 없이 `/api` → 거절, Host 가 다르면 거절
  - 신규 업체 흐름 끝까지 (PC 2대·관리자·열람자·물류대기 끔·첫 토큰) → 계정·claim·정책·통장이 실제로 생기고, 고객에게 보낼 정보가
    맞고, 관리_기록.txt 에 비밀번호가 없다
  - 중간 실패 → 다시 누르면 남은 것만
  - 업체 상세: 막기/열기, 비밀번호 재발급, 토큰 넣기/빼기·내역, 모듈 스위치, 삭제(코드를 쳐야)·되살림
  - 토큰 배율 바꾸기, 통계
- **실제 서버로는 시험하지 않는다** - 계정을 만들면 비밀번호가 찍히는 일이라 Claude 도구로 실서버 계정을 만들지 않는다.
