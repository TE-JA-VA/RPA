# 환경설정 메뉴 · 시각별 모듈 · 시간대 반복 설계

**상태:** 2026-10-06 설계 (사용자와 문답으로 정함). 2026-10-07 구현 (계획 docs/superpowers/plans/2026-10-07-settings-schedule.md). 배포·새 판·실기 확인은 사용자 확인 뒤.
**출발:** 사용자 요청 ① 대시보드 **환경설정 메뉴** (2026-10-06, 앱마다 설정을 그 메뉴에서) + 팀원 RPA(`RPA_Base`) 흡수
② **시각별 모듈** ③ **시간대 반복** (2026-10-02 메모). 그분 `utils/schedule.py` 의 `Slot.modules`(`평일 09:00 mail,orders`)·
interval 모드(끝난 시각부터 센다)는 참고만 했다 - 코드는 가져오지 않는다.

## 1. 목적 (사용자)

- 설정을 현황 화면에서 떼어 한 메뉴로 모은다. 앱이 늘면 앱마다 그 메뉴에 설정이 붙는다.
- 시각마다 돌릴 모듈을 다르게: 예) 10시 전체, 11·12시 물류관리만.
- 시간대 동안 되풀이: 예) 10~11시 물류관리를 성공할 때마다 2분 쉬고 다시.

## 2. 정한 것 (2026-10-06)

| 질문 | 답 |
|---|---|
| RPA 화면에 남길 것 | **실행 카드(단추·토큰 줄)·이번 달 사용량만**. 실행 모듈·쇼핑몰 프리셋·자동 실행은 환경설정으로 |
| 요일 | **모든 줄이 같이 쓰는 요일 하나** (지금처럼). 줄마다 요일(B안)은 "변덕스러운 업체가 요구할 수 있다" - 저장 모양에 자리만 둔다 |
| 하루 줄 수 | **업체마다 '자동 실행 개수'** - 기본 2, 우리가 관리 화면에서 늘려 준다 (유료 옵션 자리). 시각 1줄·반복 시간대 1줄을 똑같이 1로 센다 |
| 한도를 낮추면 | **넘는 줄은 안 돈다** - 시각 순으로 앞 N줄만, 나머지는 "한도를 넘어 쉬는 중" |
| 반복 중 실패 | **그 시간대 반복을 멈춘다** (사용자: 납득이 쉽다. 마음은 '쉬고 다시' - `on_fail` 칸으로 나중에 넓힐 자리) |
| '대상 없음' 토큰 | **어디서나 안 센다** - '완료' 만 뺀다 (업체가 좋아하고 규칙이 단순). 토큰 설계 2절을 바꾼다 (6-5) |
| 빈 반복 회차 | **기록에 안 올린다** - 자동 실행 칸에 "오늘 반복 24회 · 처리 2회" 로만 |
| 멈춘 반복 | RPA 화면 실행 칸의 **[반복 다시 시작]** (시간대가 남아 있을 때) |
| 반복에 쇼핑몰 받기 | **못 고른다** ('전체' 도 안 됨) - 2분마다 쇼핑몰에 로그인하면 계정이 잠길 수 있다 |
| 모듈 넘기기 | 루틴을 **띄울 때 함께 넘긴다** (환경 변수). 비밀번호가 든 사용자 설정 파일은 안 건드린다 |
| 반복 담당 | **PC 예약기**가 회차마다 루틴을 새로 띄운다 (루틴 안에서 되풀이하지 않는다 - 쉬는 사이 다른 실행 가능, 한 회차가 죽어도 다음은 새로) |
| 떠날 때 확인 | 적용 안 한 변경이 있으면 묻는다 |

## 4. 1부 - 환경설정 메뉴

- **메뉴:** 사이드바 '관리' 아래 **'환경설정'** (계정 위). 관리자·총괄만 - 유저는 링크가 없다 (그래도 열리면 "관리자만 볼 수 있습니다").
  PC 마다라서 위쪽 PC 고르기를 쓴다 (`perPc`).
- **구성:** 앱 이름 머리("RPA") 아래 카드 셋 - 실행 모듈 · 쇼핑몰 프리셋 · 자동 실행. 넓은 화면은 두 칸(왼쪽 실행 모듈·쇼핑몰
  프리셋, 오른쪽 자동 실행 - 3부로 길어진다), 좁으면 한 칸. 적용 단추는 지금처럼 카드마다. 앱이 둘이 되면 위에 앱 탭 (지금은 안 만듦).
- **실행 모듈 카드**에 한 줄 더: "전체 실행과 '전체' 예약이 이 모듈을 돌립니다" (2부의 '고르기' 와 헷갈리지 않게).
- **떠날 때 확인:** 카드 하나라도 적용 안 한 변경이 있으면 다른 메뉴·다른 PC 로 갈 때 "적용하지 않은 변경이 있습니다. 버리고
  나갈까요?" (`confirm`). 아니오면 그대로 남는다.
- **RPA 화면:** 오른쪽 열에 실행 카드와 이번 달 사용량만 (관리자만 - 지금처럼 유저는 열이 없다).
- **코드:**
  - `firebase/web/settings.js` (새) - '환경설정' 페이지 껍데기. `APPS` 가운데 `settings` 를 내보내는 앱의 설정 화면을 붙이고,
    `dirty()` 로 떠날 때 확인.
  - `firebase/web/rpa-settings.js` (새) - `rpa.js` 의 설정 카드 셋(실행 모듈·쇼핑몰 프리셋·자동 실행)과 그 함수들을 옮긴다.
    현황 `live` 를 따로 구독한다 (지금 값·PC 가 적은 예약 상태).
  - `firebase/web/rpa-common.js` (새) - 둘이 같이 쓰는 것: 경로 `P`, `esc`, 모듈 표(`MODULES`·`LOCKED`·`NEEDS`), 요일·시각 글,
    명령 보내기(`sendCommand`·`watchCommand`·토스트).
  - `app.js` - `PAGES = [settings, account]`, `mount()` 가 바꾸기 전에 `current.dirty?.()` 를 묻는다 (PC 바꾸기도).
- **시험** (`firebase/tests/check_web.py`): 설정 카드 시험(모듈·프리셋·자동 실행 적용, 잠금, 딸린 모듈)을 환경설정 페이지로
  옮긴다. 더함: 유저는 '환경설정' 링크 없음, RPA 화면에 설정 카드 없음, 떠날 때 확인(예 → 버림 / 아니오 → 남음), 환경설정에서
  PC 바꾸기.

## 5. 2부 - 시각별 모듈과 업체 한도

### 5-1. 저장 모양

웹 `apps/rpa/settings/{cid}/{pcId}/schedule` 과 PC `RPA_STATUS/settings.json` 의 `schedule` 이 같은 꼴:

```
schedule: {
  enabled: true,
  days: [0,1,2,3,4],                              // 모든 줄이 같이 쓰는 요일 (월=0)
  slots: [
    { at: "10:00" },                              // run 이 없으면 '전체'
    { at: "11:00", run: ["Login","Logistics"] },  // '고르기'
    { at: "13:00", run: ["Prepare","Login","Sales"] }
  ]
}
```

- **'전체'** = 지금의 전체 실행 그대로: 쇼핑몰 받기(프리페어) + 실행 모듈 카드에서 켠 모듈.
- **`run` 키:** `Prepare`(쇼핑몰 받기 - 쇼핑몰 프리셋 카드에서 켠 것) + 루틴 설정 키 `Login`·`Sales`·`Hold`·`Logistics`·`Output`.
  검사: 모르는 키·중복은 거절, 루틴 모듈이 하나라도 있으면 `Login` 을 늘 넣는다 (실행 모듈 카드처럼 못 끈다 - 쇼핑몰 받기만
  고른 줄에는 없다), `Output` 은 `Logistics` 와 같이 ("운송장 출력은 물류관리와 같이 골라야 합니다"), 로그인 말고 하나는 있어야
  ("모듈을 하나 이상 고르세요").
- **시각:** 5분 단위 (`SCHEDULE_MINUTE_STEP`), 같은 시각 두 줄은 거절, 저장할 때 시각 순으로 정렬.
- **넓힐 자리:** 줄마다 요일은 `slots[i].days` (없으면 위 `days`) - 지금은 안 받는다. 3부가 같은 줄에 `until` 등을 더한다.
- **PC 가 더 적는 칸** (화면은 읽기만, `live.schedule` 로 올라간다): `policy` {limit, off, read_at} (5-3),
  `next_run_at`(지금처럼 날짜·시각) 과 `next_slot`(그 줄의 `at`), 기존 `last_launch_*`·`last_error`, 3부의 `repeat`.
  반복 시간대는 시작 시각을 다음 실행으로 센다.
- **옛 모양:** `{days, times}` 는 새 판이 읽을 때·적용할 때 `slots: [{at}]` (모두 '전체') 로 바꾼다. 거꾸로는 안 한다 (옛 판으로
  되돌리면 예약을 다시 넣어야 한다).

### 5-2. 실행

- **무엇을 띄우나** (`rpa_dashboard`): 그 줄의 `run` 으로 - 없으면 `all` (지금 그대로), `Prepare` 만 → `prepare`,
  `Prepare` 없음 → `routine`, 둘 다 → `all`.
- **넘기기:** `launch(target, by, env=None)` 가 자식 환경에 더한다 - `RPA_RUN_MODULES=Login,Logistics` (루틴 키만, '전체' 면 없음),
  `RPA_RUN_TRIGGER=auto`. `Run_All.bat` 을 거쳐도 그대로 물려받는다. 프리페어는 안 본다.
- **루틴** (`run_routine.main`): `RPA_RUN_MODULES` 가 있으면 사용자 설정의 Routine 섹션 대신 그 목록 (Login 은 늘 켬, Logistics
  가 없으면 Output 끔). 로그 "이번 실행 모듈 (예약): 로그인 / 물류관리". 모르는 키는 경고하고 무시, 남는 게 없으면
  '중단' ("이번 실행 모듈이 비었습니다"). 단추로 띄운 실행·손으로 켠 exe 는 변수가 없어 지금 그대로.
- **업체가 안 쓰는 모듈:** 화면이 숨기고, 예약기가 띄울 때 `policy.off` 를 한 번 더 뺀다 (정책을 나중에 바꾼 경우). 빼고 나서
  로그인만 남으면 띄우지 않고 `last_error` "업체가 쓰지 않는 모듈만 남아 건너뜁니다".
- **다음 실행 표시:** 상태 띠 "다음 자동 실행" 이 `10월 7일 (화) 11:00 · 물류관리` 처럼 '고르기' 면 모듈 이름까지 (웹이
  `next_slot` 으로 그 줄을 찾는다). 예약 칸 토큰 안내 "다음 예약 실행에 N개" 는 그 줄의 모듈로 센다 - 에이전트가
  `live.tokens.cost.next` 를 더한다 (없으면 지금처럼 `all`).

### 5-3. 업체 한도 '자동 실행 개수'

- **자리:** `meta/companies/{cid}/apps/rpa/limits/schedule` = 0~12 정수, 없으면 **2**. 규칙상 총괄·Admin SDK 만 쓴다 (업체 관리자는 못
  올린다 - 지금 `meta` 규칙 그대로).
- **관리 화면** (AFTERMARKET_SETUP 업체 상세): `자동 실행 개수 [ 2 ] [저장]` + 안내 "기본 2. 시각과 반복 시간대를 합친 줄 수".
  `ops.setScheduleLimit(cid, n)` (0~12 정수 아니면 Refused), `companyDetail` 에 값, `POST /api/companies/:cid/limits`,
  기록 `자동 실행 개수 {cid} = n`. 터미널 `node setup.js slots <업체코드> [개수]` (개수가 없으면 지금 값).
- **웹:** 자동 실행 카드 머리에 "2/3 사용", 한도에 닿으면 [+ 시각]·[+ 반복 시간대] 잠김 + "자동 실행은 3개까지입니다. 더 필요하면
  담당자에게 문의하세요" (0 이면 "자동 실행을 쓰려면 담당자에게 문의하세요"). 한도를 넘는 줄에는 "한도를 넘어 쉬는 중", 그 상태로는
  적용이 안 된다 (줄여야 한다).
- **에이전트:** 10분마다 (값표처럼) `meta/companies/{cid}/apps/rpa` 를 한 번 읽어 `settings.json schedule.policy` 에 `limit`·`off`
  를 적는다 - 껐다 켜도, 인터넷이 끊겨도 마지막 값. `set_schedule` 은 저장 전에 한 번 더 읽어 줄 수가 한도를 넘으면 거절
  ("자동 실행은 N개까지입니다") - 못 읽으면 마지막 값. 한 번도 못 읽었으면 한도로 자르지 않는다 (PC 상한 12 까지만 - 토큰과 같은
  원칙, 인터넷 사정으로 업무가 멈추지 않게).
- **예약기:** 시각 순 앞 `limit` 줄만 돈다. PC 쪽 절대 상한 12 (`SCHEDULE_MAX_SLOTS`, 지금 `SCHEDULE_MAX_TIMES` 3 을 바꾼다).

## 6. 3부 - 시간대 반복

### 6-1. 저장 모양과 검사

2부의 줄에 칸을 더한다:

```
{ at: "11:00", until: "12:00", rest_min: 2, run: ["Login","Logistics"], on_fail: "stop" }
```

- `until` 이 있으면 반복 시간대. `at` < `until`, 둘 다 5분 단위, 자정을 넘기지 않는다.
- `rest_min` 1~60 정수, 기본 2. `on_fail` 은 지금 `"stop"` 하나 (나중에 '쉬고 다시').
- `run` 은 꼭 있어야 하고 (반복에 '전체' 없음) `Prepare` 를 못 넣는다 ("반복에는 쇼핑몰 받기를 넣을 수 없습니다").
- 반복 시간대끼리 겹치면 거절, 시각 줄이 시간대 안(`at` ≤ t < `until`)이면 거절 ("11:00~12:00 반복 안에는 시각을 넣을 수
  없습니다"). 끝 시각과 같은 시각(12:00)은 된다.
- 한도에는 1줄로 센다.

### 6-2. 동작 (PC 예약기 `rpa_dashboard.Scheduler`, 5초마다)

- **시작:** 그날 요일이고 시간대가 열리면 바로 첫 회차. 다른 실행이 돌고 있거나 옵저버가 켜져 있으면 지금 예약처럼 기다린다 (까닭 표시).
- **띄우기:** `routine` + `RPA_RUN_MODULES` + `RPA_RUN_TRIGGER=repeat`. 토큰 확인은 `launch` 안의 `TOKEN_GATE` 그대로 - 0 이하면
  (시각 줄처럼 다음으로 넘기지 않고) 반복 멈춤, 까닭 "토큰이 없습니다 …". 충전한 뒤 [반복 다시 시작].
- **회차가 끝나면** (루틴 상태 파일, 띄운 시각 뒤에 시작한 실행인지 확인):
  - 성공 ('대상 없음' 포함) → `회차 +1`, 로그인 말고 '완료' 모듈이 있으면 `처리 +1`, 쉬었다가 다음 회차.
  - 실패·중단·오류 → 그 시간대 반복 멈춤 + 까닭 "10:23 물류관리 실패로 반복을 멈췄습니다: <사유>".
- **쉬는 시간:** 마지막으로 끝난 실행(누가 띄웠든 - 루틴·프리페어 상태 파일의 끝난 시각) + `rest_min` 이 다음 회차.
- **끝 시각:** 새 회차는 안 띄운다. 돌고 있는 회차는 끝까지 (끝나면 횟수만 센다). 자동 실행을 꺼도 같다.
- **단추로 누른 실행:** 쉬는 사이에 된다. 끝나면 쉬고 이어 간다. 그 실행의 실패는 반복을 멈추지 않는다 (반복 회차만 본다).
- **시간대 중에 예약을 고쳐 적용하면:** 같은 시간대(`at`·`until` 이 같음)면 상태(횟수·멈춤)를 이어 가고, 바뀌었으면 새로.
- **에이전트가 다시 켜지면** (재부팅 등): 아직 시간대 안이고 멈춘 상태가 아니면 이어 돈다. 정한 시각은 지나면 건너뛰지만(resync)
  시간대는 '그 사이' 라 이어 도는 것이 맞다. 띄워 둔 회차가 아직 돌면 끝나기를 기다렸다가 그 결과를 센다.
- **상태 칸** `schedule.repeat` (settings.json → `live.schedule.repeat`): `{date, at, until, runs, done, stopped: {at, reason} | null,
  last_launch_at, next_at}`. 날이 바뀌거나 다른 시간대가 열리면 새로.

### 6-3. 빈 회차

- 루틴이 `RPA_RUN_TRIGGER` 를 상태·이력에 `trigger` 로 남긴다.
- 끝낼 때 **반복 회차 + 성공 + 로그인 말고 '완료' 모듈 없음** 이면 이력에 쓰지 않는다 - `rpa_status.finish(result, reason,
  record=False)`. 기록 탭·최근 20일·Firestore 기록이 모두 이력에서 나오므로 한 곳에서 빠진다. 상태 파일(지금 상태)은 그대로 써서
  현황에는 보인다. 쓴 토큰이 0 이라 토큰과 상관없다 (6-5).
- 처리한 반복 회차는 기록 표 프로그램 칸에 "루틴 · 반복".

### 6-4. 다시 시작

- RPA 화면 실행 칸 (관리자만): `repeat.stopped` 이고 시간대가 남아 있으면 "반복 멈춤: 10:23 물류관리 실패" + **[반복 다시 시작]**.
- 새 명령 `resume_repeat` (args 없음) → `rpa_dashboard.resume_repeat()`: 열린 시간대의 멈춤을 풀고 바로 다음 회차. 아니면 실패
  "지금은 멈춘 반복이 없습니다". 에이전트 `KNOWN_TYPES` 와 **데이터베이스 규칙의 명령 종류 목록**에 더한다.

### 6-5. 토큰 규칙 바꿈

- `agent.USED_STATES = ("done",)` - 실패·건너뜀·중단에 더해 '대상 없음' 도 안 뺀다. 단추·예약·반복 모두.
- 이미 올라간 기록의 `used`·`cost` 는 그대로 (기록은 만들기만). 새 판의 에이전트부터 - 업체 통장은 새 판을 깐 뒤에 만들면 깔끔하다.
- 이번 달 사용량 카드의 '회' 도 '완료' 만 (기록의 `used` 를 더하므로 따로 고칠 것 없음).
- 토큰 설계서 (`2026-10-06-tokens-design.md`) 2절 '언제 빠지나' 와 4절 `usage` 설명을 고친다.

### 6-6. 화면

- 자동 실행 카드에 [+ 반복 시간대] - 줄 `11:00 ~ 12:00 반복  ■물류관리  [2]분 쉬고  [빼기]` (모듈 단추에 쇼핑몰 받기 없음).
- 카드 아래: "오늘 반복 24회 · 처리 2회", 멈췄으면 그 까닭 (빨강).
- 상태 띠 "다음 자동 실행": 시간대 안이면 "반복 중 · 12:00까지" (다음 회차 시각), 멈췄으면 "반복 멈춤".

## 8. 한계·위험 (사용자에게 알림)

- 떠 있는 ERPia 에서 물류관리를 연달아 들어가는 것은 실측 전이다 (6-7). 막히면 30분~1시간 더.
- 반복 시간대 동안 그 PC 는 사실상 RPA 전용 (화면·마우스를 RPA 가 쓴다). 쉬는 2분 사이에만 사람이 쓸 수 있다.
- 업체 정책·한도를 바꾸면 PC 에는 10분 안에 닿는다. 화면은 바로 따른다.
- 옛 판 PC 는 시각만 ('전체'). 새 판을 깔아야 시각별 모듈·반복.
- 손으로 켠 exe 는 예약과 상관없이 실행 모듈 카드대로 돈다.
- 실행이 쉬는 시간보다 오래 걸리면 1시간에 도는 회차가 그만큼 준다 (끝난 시각부터 쉬므로 겹치지는 않는다).
