# 오토파일럿 스탠드얼론 (로컬 서버) 설계

- 작성 2026-11-23, 사용자 요청 "업체가 구글 firebase 를 통한 웹 접근을 허용하고 싶지 않음 → 스탠드얼론(옵저버 포함), 로컬 서버 위에서"
- 관련 기록: 옛 옵저버 단독 버전(2026-11-03, 폐기 - 원격 `observer-standalone` 브랜치), 회사 서버로 옮기기 2단계 메모, `server_info.py`

## 1. 왜 만드나

고객사가 PC 와 브라우저가 Google Firebase(로그인·실시간 DB·Firestore·Hosting)에 닿는 것을 허용하지 않는다.
지금 오토파일럿의 실제 일(ERPia 처리 PROCESS, 쇼핑몰 수집 ACTOR, 옵저버 기록, 예약 실행)은 이미 PC 안에서 돌고,
Firebase 는 **PC 를 밖에서 보고 시키는 통로**(업체 웹·명령·현황·실행 기록·토큰·업데이트·휴대폰 인증번호 중계·AI 키)다.
그 통로를 **고객 PC 안의 로컬 서버**로 바꾼 버전을 만든다.

## 2. 사용자가 정한 것 (2026-11-23)

| 항목 | 결정 |
|---|---|
| 서버 위치 | **(나) PC 마다 자기 로컬 서버, 그 PC 에서만 본다.** 나중에 (가) 사내 한 대 서버로 바뀔 수 있다 |
| AI 어시스트 | **완전 제외** |
| 바깥 연결 | 쇼핑몰·ERPia·메일 서버는 허용(업체가 봐줌). 그 밖(Firebase·Google·우리 업데이트 사이트·Anthropic)은 0 |
| 판매 | **1회 구매, 토큰 무제한** |
| 복사 막기 | **PC 에 묶는다** (구매한 PC 에서만 켜진다) |
| 휴대폰 인증번호 | 앱이 사내 와이파이로 그 PC 의 로컬 서버에 붙는 방식 (조건부 - 7절) |
| 문서 | 스탠드얼론용 사용설명서·보안 문서를 하나씩 더 |

## 3. 목표 · 하지 않을 것 · 실패로 볼 것

**목표**
- 스탠드얼론 PC 는 쇼핑몰·ERPia·메일 서버 말고는 회사 밖으로 한 바이트도 보내지 않는다. 업체 웹 화면에서도 Google 글꼴·CDN 을 부르지 않는다.
- 업체가 지금 쓰는 기능(현황·실행·중단·예약·모듈·프리셋·실행 기록·옵저버·ACTOR·휴대폰 인증번호)을 그 PC 브라우저에서 그대로 쓴다.
- 일반(Firebase) 버전과 **같은 코드**에서 나온다. 고치면 두 버전에 같이 들어간다.
- 나중에 (가)로 갈 때 서버만 다른 PC 로 옮기면 되는 모양.

**하지 않을 것 (이번 범위 밖)**
- (가) 사내 한 대 서버 - 모양만 열어 둔다 (12절).
- AI 어시스트 (스탠드얼론 설치본에 코드째 넣지 않는다).
- 토큰·사용량·요금 화면.
- 자동 업데이트·되돌리기 (새 버전은 설치 파일로).
- PC 사이 프리셋 옮기기 (PC 가 하나뿐인 (나)에서는 상대가 없다 - 11절 결정 1).
- 우리 쪽 관리 화면(AFTERMARKET_SETUP)·관리 웹 - 스탠드얼론 PC 는 우리가 원격으로 보지 않는다.

**실패로 볼 것 (돌아가도 실패)**
- 스탠드얼론 설치본이 어떤 경로로든 Firebase·Google·Anthropic·우리 업데이트 사이트에 연결을 시도한다 (실패해도 시도 자체가 실패).
- 로컬 서버의 관리 화면·명령 창구가 그 PC 밖(사내망)에서 열린다.
- 일반 버전 동작이 바뀐다 (일반 버전 시험·샌드박스가 그대로 통과해야 한다).
- 구매하지 않은 PC 에 설치본을 복사하면 켜진다.

## 4. 만드는 방법 (고른 것과 버린 것)

| 안 | 모양 | 장점 | 단점 |
|---|---|---|---|
| **A. 같은 코드 + 서버 종류 바꿔 끼우기 (고름)** | 에이전트가 쓰는 `fb.py` 와 같은 꼴의 `local_store.py` 클라이언트, 업체 웹은 데이터 부분(`data.js`)만 두 가지 구현. 설치할 때 '버전 종류'(일반/스탠드얼론)를 정한다 | 고침이 두 버전에 같이 감. (가)로 갈 때 서버 주소만 바꿈 | 처음에 데이터 읽는 자리를 한 곳으로 모으는 정리가 든다 |
| B. 따로 브랜치 | 11-03 옵저버 단독처럼 갈라서 고침 | 처음은 빠름 | 고칠 때마다 두 번, 이미 한 번 폐기된 방식 |
| C. 옛 로컬 대시보드(dashboard.html) 되살리기 | 8765 화면을 다시 씀 | 서버 코드가 이미 있음 | 화면이 지금 업체 웹과 달라져 기능·모양이 두 벌 |

A 를 고른 까닭: 사용자가 원하는 건 '지금 제품을 Firebase 없이' 이고, (가)로 바뀔 가능성까지 있다. (Claude 판단, 사용자에게 2026-11-23 추천으로 말함)
관리는 사용자 지시로 브랜치 `StandAlone` 에서 한다 (11절 5). 코드 모양은 A(버전 종류 나누기)로 짜서, 브랜치에 있어도 develop 을 합쳐 받기 쉽고 나중에 develop 으로 합칠 길도 남긴다.

## 5. 전체 모양 ((나) 한 PC)

```
[같은 PC 의 브라우저] ──http://127.0.0.1:<웹 포트>──▶ ┌──────────────────────────┐
                                                     │ 로컬 서버 (local_server)  │
[에이전트(지금 agent.py)] ──127.0.0.1──────────────▶ │  - 계정·세션              │
     │  real_actions: 실행·중단·예약·모듈·프리셋      │  - 저장소: 현황·명령·기록  │
     ▼                                               │  - 업체 웹 파일 내주기     │
[PROCESS · ACTOR · 옵저버] (지금 그대로)             │  - 라이선스 확인           │
                                                     └────────┬─────────────────┘
[휴대폰 앱] ──사내 와이파이 https://<PC IP>:<휴대폰 포트>───────┘ (인증번호 창구 하나만 사내망에)
```

- **로컬 서버**는 감독 프로그램(background.py)이 에이전트와 함께 띄우고 지킨다. 새 exe 를 만들지 않고 지금 내장 파이썬으로 돈다.
- **웹 포트**는 127.0.0.1 에만 묶는다. **휴대폰 포트**만 사내망(0.0.0.0)에 묶고, 그 포트에서는 인증번호 창구 말고 아무것도 답하지 않는다.
- 에이전트는 지금처럼 '현황 올리기·명령 받기·기록 올리기' 를 한다. 받는 쪽이 Firebase 에서 로컬 서버로 바뀔 뿐이다. (같은 프로세스로 합치지 않는 까닭: (가)에서 에이전트는 각 PC, 서버는 한 곳으로 갈라져야 한다.)
- **ACTOR 실행·옵저버도 서버에 직접 붙는다**: 인증번호 중계는 에이전트를 거치지 않고 `otp_relay.agent_relay`·`phone_list` 가 에이전트 계정으로 서버에 붙는다 (web_runner.py:1460, rpa_observer.py:357·1101, otp_relay.py:195). 그래서 `local_store` 클라이언트와 그 인증(에이전트 비밀 값)은 에이전트·ACTOR·옵저버 세 프로세스가 같이 쓴다.

## 6. 부분별 설계

### 6.1 버전 종류 (edition)
- `server_info.py` 에 `EDITION` 을 둔다. 설치 때 정해진 값을 ProgramData 의 설정에서 읽는다: `"cloud"`(지금) / `"standalone"`.
- 값은 **빌드 때 정해진다**: 스탠드얼론 빌드가 설치 파일에 실어 설치 마법사가 ProgramData 에 적고, 프로그램은 그것을 읽기만 한다 (화면에서 바꾸는 곳 없음). 스탠드얼론 설치 파일은 일반 버전과 **다른 AppId·같은 폴더 이름 규칙**을 쓰고, 일반 버전이 깔린 PC 에서는 설치를 멈추고 안내한다 (반대도). (Claude 판단 - 바꿔 끼우기 여부는 11절 질문)
- 스탠드얼론이면: 서버 주소는 `http://127.0.0.1:<포트>`, Firebase 값(PROJECT_ID·API_KEY·DATABASE_URL·UPDATE_BASE_URL)은 **쓰지 않고**, 그 값을 쓰는 코드 경로(업데이트 받기·Firebase 로그인·AI)는 들어가는 순간 막는다(시험으로 지킨다).
- 빌드: `tools/build_release.py --edition standalone` 이 스탠드얼론 설치 파일을 만든다. AI 어시스트 파일(`ai_rescue.py` 와 그 부르는 자리)은 이 빌드에 넣지 않는다.

### 6.2 로컬 서버 (`local_server.py`, 새로)
표준 라이브러리 `http.server`(ThreadingHTTPServer) 로 만든다. 옛 `rpa_dashboard.py` 의 함정 처리(같은 포트 두 번 뜨기 막기 `SO_EXCLUSIVEADDRUSE`, `getfqdn` 멈춤 피하기)를 그대로 쓴다.

**저장소**: 에이전트가 Firebase 에 쓰던 자리를 같은 이름으로 받는다. 꼭 필요한 자리만:

| 자리 | 지금 (Firebase) | 로컬 | 비고 |
|---|---|---|---|
| 현황 `live/<pc>` | RTDB | 메모리 + 파일 하나 | 웹에 SSE 로 바로 밀어 줌 |
| 명령 `commands/<pc>` | RTDB | 메모리 + 파일 | 상태 queued→running→done/failed, 만료는 지금과 같은 값 |
| 실행 기록 `runs` | Firestore | SQLite (`runs.db`) | 날짜·PC 로 거르기, 최근 N 개 |
| 업체 정책 `meta/companies/<cid>/apps/rpa/{modules,limits,features}` | RTDB | **라이선스 파일에서** | 6.4 |
| 휴대폰 목록 `meta/companies/<cid>/phones` | RTDB | 짝지은 휴대폰 표 (SQLite) | 7절 |
| 인증번호 `apps/otp/{requests,codes}` | RTDB | 메모리 (2분, 쓰면 지움) | 지금 약속(CONTRACT) 그대로 |
| 토큰 `wallet`·`meta/prices` | Firestore·RTDB | **없음** | 무제한 - 토큰 막기 항상 통과 |
| AI 키 `aikey` | RTDB | **없음** | |
| 프리셋 옮기기 `transfers` | RTDB | **없음** | (나)에선 끔 |

**HTTP 창구** (웹·에이전트 공용, 모두 JSON):
- `POST /api/login`·`/api/logout`·`/api/password` - 6.5
- `GET /api/stream` - SSE: 현황·명령 상태가 바뀔 때마다 (Firebase `onValue` 대신)
- `POST /api/commands` - 웹이 명령을 넣는다 (관리자만), `GET /api/commands/<id>`
- `GET /api/runs?date=&limit=` - 실행 기록
- `GET /api/policy` - 라이선스에서 읽은 모듈·기능·한도·업체 이름
- 에이전트 전용 `/agent/...` - 현황 올리기·명령 받기(롱폴 또는 SSE)·상태 표시·기록 올리기. 에이전트는 **에이전트 비밀 값**(설치 때 만들어 ProgramData 에 관리자만 읽게 저장)으로 인증.
- 모든 쓰기 요청: 세션 쿠키(HttpOnly·SameSite=Strict) + `Origin`/`Host` 검사 + 머리글 `X-RPA-Action: 1` (옛 대시보드와 같은 CSRF 막기).

**에이전트 쪽**: `firebase/agent/fb.py` 의 `Client` 와 같은 메서드(put/patch/get/delete/stream/server_now/renew/token, Firestore 용 fs_create/fs_get/fs_sum)를 가진 `local_store.py` 클라이언트를 만들어 `EDITION == "standalone"` 이면 그걸 쓴다. fs_* 는 SQLite 실행 기록으로 받는다.
에이전트에서 따로 손볼 곳 (검토에서 찾음 - 분기 하나로 끝나지 않는다):
- 자기 확인: 지금은 로그인 토큰의 role=agent·cid·pcId 로 확인한다 (agent.py:1381·1500) → 라이선스의 업체 코드·PC 번호로.
- 다른 PC 동시 켜짐 검사 `other_pc`(agent.py:1288), `purge_excel_pw_commands`·`cleanup_transfers`(agent.py:1528·1618) → 로컬 저장소에 맞추거나 끔.
- 설정 창의 Firebase 로그인(rpa_settings.py:497), 감독의 `warm_windows_roots`(background.py:162-186, 시작마다 googleapis·업데이트 주소를 부름) → 스탠드얼론에서 끔.
- **업체 정책을 예약 실행기까지**: 예약 실행기는 에이전트 안에서 돌고(agent.py:1561, `dash.TOKEN_GATE`), 정책은 `Policy` 가 10분마다 읽어 `dash.set_policy` 로 settings.json 에 적는다(agent.py:901-937). 스탠드얼론은 `Policy` 가 서버 대신 **라이선스**에서 읽어 같은 길로 넣는다.
- 웹이 쓰는 `apps/rpa/settings/<cid>/<pc>` 는 에이전트가 읽지 않으므로 로컬 저장소에 두지 않는다 (웹의 그 쓰기는 스탠드얼론에서 뺀다).

**서버 검사**: 지금 RTDB 규칙이 하는 검사를 로컬 서버도 똑같이 한다 - 관리자만 명령, 명령 인자는 만들 때만·엑셀 비밀번호 칸 거부, 실행·중단 명령 90초·나머지 600초 만료, 에이전트는 자기 PC 자리만. (Claude 판단 - 보안 자료가 같은 약속을 말하려면 필요. 시험은 rules.test.js 의 해당 경우를 로컬 서버 시험으로 옮긴다.)

### 6.3 업체 웹 (`firebase/web`)
- 화면 모양은 **지금 그대로**. 바꾸는 곳은 데이터 읽기뿐이다.
- Firebase SDK 를 부르는 자리(지금 app.js 4·rpa-common.js 3·rpa-settings.js 6·rpa.js 10곳)를 새 `data.js` 한 파일로 모은다. `data.js` 는 두 구현: `data-firebase.js`(지금 동작 그대로 옮김) / `data-local.js`(fetch + EventSource). 어느 것을 쓸지는 로컬 서버가 내주는 `edition.js` 가 정한다. **첫 작업은 일반 버전에서 동작이 그대로인 채 `data.js` 로 모으는 정리**이고, 일반 버전 화면 시험(check_web.py)이 그대로 통과해야 다음으로 간다.
- 스탠드얼론에서 숨기는 것: 토큰 막대·토큰 사용량, AI 표시, [업데이트]·[되돌리기], 프리셋 옮기기, PC 고르기(한 대뿐), 총괄 화면.
- 바깥 파일: index.html 의 Google Fonts·jsdelivr, account.js 의 gstatic 을 **로컬 사본**으로 (스탠드얼론 설치본에 글꼴·아이콘 파일을 싣는다). 일반 버전도 같이 바꿀지는 만드는 사람 판단(바꾸면 보안 머리글 CSP 에도 좋다).
- 로컬 서버가 이 파일들을 내준다. 보안 머리글: CSP `default-src 'self'`, `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`.

### 6.4 라이선스 (PC 에 묶기)
- **라이선스 파일** `license.json` = {업체 이름, 업체 코드, PC 번호, 발급일, 모듈·기능(웰라이프 등)·한도(예약 줄 수·동시 실행 수), 버전 종류 "standalone"} + **우리 서명**.
- PC 번호 = 윈도우 `MachineGuid` (11-03 단독 버전과 같은 값, `release/PC번호_확인.bat` 를 되살림).
- 서명 열쇠는 **업데이트 서명 열쇠와 따로** 만든다 (라이선스 열쇠가 새도 업데이트 서명은 안전하도록). 개인 열쇠는 우리 PC 의 Keys 폴더에만, 공개 열쇠는 프로그램에 싣는다. 발급 도구 `tools/make_license.py <PC번호> <업체 정보 파일>`.
- 확인 시점: 로컬 서버·에이전트·PROCESS·ACTOR·옵저버가 켤 때. 맞지 않으면 켜지지 않고 "이 PC 의 라이선스가 아닙니다 (PC 번호 …)" 를 보여 준다. 설치 마법사는 라이선스가 없으면 PC 번호를 보여 주고 파일을 고르게 한다.
- 설치 파일은 **모든 업체 공용 하나**, 라이선스만 PC 마다 다르다. 그래서 새 버전 설치 파일을 PC 마다 다시 만들 필요가 없다. (11-03 단독 버전은 설치 파일 자체를 PC 마다 만들었다 - 버린 까닭: 업데이트 때마다 PC 수만큼 빌드)
- 업체 정책(모듈·웰라이프 기능·한도)은 지금 관리 화면 대신 라이선스에 실린다 → 바꾸려면 새 라이선스를 발급한다.
- 윈도우를 다시 깔면 MachineGuid 가 바뀐다 → 새 라이선스 발급 (사용설명서에 적는다).

### 6.5 로그인 · 계정
- 계정은 그 PC 의 로컬 서버에 둔다 (pbkdf2 해시, 옛 대시보드 방식). 역할은 지금 웹과 같이 **관리자 / 사용자(보기만)** 둘.
- 설치 마무리 때 관리자 계정을 만들고 첫 로그인에 비밀번호를 바꾸게 한다 (기본 비밀번호 없음).
- 지금 업체 웹과 같은 규칙: 30분 자동 로그아웃(단추의 남은 시간 표시 포함), 5번 틀리면 잠깐 잠금, 세션은 서버를 다시 켜면 풀림.
- **보기만 하는 계정 추가·삭제**: 지금은 우리 쪽(setup.js·관리 화면)이 만들지만 스탠드얼론은 우리가 손댈 수 없으므로, 업체 웹 환경설정에 관리자만 보는 '계정' 칸을 새로 둔다 (추가·사용 중지·비밀번호 다시 정하기). 화면은 지금 웹 모양을 따르고, 새 모양이 필요하면 시안 먼저. (Claude 판단)
- **관리자 비밀번호를 잊었을 때**: 그 PC 의 윈도우 관리자 권한으로 여는 설정 창에 [관리자 비밀번호 다시 정하기] 를 둔다 (UAC 를 거쳐야 하므로 PC 를 관리하는 사람만). 다시 설치하지 않는다. (Claude 판단)
- 웹 포트가 127.0.0.1 뿐이라 그 PC 에 앉은 사람만 열 수 있다. 로그인은 같은 PC 를 쓰는 다른 사람(보기만 하는 직원)과 관리자를 가르는 용도.

### 6.6 설치 · 업데이트
- 스탠드얼론 설치 파일 `AUTOPILOT_Standalone_Setup_<버전>.exe`. 마법사: 라이선스 고르기 → (지금 설정 창의 ERPia 위치 등) → 관리자 계정 만들기. 에이전트 계정(기계 계정) 입력 단계는 없다.
- 업데이트는 **새 설치 파일을 덮어 설치**. 설정·기록·라이선스·계정은 남는다. 자동 업데이트 도우미·3분 점검·되돌리기는 스탠드얼론에서 쓰지 않는다.
- 파일 변조 감지(tampered 면 실행 막기)는 그대로 둔다. 복구는 '같은 버전 설치 파일로 다시 설치' 로 안내.
- 설정 폴더 권한 정리(lock_data_acl)는 그대로.

### 6.7 옵저버 · ACTOR · PROCESS
- 코드 경로는 그대로. 다르게 되는 곳:
  - 인증 휴대폰 목록 = 짝지은 휴대폰 (7절).
  - AI 어시스트 칸·호출 없음 (빌드에서 빠짐 - 부르는 자리는 '없으면 끔' 으로).
  - 토큰 막기 항상 통과.
- 옵저버의 프리셋 옮기기(내보내기·받기) 단추는 숨긴다.

## 7. 휴대폰 인증번호 ((나)에서)

**조건** (업체 망 확인 필요 - 사용설명서·보안 문서에 적는다)
1. 휴대폰(사내 와이파이)과 PC 가 서로 닿는 망이어야 한다. 무선 격리·손님용 와이파이면 안 된다.
2. 그 PC 의 윈도우 방화벽에 휴대폰 포트 하나를 '개인/도메인' 망에서만 연다 (설치 마법사가 휴대폰을 쓸 때만 규칙을 만든다).
3. PC 주소가 바뀌면 다시 짝짓는다.

**짝짓기**: 웹 환경설정 '휴대폰' 에서 [휴대폰 추가] → 화면에 QR (PC 주소·포트·짝 열쇠·그 PC 인증서 지문) → 앱으로 찍음 → 서버가 휴대폰 이름·짝 열쇠 해시를 저장. 짝 열쇠는 한 번만 보여 준다.

**통신**: 휴대폰 포트는 HTTPS(그 PC 가 처음 켤 때 만든 자체 서명 인증서). 앱은 QR 의 지문과 맞는 인증서에만 붙는다(지문 고정) → 같은 망의 다른 기기가 흉내 내거나 엿볼 수 없다. 창구는 지금 RTDB `apps/otp` 약속과 같은 뜻: '열린 요청 있나' 확인, '번호 보내기'(본문 아님·번호만·발신번호 일치·2분·쓰면 지움).

**앱 쪽**: 휴대폰 앱 코드는 비공개 저장소 `TE-JA-VA/RPA-PhoneRelay`(맥에서 빌드)에 있다. 그 저장소에 '로컬 서버로 보내기' 방식(QR 짝짓기·지문 고정·HTTPS)을 더한다 - 이 저장소에서는 **약속 문서와 휴대폰 흉내 시험**(지금 `firebase/tests/check_phone_relay.py` 처럼)을 먼저 만들어 넘긴다. 아이폰 단축어는 이번 범위 밖(만드는 사람이 가능하면 같은 창구를 쓰게).

**안 될 때**: `otp_relay.ManualOtp` 가 이미 있지만 지금은 옵저버 미리보기에서만 쓰이고(rpa_observer.py:360), 따로 창을 띄우는 게 아니라 **사이트의 인증 칸에 사람이 직접 칠 때까지 기다리는** 방식이다(otp_relay.py:162-189). 스탠드얼론에서는:
- 그 사이트에 짝지은 휴대폰이 없거나 휴대폰이 2분 안에 답하지 않으면, 실제·예약 ACTOR 실행도 `ManualOtp` 로 넘어가 Edge 의 인증 칸에 사람이 넣기를 **5분** 기다린다 (11-03 단독 버전 때 사용자가 정한 5분 대기·재발송 없음과 같게).
- 5분 안에 안 들어오면 **그 사이트만 실패**(사유 '인증번호를 받지 못함')로 두고 다른 사이트는 계속한다. 실행 기록과 현황에 남는다. (Claude 판단)
- 메일 2차 인증은 PC 가 메일을 직접 읽으니 영향 없음.

## 8. 바깥 연결 0 지키기

- **'바깥 연결 0' 의 뜻**: 오토파일럿 프로그램이 **스스로 여는** 연결이 쇼핑몰·ERPia·업체 메일 서버뿐이라는 뜻이다. ACTOR 가 연 Edge 안에서 쇼핑몰 페이지가 부르는 것(그 쇼핑몰의 분석 도구·reCAPTCHA 등)은 쇼핑몰 화면의 일부로, 업체 메일이 Gmail 이면 IMAP 이 Google 로 가는 것은 업체 메일 서버로 본다. Edge 자체의 Microsoft 통신은 지금 켜는 옵션 그대로 두고 보안 자료에 밝힌다. (Claude 추천 - 11절 질문)
- 스탠드얼론 내장 파이썬에서는 `anthropic` 패키지를 뺀다 (AI 완전 제외). 스탠드얼론은 설치 파일로만 바뀌므로 내장 파이썬 사본을 따로 둬도 업데이트 문제가 없다.
- 스탠드얼론 설치본에서 Firebase·Google·Anthropic·우리 업데이트 사이트 주소를 쓰는 코드 경로는 `EDITION` 검사로 막고, 시험 `tests/test_standalone_offline.py` 가 ① 스탠드얼론 빌드 재료 중 **우리 코드와 웹 파일**에 그 주소 문자열이 없는지 (내장 파이썬의 남의 패키지는 보지 않는다 - playwright 등에 주소가 들어 있다), ② 스탠드얼론 설정으로 에이전트·서버를 돌릴 때 소켓 연결 대상이 127.0.0.1 뿐인지 본다.
- 샌드박스 `tools/sandbox_test.py --standalone`: 샌드박스 안 hosts 파일로 우리 Firebase 주소(`*-default-rtdb…firebasedatabase.app`·identitytoolkit·securetoken·firestore.googleapis.com·`rpa-test-f02e0*.web.app`)·api.anthropic.com·fonts.googleapis.com·cdn.jsdelivr.net 을 막은 채 (gstatic.com 전체는 막지 않는다 - 쇼핑몰의 reCAPTCHA 가 깨진다) 설치 → 로그인 → 현황 → 명령(가짜 실행) → 기록이 돌아야 통과.

## 11. 정해야 할 것 · 만드는 사람에게 맡기는 것

**사용자가 정한 것** (설계 검토 뒤, 2026-11-23)
1. PC 사이 프리셋 옮기기: **끈다** ((가)로 갈 때 되살림).
2. 복사 막기: **컴파일로 보강** - 라이선스 확인과 변조 감지를 컴파일 조각(.pyd, `build_release.py --modules` 방식)으로 옮겨, .py 를 고쳐 확인 줄을 지우는 우회를 막는다. MachineGuid 바꾸기는 완전히 못 막는다 - 확인 조각이 MachineGuid 와 함께 윈도우 설치 정보(예: 설치 날짜·시스템 드라이브 일련번호) 하나를 더 묶을지는 만드는 사람이 정한다 (재설치 때 다시 발급하는 것은 같다).
3. '바깥 연결 0' 의 뜻: **8절 그대로** (프로그램이 스스로 여는 연결만, 쇼핑몰 화면이 부르는 것·Gmail·Edge 자체 통신은 보안 자료에 밝히기만).
4. 일반 버전이 깔린 PC 바꾸기: **없음, 새 PC 에만 깐다** (6.1 처럼 일반 버전이 깔린 PC 에서는 설치를 멈추고 안내).
5. **브랜치**: 이 일은 새 브랜치 **`StandAlone`** 에서 관리한다 (사용자 2026-11-23). develop 의 고침은 StandAlone 으로 한 방향으로 계속 합쳐 받는다. 버전 종류(edition) 나누기는 그대로 둬서, 나중에 develop 에 합칠지는 사용자가 정할 수 있게 한다. StandAlone 에서 고친 것 중 일반 버전에도 필요한 것(예: 웹 `data.js` 정리)은 develop 에 따로 옮길지 그때마다 사용자에게 묻는다.

**만드는 사람에게 맡김 (Claude 판단으로 정해 둔 것 포함)**
- 포트 번호, SQLite 표 모양, SSE 와 롱폴 중 에이전트 쪽 방식.
- 라이선스 서명 방식(Ed25519 권장 - 지금 업데이트 서명과 같은 도구로).
- 일반 버전 웹도 글꼴·아이콘을 로컬 사본으로 바꿀지.
- 실행 기록 보관 기간 기본값 (보안 자료의 '보관 기간' 과 맞춘다 - 사용자 확인 받기).

## 12. 나중에 (가)로 갈 때

로컬 서버를 사내 한 대로 옮기고, 각 PC 의 에이전트는 `local_store` 의 주소만 그 서버로 바꾼다. 그때 더할 것: 서버를 사내망에 열기(HTTPS·인증서), PC 별 에이전트 계정, 여러 PC 고르기 화면(지금 업체 웹에 있음), 라이선스를 'PC 수' 로, 프리셋 옮기기 되살리기. 이번 설계의 저장소 자리 이름에 PC 번호를 넣어 두는 까닭이다.

## 13. 차례 (계획 때 나눌 단위)

1. 웹 데이터 자리 모으기 (`data.js`, 일반 버전 동작 그대로)
2. 버전 종류 + 로컬 서버(저장소·계정·창구) + `local_store` + 에이전트 분기
3. 라이선스 + 발급 도구
4. 웹 스탠드얼론 구현(`data-local.js`)·숨기기·로컬 글꼴
5. 스탠드얼론 빌드·설치 마법사·샌드박스 `--standalone`·바깥 연결 0 시험
6. 휴대폰 창구(서버 쪽) + 약속 문서·흉내 시험 → 맥 세션에 앱 고침 부탁
7. 사용설명서·보안 자료
