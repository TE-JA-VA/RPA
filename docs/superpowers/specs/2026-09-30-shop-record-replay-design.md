# 쇼핑몰 조작 기록·재생 설계 (프리셋과 옵저버)

**날짜:** 2026-09-30
**상태:** 구현됨 (2026-10-01, 판 2026.10.01-1 - 샌드박스 33/33). 설계는 2026-09-30 사용자 승인 ("허가합니다!"), 이름은 2026-10-01 '옵저버'.
2026-10-02 미룬 것 손질 (사용자 승인 "가랏!", 판 2026.10.02-1 - 샌드박스 34/34): 미리보기 [Ⅱ 일시정지]·[■ 중단]과 창 닫기, 저장 단추·저장 날짜, 팝업이 내려 주는 파일, 알림창 한 곳, 대시보드 실행 단추 '… 실행중'·잠긴 까닭 글, 설치 파일의 옵저버 확인 (3·4·6·7절에 그날 날짜로)
2026-10-02 첫 실행에서 옵저버 exe 가 켜자마자 `OSError: [WinError 6]` → 판 2026.10.02-2 (7절)
**이 문서는 결정 기록이다.** 무엇을 왜 그렇게 정했는지 남긴다. 구현하며 바뀌면 여기에 날짜와 함께 고쳐 적는다.

## 0. 왜 하나

- 프리페어 RPA 의 '메일 작업' (로그인 → 메일 첨부 → 바탕화면 ERPIA_AI) 은 사실 **쇼핑몰 로그인 → 사람의 조작 → 엑셀 받기 → 루틴의 주문매핑 매출처리가 읽기** 를 흉내낸 것이다. 실제로 필요한 것은 쇼핑몰(지마켓·11번가·쿠팡 등)에서 엑셀을 받는 일이다.
- 쇼핑몰은 10곳이 넘고, 엑셀을 받는 순서는 곳마다 다르며 우리도 모른다. 사이트마다 코드를 짤 수 없다.
- 그래서 **어느 사이트에나 같은 옵저버** 를 둔다. 순서를 아는 사람(고객 업체 직원, 우리와 함께)이 한 번 해 보이면 기록하고, 함께 재생해 확인한 뒤, 다음 프리페어부터 혼자 따라 한다. 사이트 디자인이 바뀌지 않는 한 누르는 것은 같다고 본다.
- 가짜 쇼핑몰로 해 본 spike (버리는 코드, 아래 7절) 에서 방식이 통한다는 것을 확인했다: 새 창·iframe·매번 바뀌는 id·마우스를 올려야 생기는 메뉴·가끔 뜨는 공지·오늘 기준 날짜·'요청 → 목록에서 받기'·느린 목록·PC 가 바쁠 때.

## 1. 확정한 결정

**사용자가 고른 것** (2026-09-30)

| 질문 | 답 |
|---|---|
| 사이트마다 따로 짜나 | **아니요.** 같은 옵저버로 사람이 한 번 해 보인다 |
| 옵저버 모양 | 한 화면: 왼쪽 브라우저, 오른쪽 행위 기록(단계마다 켜기/끄기·삭제), 아래 [미리보기] [저장] (사용자 스케치) |
| 프리셋 | 기록 목록 위 ① ② ③ … 사이트마다 '로그인 ~ 엑셀 받기' 하나. **최소 2개, 최대 10개** |
| 저장 모양 | 배열: 프리셋 번호 + 이름 + 기록 (사이트코드는 루틴이 파일을 알아보는 데 필요해 더했다) |
| 주소줄 | **보인다.** 사람이 주소줄에 친 주소도 단계로 기록한다 |
| 켬/끔 | **대시보드 환경설정에서** 프리셋마다 스위치 |
| 옵저버 프로그램 | **콘솔 창 없는 따로 된 exe** (Nuitka) |
| 로그 | 콘솔 대신 **대시보드에서** - 옵저버의 [미리보기] 한 번이 대시보드 '기록' 표 한 줄 |
| 아이콘 | 프리페어·옵저버는 '나. 주황 A'. 루틴·설치 파일·설정 창·에이전트는 크림 A 그대로 (**구현됨 2026-09-30**, 커밋 `4ce8b71`) |
| 기록 중 자동 실행 | 옵저버가 떠 있으면 자동 실행은 닫힐 때까지 기다리고 실행 단추는 거절. RPA 가 돌고 있으면 옵저버가 안 켜진다 (2026-09-30 사용자 "바로 고쳐도 될 것 같은데? 진행해봐". 대시보드 쪽 **구현됨**, 옵저버 쪽은 작업 4) |
| 이름 | '쇼핑몰 기록기' 대신 **옵저버** (2026-10-01 사용자 "이름은 옵저버로 가자"). 시작 메뉴 'RPA 옵저버', exe `Prepare_Observer.exe`, 파일 `rpa_observer.py` |

**요약으로 보여 드리고 그대로 가기로 한 것**
- 옵저버는 설정 창처럼 켤 때 관리자 권한을 묻는다. 설정 폴더는 관리자만 고칠 수 있고, 비밀번호는 윈도우 계정마다 잠기기 때문이다 (DPAPI 사용자 범위).
- 기록은 설정 폴더의 프리셋 파일 하나에. 아이디와 잠근 비밀번호는 사용자 설정 `Sites` 에 프리셋마다 한 칸. 켬/끔은 그 칸의 `Stts`.
- 프리페어에 새 할 일 `replay`. 켜진 프리셋을 차례로 재생하고, 받은 엑셀을 `(사이트코드)원래이름` 으로 `ERPIA_AI_EXCEL` 에 넣는다. 루틴의 엑셀업로드가 그대로 읽는다.
- 대시보드로는 이름·사이트코드·단계 수만 간다. 기록 내용·아이디·비밀번호는 안 간다.

**내가 정한 것** (되돌리기 쉬움. 바꾸려면 말씀만)
- 새로 저장한 프리셋은 **꺼진 채(`Stts` 9)** 로 시작한다. 대시보드에서 켜야 프리페어가 돈다. 저장했다고 다음 자동 실행에 바로 끼어들지 않게.
- 미리보기로 받은 파일은 `ERPIA_AI_EXCEL` 이 아니라 기록 폴더에 둔다. 루틴이 미리보기 파일을 올리면 안 된다.
- 대시보드로 가는 로그 줄에는 칸에 친 값, 주소의 `?` 뒤를 넣지 않고, 누른 것의 글자는 20자까지만.

**고르지 않은 것**
- 사이트마다 코드 / 버튼 id 만 기억하기: 매번 id 를 바꾸는 사이트가 있다 (spike 의 가짜 쇼핑몰이 그렇다). 단서를 여러 개 적고 차례로 찾는다 (3절).
- Playwright codegen: 사이트마다 파이썬 코드를 만든다. 개발자가 아니면 검토·수정할 수 없고, 친 값(비밀번호 포함)이 코드에 들어간다.
- 브라우저를 옵저버 창 속에 끼우기 (SetParent): 한글 입력·포커스가 흔들린다. 창을 나란히 붙여 같이 옮긴다.
- 주소줄 없는 앱 모드 창: 사용자가 주소를 직접 쳐서 들어가야 한다.
- `Prepare_RPA.exe --record`: 프리페어 exe 는 로그를 보여 주려고 콘솔 창과 함께 뜬다. 옵저버에 검은 창이 같이 뜬다.
- 비밀번호를 프리셋 파일에: 파일이 사람 손을 거쳐 옮겨질 수 있다. 비밀번호는 지금처럼 사용자 설정에만, 잠가서.
- 웹에서 아이디·비밀번호 받기: 비밀번호가 인터넷을 거쳐 PC 로 온다 ("PC 밖으로 안 나간다" 원칙).

## 3. 기록·재생 엔진 `web_replay.py`

spike `rec.py` 를 옮긴다. 시험으로 확인한 규칙을 그대로 지킨다 (spike 시험 44개도 옮긴다, 9절).

**기록**
- 페이지마다 기록 스크립트를 심는다. `add_init_script` 만으로는 `window.open` 새 창의 진짜 문서에 안 심긴다 → 문서가 바뀔 때마다(`framenavigated`·`domcontentloaded`) 다시 심고, 두 번 붙지 않게 표시는 `document` 에 둔다.
- 사람이 한 것만 (`isTrusted`). 단추·링크·칸도 아니고 손가락 모양도 아닌 곳을 누른 것은 버린다 (사람은 기다리며 표 칸·제목·빈 곳을 누른다). Enter 가 만든 단추 눌림은 버린다. 더블클릭은 한 단계.
- 같은 칸에 이어 친 것은 한 단계로 합친다.
- 비밀번호 칸은 값 없이 `secret` 단계. 그 앞의 글자 칸은 `credential: "ID"` 로 바꾸고 값을 지운다. 단서에 칸의 값을 담지 않는다.
- 누를 것마다 처음 나타난 시각을 적어 '몇 단계 뒤에 새로 생긴 것' (`appearsAfter`) 으로 남긴다. 목록에 옛 파일과 새 파일이 같은 글자로 있을 때 새것만 고르기 위해서다.
- 마우스를 올려야 만들어지는 메뉴: 올린 뒤 1.5초 안에 새로 나타난 것을 누르면 앞에 `hover` 단계를 넣는다 (그 사이 다른 조작이 없을 때만).
- 주소줄 (2026-09-30 실험): 크롬 이력의 이동 종류가 `typed` 이면 `goto` 단계 (첫 `goto` 가 시작 주소), 이력 번호가 줄면 `back`, 사람이 연 새 탭은 `newtab`. 링크·로그인 뒤 이동·iframe 안 이동은 누른 것의 결과라 기록하지 않는다.
- 글자는 `textContent` 로 읽는다. `innerText` 는 PC 가 바쁠 때 표 칸 사이 띄어쓰기가 빠져 같은 옛 줄이 새것처럼 보였다.

**다듬기** (저장·미리보기 전): 단계 사이 기다린 시간, 직접 친 날짜는 '오늘 기준 며칠', 공지 닫기는 '떠 있을 때만', 끈·지운 단계를 빼고 '새로 생긴 것' 번호를 다시 맞춤.

**재생**
- 단서 순서: id → 하나뿐인 글자(정확히 같음) → name → aria-label·title·placeholder → 칸 이름(표 머리에서 몇 번째) → 위치(css) → 글자 n번째. 찾은 것의 태그·종류·글자가 기록과 같은지 본다.
- 단계 사이는 사람이 기다린 시간의 절반 (0.3~3초). '새로 생긴 것' 의 기준은 화면이 다 뜬 뒤에 잡는다.
- 가린 공지는 가로막힐 때만 닫는다. 숨은 메뉴는 보이는 위 칸에 마우스를 올린다. 알림창은 확인하고 로그에 적는다 (대시보드로 갈 때는 20자까지 - 2026-10-02).
- 받은 파일은 `(사이트코드)원래이름`. 같은 이름이 있으면 ` (1)` 을 붙인다. 파일은 누른 창이든 그 단추가 연 새 창(팝업)이든 기다린다 - 작은 창이 파일을 내려 주고 스스로 닫히는 쇼핑몰이 흔한데, 누른 창에서만 기다려 못 받았다 (2026-10-02).
- 멈추기 (2026-10-02): `cancel` 이 켜지면 단서를 찾거나 파일·기다림 중에도 0.2초 안에 멈춘다 (예전엔 다음 단계 앞에서만 - 한 단계가 20초까지 걸렸다). `pause` 가 켜져 있으면 하던 단계를 마치고 다음 단계 앞에서 기다린다.
- 못 찾으면 그 단계에서 멈추고 화면 사진을 남긴다. 몇 번째 단계를 어떤 단서로 찾았는지 로그에 남긴다.

**기록 모양** (프리셋 파일 안 `record`)
```json
{"version": 1, "start_url": "https://…/login", "record_date": "2026-09-30", "viewport": {"width": 1280, "height": 900},
 "steps": [{"kind": "goto", "page": 0, "href": "https://…/login", "gap": 0},
           {"kind": "fill", "credential": "ID", "page": 0, "frame": {"main": true}, "url": "/login", "target": {"tag": "input", "id": "…", "name": "…", "placeholder": "아이디", "css": "…"}, "gap": 2100},
           {"kind": "secret", "credential": "PW", "…": "…"},
           {"kind": "click", "target": {"text": "다운로드", "textCount": 3, "…": "…"}, "appearsAfter": 9, "download": "주문목록_….xlsx"}]}
```
- `kind`: `goto` `back` `newtab` `click` `fill` `secret` `select` `check` `enter` `hover`. `version` 이 모르는 값이면 재생하지 않는다.
- `viewport` 는 기록 때 브라우저 안쪽 크기. 재생은 같은 크기로 연다 (반응형 사이트에서 메뉴 모양이 바뀌지 않게).

## 4. 옵저버 `rpa_observer.py` → `Prepare_Observer.exe`

spike `rec_app.py` 의 화면을 옮긴다 (2026-09-30 사용자가 직접 써 보고 "아주 좋아").

**화면**
- 오른쪽 기록 창(작업 영역의 30%), 그 왼쪽에 브라우저를 붙여 같이 옮긴다. 브라우저는 주소줄·탭이 보이고, 자동화 안내 띠·비밀번호 저장 제안·다운로드 알림은 끈다.
- 위: 프리셋 번호 단추 ①~⑩ 과 [+] [−] (2개 아래·10개 위로는 안 됨. [−] 는 마지막 것만 지운다 - 번호가 밀리지 않게), 이름, 사이트코드, 아이디·비밀번호 (2026-10-02 사용자 요청으로 아래에서 옮김 - 프리셋마다 따로인 칸은 한 묶음에, 두 줄 칸 폭을 맞춘다).
- 가운데: 안내 한 줄 + [● 기록 시작] / [■ 기록 끝], 단계 목록 (켜기/끄기, ✕ 삭제). 미리보기 때 단계마다 ▶ ✓ – ✗ 와 찾은 단서. 안내는 이 한 줄뿐이다 (2026-10-02 - 아래에 한 줄이 더 있어 지난 미리보기 글이 새 기록 뒤에도 남았다). 프리셋을 바꾸면 비우고, 기록을 끝냈는데 남은 단계가 없으면 '기록된 단계가 없습니다'.
- 아래: [▶ 미리보기] [저장].
- 기록이 없는 프리셋으로 켜지면 바로 기록을 시작한다 (브라우저에 '주소줄에 주소를 치세요' 안내). 기록이 있는 프리셋에서 다시 기록하면 먼저 묻는다.
- [■ 기록 끝] 이나 브라우저 닫기: 브라우저와 그 프로필(로그인 흔적)을 지운다. 단계 목록은 남는다. 기록 중·미리보기 중에는 다른 프리셋으로 못 바꾼다.
- 기록하며 받은 파일도 기록 폴더 `data\옵저버\기록` 에 둔다 (`ERPIA_AI_EXCEL` 에 두지 않는다).

**미리보기**: 새 프로필(로그아웃 상태) 브라우저가 기록 창 자리에 겹쳐 뜨고 켜 둔 단계만 따라 한다. 누를 곳에 빨간 테두리 0.9초. '보기만 하세요' 안내. 받은 파일은 기록 폴더 `data\옵저버\미리보기`. 한 번 할 때마다 대시보드 '기록' 에 한 줄 (6절).
- **멈추기와 창 닫기** (2026-10-02 사용자 결정): 미리보기 중에는 [▶ 미리보기]·[저장] 자리가 **[Ⅱ 일시정지]/[▶ 계속]** 과 **[■ 중단]** 이 된다 (⏸ 는 맑은 고딕에 없어 빈 네모로 나왔다). 일시정지는 하던 단계를 마치고 다음 단계 앞에서 기다린다. 중단은 곧 멈추고 브라우저와 프로필을 지운다 - 그 단계는 빨간 ✗ 가 아니라 회색 '■ (중단)'.
- 미리보기가 도는 중에는 창을 닫지 않는다 ('일시정지나 중단을 누른 뒤 닫으세요'). 일시정지·중단 중에 닫으면 미리보기를 멈추고 정리가 끝난 뒤 닫힌다. 예전엔 닫기가 30초 기다리다 그냥 끝나 로그인 쿠키가 든 프로필이 남았다.
- 미리보기 브라우저를 못 띄우면 까닭을 보이고 단추를 돌려준다 (예전엔 미리보기 상태로 멈췄다). 그래도 남은 프로필 (작업 관리자로 끔·정전) 은 다음에 옵저버를 켤 때 지운다 (잠금을 쥔 뒤라 다른 옵저버의 것일 수 없다).

**아이디·비밀번호**: 저장하면 이 PC 의 사용자 설정 `Sites` 에 넣는다 (비밀번호는 쓰는 순간 잠긴다). 다시 켜면 아이디는 보이고, 비밀번호 칸은 비운 채 '저장된 비밀번호 있음 - 바꿀 때만 입력'. 미리보기는 칸이 비었으면 저장된 비밀번호를 쓴다.

**저장**
1. 기록이 있는 프리셋은 사이트코드가 숫자 세 자리여야 한다 (루틴이 파일 이름 앞 `(012)` 로 ERPia 사이트 행을 찾는다. 그 행의 '엑셀업로드' 가 켜져 있어야 올라간다 - 지금 루틴 그대로).
2. 기록에 비밀번호 글자가 들어 있으면 저장하지 않는다 (비밀번호 칸이 아닌 곳에 비밀번호를 친 경우).
3. 프리셋 파일을 통째로 새로 쓴다 (임시 파일에 다 쓰고 바꿔치기).
4. 사용자 설정을 다시 읽어 `Sites` 의 `PRESET1` … 칸만 고쳐 쓴다 (설정 창·에이전트가 쓴 다른 섹션은 그대로). 새 칸은 `Stts` 9. 지운 프리셋의 칸은 지운다.
5. (2026-10-02) [저장] 은 기록 중·미리보기 중에는 잠기고, 지금 프리셋에 켜 둔 단계가 한 줄은 있어야 눌린다. 저장 날짜는 이번에 바뀐 프리셋 (이름·사이트코드·기록·아이디·비밀번호) 만 그날로 - 예전엔 모든 프리셋이 그날로 바뀌었다. 저장하지 않은 기록이 있는데 창을 닫으면 묻는다.

**켤 때 확인**: 관리자가 아니면 자기를 관리자 권한으로 다시 띄운다 (UAC). 권한을 올린 계정이 화면에 로그인한 계정과 다르면 멈추고 알린다 - 다른 계정으로 잠근 비밀번호는 RPA 가 풀지 못한다. 이 확인들은 설정 창의 것을 `rpa_status` 로 옮겨 둘이 같이 쓴다. 그다음 옵저버 잠금(`rpa_status.OBSERVER_LOCK`)을 쥔다 - 다른 옵저버가 쥐고 있으면 '이미 켜져 있습니다', 쥔 뒤 프리페어·루틴이 돌고 있으면 멈추고 알린다 (RPA 가 화면·마우스를 쓰는 동안 기록하면 부딪힌다). 잠금은 옵저버가 끝나면 (죽어도) 윈도우가 푼다.

**창 없는 모드**: `--check` 는 창을 띄우지 않고 프리셋 파일·브라우저 위치·Tcl 을 확인한 뒤 끝 줄 `옵저버 점검 끝` 을 찍는다 (빌드·샌드박스가 본다). 관리자 권한을 묻지 않는다.

## 5. 프리셋 파일과 사용자 설정

**프리셋 파일** `RPA_Presets.json` - 사용자 설정과 같은 폴더 (새 구조는 `ProgramData\AFTER MARKET\RPA\config`). 시험은 `RPA_USER_CONFIG` 를 바꾸면 같이 따라온다.
```json
[{"no": 1, "name": "지마켓", "code": "012", "saved_at": "2026-09-30T18:20:00", "record": {"version": 1, "…": "…"}},
 {"no": 2, "name": "프리셋 2", "code": "", "saved_at": null, "record": null}]
```
- 비밀이 없다. 그래도 사이트 메뉴 이름·누른 글자가 들어 있으니 PC 밖으로 보내지 않는다.

**사용자 설정 `Sites`** - 프리셋마다 한 칸. 지금 `web_runner` 의 사이트 칸 규칙 그대로라 점검·실행·켬/끔이 다 통한다.
```json
"PRESET1": {"URL": "https://…/login", "ID": "seller01", "PW": "<잠김>", "Action": ["replay"], "Stts": 0, "Preset": 1, "note": "지마켓"}
```
- 이름·사이트코드·기록의 원본은 프리셋 파일이다. `note` 는 사람이 파일을 볼 때를 위한 사본.
- 옛 `SITE1` (메일) 칸은 건드리지 않는다.

## 6. 프리페어·에이전트·대시보드

**프리페어 `web_runner.py`**
- 할 일 `replay`: 칸의 `Preset` 번호로 프리셋 파일의 기록을 찾아 재생한다. 브라우저 안쪽 크기를 기록 때와 같게, 받은 파일은 지금의 `download_dir()` (`바탕화면\ERPIA_AI\ERPIA_AI_EXCEL`) 에 `(사이트코드)원래이름`.
- 대시보드 단계 이름은 `<프리셋 이름> 엑셀 받기`. 재생 단계마다 로그 한 줄 (값은 뺀다, 1절). 멈추면 지금처럼 그 단계 실패 + 화면 사진.
- 재생하는 동안 알림창은 재생기 하나만 받는다 - 프리페어 창의 알림 받기(`prepare_page`)를 떼었다가 끝나면 다시 붙인다. 둘이 받아 로그가 두 줄이고 알림 글이 줄지 않은 채 대시보드로 갔다 (2026-10-02).
- `--check`: `replay` 칸의 프리셋에 기록이 없거나 사이트코드가 틀리면 문제로 적는다.

**에이전트**
- 현황에 `presets`: `[{no, name, code, steps, saved_at, has_login, on}]`. 기록 내용·아이디·비밀번호는 안 싣는다.
- 명령 `set_presets` `{"PRESET1": true, "PRESET2": false}` (키는 `Sites` 칸 이름. 숫자 키는 Realtime DB 가 배열로 바꿔 읽는다 - 2026-09-30 계획 때 고침): 아는 번호만, 켜기는 기록과 아이디·비밀번호가 있는 것만. `Stts` 를 0/9 로 쓴다. 결과 `프리셋을 바꿨습니다 (켬: ① 지마켓)`.
- 날짜별 성공·실패 도넛은 프리페어·루틴만 센다 (옵저버 줄은 뺀다).

**대시보드**
- 환경설정 '실행 모듈' 아래 **'쇼핑몰 프리셋'**: 줄마다 `① 지마켓 (012) · 12단계 · 9/30 저장` 과 스위치, [적용]. 관리자만. 기록이 없거나 아이디·비밀번호가 없는 줄은 스위치가 잠기고 까닭을 줄 아래 작은 글로 보인다 (2026-10-02 - 마우스 글(title)은 휴대폰에 안 보였다. '실행 모듈' 의 잠긴 까닭도 같게). 적용하면 설정에 값을 적고 `set_presets` 를 보낸다 (실행 모듈과 같은 길).
- 실행 단추 (2026-10-02 사용자 요청): 도는 RPA 의 단추는 화살표 없이 `프리페어 RPA 실행중` (흐리지 않게), 끝나면 (성공·실패·오류) `→ 프리페어 RPA` 로 돌아와 다시 누를 수 있다. 다른 단추는 지금처럼 흐리게 잠긴다.
- '기록' 표: 옵저버 미리보기 줄은 프로그램 칸이 '옵저버'. 누르면 단계 ✓/✗ 와 로그 끝부분 (지금 프리페어·루틴과 같다). 지금 실행 카드·실행 단추에는 섞이지 않는다 - 상태 기록에서 옵저버는 `PROGRAMS` 밖의 이름이라 현황 카드가 보지 않는다.
- Realtime DB 규칙: 명령 종류에 `set_presets` 를 더한다. **규칙·화면 배포는 사용자 확인 뒤** (밖으로 나가는 일).
- **옵저버가 떠 있으면** (`rpa_status.observer_open()`) 자동 실행은 닫힐 때까지 기다리고 (건너뛰지 않는다), 실행 단추 (대시보드·옛 8765 화면) 는 `옵저버가 켜져 있습니다. 옵저버를 닫은 뒤 실행하세요` 로 거절한다. 기다리는 까닭은 웹 대시보드에 안 보인다 (지금의 'RPA 가 돌고 있어 기다림' 과 같다). **2026-09-30 구현.**

## 7. 빌드·설치

- `EXES` 에 `Prepare_Observer.exe` (`rpa_observer.py`). Nuitka 옵션: 주황 아이콘, Playwright, `tk-inter` 플러그인, 콘솔은 `attach` (시작 메뉴로 켜면 창 없음, `--check` 는 부른 쪽이 출력을 받음 - 첫 빌드 때 확인). 콘솔 옵션은 exe 마다로 옮긴다 (루틴·프리페어는 지금처럼 `force`).
- **콘솔 없이 켜진 attach exe** (2026-10-02 첫 실행): 시작 메뉴·관리자 권한으로 다시 켜기처럼 붙을 콘솔이 없으면 Nuitka 가 표준 핸들 셋을 `INVALID_HANDLE_VALUE` 로 둔다 (`HelpersConsole.c`). Playwright 는 `sys.stderr` 가 None 이면 드라이버의 stderr 를 비워 두고, `subprocess` 가 그 표준 핸들을 집다 `WinError 6` - 일꾼이 Playwright 를 못 띄워 옵저버가 켜자마자 오류만 보였다. `main()` 이 맨 먼저 `fix_std_handles()` 로 못 쓰는 핸들을 NUL 로 바꾼다 (판 2026.10.02-2). `--check` 는 콘솔에서 불러 못 잡았다 → `tests/test_presets.py` 8절이 핸들을 그 값으로 만들고 드라이버를 띄우고, 샌드박스는 설치된 옵저버를 콘솔 없는 pythonw 로 켜 드라이버(node.exe run-driver)가 뜨는지 본다 (35/35). 바로 가기를 탐색기로 여는 실측: 고치기 전 핸들 셋 다 `0xFFFF…`·`WinError 6`, 고친 뒤 성공.
- **빌드 PC 의 CPU 에 맞춘 exe** (2026-10-02 c_demo 시연 노트북, 인텔): 루틴·프리페어·옵저버가 모두 켜자마자 `0xC000001D`(모르는 명령)로 출력 없이 죽었다. 이 PC 는 MSVC 에 Windows SDK 가 없어 Nuitka 가 Zig 로 컴파일하는데, `-march=x86_64` 를 컴파일에만 주고 링크에는 안 줘서 Zig 가 C 런타임(memcpy 등)을 이 PC 의 Ryzen 9700X 에 맞춰 AVX-512 로 붙였다 (`vmovups zmm0,[rdx]`). `build_release.NUITKA_ENV` 의 `LDFLAGS=-march=x86_64` 로 링크도 일반 x86-64 로 (판 2026.10.02-4, 시험 exe 의 AVX-512 명령 106 → 0). 샌드박스는 이 PC 의 CPU 를 그대로 써서 못 잡는다 - 노트북 점검은 `D:\AX\RPA_점검.ps1` (이벤트 로그의 예외 코드까지 모은다).
- **Tcl/Tk 꺼내기** (2026-09-30 실측): 파이썬 3.14 의 Tcl/Tk 9 는 라이브러리가 `tcl90.dll`·`tcl9tk90.dll` 안의 압축(zipfs)에 있어 Nuitka 가 못 찾는다. 빌드가 tkinter 로 `//zipfs:/lib/tcl/tcl_library` 와 `//zipfs:/lib/tk/tk_library` 를 작업 폴더에 꺼내 `--tcl-library-dir`·`--tk-library-dir` 로 넘긴다. `info library` 가 진짜 폴더면 그대로 쓴다. spike 빌드: 176초, 52MB, exe 로 혼자 도는 시험 통과.
- `MARKERS` 에 `옵저버 점검 끝`. `--exes-from` 으로 가져올 판에 옵저버 exe 가 없으면 무엇이 없는지 말하고 멈춘다.
- 설치 파일 시작 메뉴 `RPA 옵저버` (주황 아이콘, AppUserModelID `AFTERMARKET.RPA.Observer`).
- 옵저버가 켜져 있으면 설치 파일은 판 올림을 에이전트를 멈추기 전에, 지우기는 시작할 때 멈춘다 (`CheckForMutexes`, 잠금 이름은 `rpa_status.OBSERVER_LOCK`) - 켜진 exe 를 덮다 설치가 가운데서 막혔다 (2026-10-02). 업데이트가 있다는 안내는 3부 자동 업데이트 때.
- 빌드는 Nuitka 로만 (`--builder` 선택지를 뺐다 - pyinstaller 를 고르면 늘 실패했다, 2026-10-02).
- 샌드박스: 옵저버 `--check`, 아이콘 주황, 바로 가기 대상·아이콘.
- 설치 파일이 exe 하나만큼 커진다 (Playwright 드라이버를 프리페어와 따로 들고 있다). 브라우저 폴더 `ms-playwright` 는 같이 쓴다.

## 8. 안전

- 비밀번호는 기록·프리셋 파일·로그·대시보드 어디에도 없다. 사용자 설정에만 잠겨 있다 (지금 원칙 그대로).
- 로그인 아이디도 기록에는 없다 (`credential: "ID"`). 사용자 설정에만.
- 저장 때 기록에 비밀번호 글자가 보이면 거부.
- 대시보드로 가는 것: 프리셋 이름·사이트코드·단계 수·저장 시각·켬/끔, 미리보기·재생 로그 (칸에 친 값·주소 `?` 뒤는 빼고, 누른 글자는 20자까지).
- 옵저버는 로그인한 계정의 관리자 권한으로만 돈다 (4절). 설정 폴더 권한은 설치 파일이 이미 막아 두었다.
- 받은 엑셀(개인정보가 있을 수 있음)은 지금처럼 바탕화면 `ERPIA_AI_EXCEL` 로만. 미리보기 파일은 기록 폴더.
- 개발 PC: 옵저버·시험은 `RPA_USER_CONFIG`·`RPA_PROGRAMDATA` 로 시험 폴더를 가리킨 채로만 켠다. 진짜 `ProgramData` 설정과 `dist\RPA_UserConfig.json` 을 건드리지 않는다.

## 10. 하지 않는 것

- 실제 쇼핑몰 시험 (spike 2): 이 구현과 별개로, 계정 있는 사이트 한 곳을 사용자와 함께. 거기서 나온 것을 이 문서에 더한다.
- 달력 위젯으로 고른 날짜 (날 칸을 누른 것이 고정된다), 캡차·새 기기 인증·키보드 보안, 비밀번호 걸린 엑셀.
- 단계 고치기 (지금은 켜기/끄기·삭제·다시 기록만), 프리셋 중간 번호 지우기·순서 바꾸기.
- 대시보드에서 옵저버 띄우기 (사람이 PC 앞에 있어야 한다), 기록 내용을 대시보드에서 보기.
- 미리보기 파일 자동 정리, 사이트 구조가 바뀐 것을 미리 알리기.
- 자동 업데이트 (3부).

## 11. 위험과 대비

| 위험 | 대비 |
|---|---|
| 자동화 브라우저를 막는 사이트 | spike 2 에서 먼저 본다. 옵저버와 프리페어가 같은 브라우저라 기록 때 막히면 바로 안다 |
| 사이트 디자인이 바뀜 | 그 단계에서 멈추고 대시보드에 실패 단계·사유가 뜬다. 다시 기록하면 된다 |
| 콘솔 `attach` 가 `--check` 출력을 못 넘김 | 첫 빌드에서 확인. 안 되면 `--check` 가 끝 줄을 파일에도 쓰고 빌드·샌드박스가 그 파일을 본다 |
| 파이썬을 바꾸면 Tcl 자리가 달라짐 | 꺼내기는 `info library` 가 가리키는 곳을 따른다 (zipfs 든 폴더든) |
| 설정 파일을 두 곳이 같은 순간 씀 (옵저버 저장·에이전트 명령·설정 창) | 셋 다 쓰기 직전에 다시 읽고 자기 칸만 고친다 (지금 설정 창·에이전트와 같은 방식). 남는 틈은 1초 안쪽 |
| 관리자 권한으로 뜬 크롬 | spike 와 같은 Playwright 크롬. 첫 설치 PC(노트북)에서 확인 |
| 설치 파일이 커짐 | exe 하나만큼. 받아들인다 |
| 예약이 RPA 를 띄우고 RPA 가 '도는 중' 을 적기 전 몇 초 안에 옵저버를 켬 | 둘 다 뜬다. 받아들인다 (그 순간에 켤 일은 드물고, 옵저버가 먼저 떠 있으면 예약이 기다린다) |

## 12. 만드는 순서

1. 엔진 `web_replay.py` 와 가짜 쇼핑몰·엔진 시험 (spike 를 옮기고 시험부터 통과)
2. 프리셋 파일·`Sites` 칸·요약 (`rpa_status`), 관리자·계정 확인 옮기기
3. 프리페어 `replay`
4. 옵저버 창 `rpa_observer.py` 와 화면 시험
5. 빌드·설치·샌드박스 (세 번째 exe, Tcl/Tk, 바로 가기)
6. 에이전트·규칙·대시보드 (배포는 사용자 확인 뒤)
7. 문서 (`docs/firebase-architecture.md` 파일 지도·시험 표), 새 판 빌드와 샌드박스
