# 내장 Python 도 [업데이트] 단추로 바꾸기 - 설계 (2026-11-20)

## 왜

고객사 보안 검토(2026-11-19)가 Python 3.14.7 · OpenSSL 3.5.7 을 최신으로 올리라고 했다. 고객 PC 에서 도는 Python 은
개발 PC 의 Python 이 아니라 배포에 싣는 `python\` 폴더다 (`D:\AX\runtime\python` 을 빌드가 그대로 복사, 조각 방식에서는
exe 셋·에이전트·옵저버가 모두 이 폴더의 `python314.dll` 로 돈다).

그런데 지금 PC 들의 업데이트 코드는 내장 Python 버전이 다른 버전을 거절한다 (`rpa_update._fetch_from`:
"파이썬이 변경된 버전입니다. 설치 파일로 설치하여 주십시오."). `python\` 폴더가 버전 목록(manifest)의 `files` 밖이라
업데이트가 바꿀 방법이 없었기 때문이다. 그대로 두면 Python 을 올릴 때마다 PC 를 한 대씩 찾아가 설치 파일을 돌려야 한다.

사용자 결정 (2026-11-20): 업데이트를 먼저 고쳐 단추로 올린다. 버전을 둘로 나눈다.

## 목표 / 하지 않는 것

- 목표: A 이상인 PC 는 내장 Python 이 바뀐 버전을 [업데이트] 로 받고, 실패하면 지금처럼 저절로 되돌아가고, [이전 버전으로 되돌리기] 도 된다.
- 목표: A 보다 옛 버전인 PC 가 A 로 올라올 때는 지금 깔린 코드가 그대로 받는다 (그 코드는 고칠 수 없다) - 그때 `python\` 은 건드리지 않는다.
- 하지 않는다: 옛 버전 PC 가 A 를 건너뛰고 B 로 바로 가는 길 (옛 코드가 거절한다 - 글도 옛 글 그대로 나온다).
- 하지 않는다: 관리 화면이 알아서 A 를 먼저 보내는 단계 업데이트. 버전은 지금처럼 관리 화면에서 사람이 고른다.
- 하지 않는다: 파일 변조 감지를 `python\` 폴더까지 넓히기 (아래 '변조 감지').

## 버전 둘

| | 버전 A (다리) | 버전 B |
|---|---|---|
| 내장 Python | 3.14.7 그대로 | 3.14.10 (OpenSSL 3.5.9) |
| 빌드 환경 | Python 3.14.7 (지금까지와 같음 - 바뀐 조각만 새로) | Python 3.14.10 (조각 전부 새로) |
| 내용 | 보안 보완 1차 + 이 설계의 업데이트 코드 + 목록의 `runtime_files` | A 와 같은 코드, Python 만 다름 |
| 받는 PC | 모든 PC (옛 코드가 받는다) | A 이상인 PC |
| 받는 양 | 바뀐 파일만 | 조각 전부 + Python 폴더 (한 번, 약 180MB) |

A 를 안정본으로 지정해 둔다 - 안정본은 사이트에서 지워지지 않으므로 늦게 켜진 PC 도 A 를 거칠 수 있다.

## 접근 (견준 셋)

1. **목록에 새 칸 `runtime_files` (고름)** - 옛 코드는 모르는 칸을 무시하므로 A 로 올라올 때 `python\` 을 건드리지 않는다.
   A 부터의 코드만 이 칸을 본다. 도우미(바꾸기·되돌리기)는 계획의 경로를 가리지 않아 그대로 쓴다.
2. `files` 칸에 Python 파일을 넣기 - 옛 코드가 A 를 받을 때 Python 파일 648개(39MB)를 모두 다시 받아 덮어쓰고, 변조 감지가
   `python\` 까지 걸린다. PC 마다 `python\` 이 목록과 한 바이트도 다르지 않은지 확인된 적이 없어, 다르면 실행이 막힌다.
3. Python 을 압축 하나로 통째 바꾸기 - 끊김·되돌리기를 파일 단위로 다루는 지금 도우미를 못 쓰고 새로 짜야 한다.

## 설계

### 목록 (manifest.json)

- 새 칸 `runtime_files`: `{"python/…": {"sha256", "size"}}`. `RUNTIME_DIRS` 안의 모든 파일에서 `__pycache__` 와 이미 `files` 에
  있는 것(이름 붙인 exe 둘)을 뺀 것. `format` 은 1 그대로 (옛 코드는 다른 format 을 거절한다).
- `runtime` 칸(`{"python": "3.14.7"}`)은 그대로 - 버전 표기.

### 받기 (`rpa_update`)

- `_check_manifest`: `runtime_files` 가 있으면 경로를 검사한다 - `manifest_path_ok`, `RUNTIME_DIRS` 로 시작, `files` 와 겹치지 않음.
- `runtime` 표기가 같으면 지금과 같다 (`python\` 을 보지 않는다).
- 다르면:
  - 새 목록에 `runtime_files` 가 없으면 지금처럼 거절 (글 그대로).
  - 있으면 Python 계획을 더한다. 받을 것 = 새 `runtime_files` 가운데 디스크에 없거나 지문이 다른 것 (`disk_differs`).
    치울 것 = 지금 목록의 `runtime_files` 에 있고 새 목록에는 없는 것. 새로 생기는 것(plan.new) = 받을 것 가운데 디스크에 없던 것.
  - 디스크 기준인 까닭: 옛 설치 파일로 깐 PC 의 `python\` 이 A 의 목록과 같다는 보장이 없다. 다른 것은 모두 새 것으로 맞춘다.
- 디스크 여유 계산에 넣는다.
- `handoff` 는 그대로다. 도우미는 프로그램 폴더 밖 사본(runner)의 Python 으로 돌아 `python\` 을 바꿔도 된다 (주석만 고친다).

### 되돌리기 (`stage_rollback`)

- 보관본 목록과 지금 목록의 `runtime` 표기가 다르면 `runtime_files` 도 `files` 처럼 계획한다 (받을 것 = 지문이 다른 것, 보관본에서 가져옴).
- 보관본 파일의 지문이 보관본 목록과 다르거나 없으면 지금처럼 "되돌릴 수 없습니다" - 반쯤 섞인 Python 으로 돌아가지 않는다.
- 업데이트 실패 때의 자동 되돌리기는 도우미가 옮겨 둔 실제 파일을 그대로 되돌리므로 바뀔 것이 없다.

### `__pycache__`

목록에 넣지 않고 업데이트가 건드리지 않는다 (Python 이 스스로 쓰는 파일). 새로 쓰인 `.py` 는 수정 시각이 달라져 Python 이
옛 pyc 를 쓰지 않는다. 설치 파일에는 지금처럼 그대로 싣는다.

### 변조 감지

지금처럼 `files` 만 본다. `python\` 을 넣으면 A 로 올라온 PC 가운데 `python\` 이 목록과 조금이라도 다른 PC 는 실행이 막힌다.
B 로 올라온 뒤에는 업데이트가 쓴 파일이라 목록과 같아지므로, 넓히는 일은 그 뒤에 따로 정한다.

### 빌드·내보내기

- `build_release.write_manifest`: `runtime_files` 를 적는다. `verify_zip`: 압축 안 파일과 지문을 견준다.
- `publish_release`: `runtime_files` 의 파일도 blobs 에 올리고, 정리(`_prune`)가 쓰는 파일로 센다 (안 세면 지워진다). 크기 합계에도 넣는다.
- `D:\AX\runtime\python` 은 A 때는 그대로, B 를 빌드하기 전에 3.14.10 으로 바꾼다. 3.14.10 후보는 같은 규칙(기본 설치본에서
  Doc·Scripts·include·libs·share·ensurepip·idlelib·site-packages 를 뺌, 파일 목록이 지금 것과 같음)으로 만들어 두었다
  (`D:\AX\runtime_31410_candidate`).

## 시험

- 단위: 계획(받을·치울·새로 생기는 것), `runtime_files` 없는 목록 거절, 경로 검사, 되돌리기 계획과 보관본 지문 거절,
  빌드가 적는 목록, 내보내기의 blob·정리.
- 샌드박스 `--update` 에 'Python 이 바뀐 버전' 을 더한다 (판 B 에 3.14.10 후보 Python 을 넣은 것):
  업데이트 뒤 설치 폴더의 Python 이 3.14.10 · OpenSSL 3.5.9 이고 에이전트가 살아 있다 → [되돌리기] 뒤 3.14.7 →
  Python 이 바뀌었고 켜지지 않는 버전은 저절로 되돌아가 3.14.7.
- 샌드박스 `--from <옛 설치 파일>`: 옛 코드가 A 를 받는다 (새 칸을 무시하고 `python\` 을 건드리지 않는다).
- B 를 만든 뒤: `--from <A 설치 파일> <B 설치 파일>` 로 실제 A → B.

## 내보내는 순서

A 빌드(3.14.7 환경) → 샌드박스 → 내보내기 + 안정본 지정 → 모든 PC 를 A 로 → 업체 웹 배포 →
`D:\AX\runtime\python` 을 3.14.10 으로 → B 빌드(3.14.10 환경) → 샌드박스(`--from A`) → 내보내기 → PC 를 B 로.

## 검토 뒤 더한 것 (2026-11-20, 새 검토자 1명)

- 새로 생기는 것(plan.new)에서 파이썬 파일은 **디스크에 없던 것만** 넣는다 (받기·되돌리기 둘 다). 목록 기준으로 적으면, 목록에 없이
  디스크에 있던 파이썬 파일이 '새 파일' 이 되어 바꾸다 끊겼을 때 되돌리기가 보관본 없이 지운다.
- `runtime_files` 와 `files` 의 겹침은 대소문자를 가리지 않고 본다 (윈도우에서는 같은 파일).
- 도우미 두 군데 (도우미는 A 에 실려야 A → B 와 그 뒤 업데이트에서 쓰인다):
  - 성공 뒤 정리: 옛 보관본을 지우지 않고 `backup_old_<시각>` 으로 비킨 뒤 새 보관본을 놓고, 비켜 둔 것은 그 뒤에 지운다.
    오래 켜 둔 프로그램(설정 창 등)이 옛 보관본의 `python314.dll` 을 쥐고 있으면 폴더가 다 안 지워져 새 보관본을 못 놓았다.
  - 되돌리는 중 쥔 파일(PermissionError)을 만나면 에이전트를 한 번 더 끄고 이어서 되돌린다. 로그온 때는 에이전트 작업과 도우미가 같이 떠서,
    도우미가 끈 뒤에 에이전트가 켜져 되돌릴 자리의 파일을 쥘 수 있다. 그래도 안 되면 지금처럼 남기고 멈춘다.
- 샌드박스: 버전 글뿐 아니라 `python\` 의 모든 파일이 목록과 같은지, 상대 버전에만 있던 파일이 남지 않았는지 본다 (섞인 폴더).
  `--from` 사이트는 옛 판의 같은 경로와 지문이 다른 파일을 남긴다 (지문만 보면 다른 경로의 같은 내용을 지운다).

## 구현자에게 남긴 것

- `runtime_files` 계획을 넣는 자리 (`_fetch_from` 안 / 따로 뗀 함수) 와 이름.
- 샌드박스 점검의 글과 번호.
