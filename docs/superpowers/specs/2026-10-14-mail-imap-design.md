# 메일에서 엑셀 받기 (IMAP) 설계

> **상태: 구현 (2026-10-22).** 업체 메일은 아직 모르지만 "IMAP 을 연다" 고 보고 만든다 (사용자 2026-10-22 - 안 되는 업체는
> 지금의 웹메일 기록 방식을 그대로 쓴다). 2026-10-14 에는 보류였다. 아래 14절이 이 설계와 달라진 것·정한 것이다.

## 1. 왜

옵저버(기록·재생)는 쇼핑몰에서 엑셀을 받는 일은 잘하지만, 메일에서 첨부를 받는 일에는 약하다.

- 재생은 기록 때 누른 **그 메일**(제목 글자·화면 위치)을 다시 누른다. 다음 날 새 메일은 제목이 달라 못 찾거나, 같은 자리의 **다른 메일**을 눌러 엉뚱한 첨부를 받을 수 있다.
- 이미 처리한 메일을 기억하지 못해 같은 첨부를 또 받을 수 있다.
- 예전 메일 기능(`web_runner.action_mail_check`·`action_mail_download`)은 비즈메카 화면 전용이고, 조건이 '안 읽은 메일 + 제목이 `>>>` 로 시작' 하나뿐이다.

필요한 것은 **메일을 고르는 규칙**이다: 누가 보냈나, 제목이 어떤 꼴인가(구분자 포함), 안 읽은 것만인가, 언제 받은 것까지인가.
이 규칙은 그대로 메일 서버의 검색 조건이라, 화면을 누르는 대신 메일 서버에 직접 묻는다 (IMAP).

## 2. 범위

**한다**
- IMAP 서버(암호화 연결)에 아이디·비밀번호로 로그인해, 규칙에 맞는 메일의 첨부 엑셀을 `ERPIA_AI_EXCEL` 에 받는다.
- 규칙은 옵저버 화면에서 프리셋마다 정한다. 실행은 ACTOR 오토파일럿이 한다 (쇼핑몰 프리셋과 같은 자리·같은 켬/끔·같은 예약).
- 처리한 메일을 PC 에 기억해 두 번 받지 않는다.

**안 한다 (이번 범위 밖)**
- 메일을 지우거나 옮기기, 답장·전달. 메일 서버에서 바꾸는 것은 (선택한 경우) '읽음 표시' 하나뿐이다.
- 웹메일 화면을 눌러 받기 (IMAP 이 막힌 메일). 필요해지면 옵저버의 '메일 고르기' 단계로 따로 설계한다 (13절).
- OAuth 로그인 (Microsoft 365·회사 Google 계정처럼 비밀번호 로그인을 막은 곳). 13절.
- 압축(zip)·암호 걸린 엑셀 풀기, 본문 속 링크로 받는 파일.

## 3. 사용자 쪽 흐름

1. 옵저버에서 프리셋을 고르고 종류를 **'메일 받기'** 로 바꾼다 (지금 프리셋은 '기록' 종류. 기록 단추 대신 아래 칸이 보인다).
2. 서버 칸(주소·포트·보안 방식)과 아이디·비밀번호를 넣는다. 잘 알려진 메일은 주소를 고르면 서버 칸이 채워진다 (표: 네이버·다음·Gmail·비즈메카 등 - 실제 값은 보류 해제 때 확인).
3. 규칙 칸을 채운다 (4절).
4. **[찾아보기]**: 지금 규칙에 맞는 메일 목록(받은 시각·보낸 사람·제목·첨부 이름)을 보여 준다. 받지도, 읽음 표시도 하지 않는다.
5. 저장 → 웹 대시보드의 '사이트 수집' 에서 켠다. 이후 ACTOR 오토파일럿이 예약대로 돈다.

## 4. 규칙

| 칸 | 값 | 기본 |
|---|---|---|
| 메일함 | 폴더 이름 | `INBOX` (받은편지함) |
| 보낸 사람 | 주소나 이름 여럿 (쉼표). 하나라도 들어 있으면 맞음 | 비움 = 따지지 않음 |
| 제목 - 시작 글자 | 예 `>>>`, `[주문]` | 비움 |
| 제목 - 들어 있어야 할 말 | 여럿 (쉼표). **모두** 들어 있어야 맞음 | 비움 |
| 제목 - 빼는 말 | 여럿 (쉼표). 하나라도 있으면 뺌 (예 `RE:`, `회신`) | 비움 |
| 읽음 상태 | 안 읽은 것만 / 모두 | 안 읽은 것만 |
| 기간 | 오늘 받은 것만 / 최근 N일 (1~30) | 오늘 |
| 첨부 종류 | 확장자 여럿 | `xlsx, xls, csv` |
| 첨부 이름에 들어 있을 말 | 비움 = 따지지 않음 | 비움 |
| 한 번에 최대 | 메일 수 (1~50) | 20 |
| 받은 뒤 읽음 표시 | 켬 / 끔 | **끔** (서버 상태를 바꾸지 않는 쪽. 중복은 5절의 기억으로 막는다) |

- 규칙이 하나도 없으면 저장하지 않는다 (받은편지함의 모든 첨부를 받는 실수를 막는다). 보낸 사람·제목 칸 중 하나는 꼭 채운다.
- 글자 비교는 대소문자·전각/반각·앞뒤 공백을 가리지 않는다.
- '오늘' 은 이 PC 시각 기준 00:00 부터.

## 5. 처리한 메일 기억

- 메일마다 `Message-ID` 를, 없으면 `메일함 UIDVALIDITY + UID` 를 기억한다. 프리셋마다 파일 하나 (`data\메일\PRESETn.json`), 90일 지난 것은 지운다.
- 첨부를 **모두** 받은 메일만 기억한다. 하나라도 못 받으면 기억하지 않아 다음 실행에서 다시 시도한다 (이미 받은 파일은 이름 뒤 (1) 로 따로 남는다 - 덮어쓰지 않는다).
- 사람이 먼저 메일을 열어 '안 읽음' 이 풀려도, 기억에 없으면 '모두' 규칙일 때만 받는다. '안 읽은 것만' 규칙이면 받지 않는다 (사람이 이미 손으로 처리했다고 본다) - 보류 해제 때 사용자 확인.
- 규칙을 바꿔 저장해도 기억은 그대로 둔다. [기억 지우기] 단추로만 비운다.

## 6. 동작 (ACTOR 오토파일럿 한 번)

1. 연결: IMAPS(993) 또는 IMAP+STARTTLS(143). **암호화 없는 연결과 인증서 검증 끄기는 쓰지 않는다.**
2. 로그인 → 메일함 고르기 (읽기 전용 `EXAMINE`. 읽음 표시를 켠 경우만 `SELECT`).
3. 서버에 대충 묻기: `SINCE <기간 첫날>` (+ `UNSEEN`). 한글 제목·이름 검색은 서버마다 달라 **서버에 맡기지 않는다**.
4. 머리글만 받기 (`BODY.PEEK[HEADER.FIELDS (FROM SUBJECT DATE MESSAGE-ID)]` + `BODYSTRUCTURE`) → PC 에서 머리글을 풀어(MIME encoded-word, EUC-KR/CP949 포함) 규칙으로 거른다 → 기억에 있는 것 뺌 → 최근 것부터 '한 번에 최대' 까지.
5. 메일마다 맞는 첨부만 받기 (`BODY.PEEK[<부분>]`, PEEK 라 읽음 표시가 안 바뀐다). 파일 이름 풀기 (RFC 2231·encoded-word), 위험한 글자 빼기 → `ERPIA_AI_EXCEL\(사이트코드)원래이름` (같은 이름이면 (1), (2) - `web_runner.unique_path`).
6. 읽음 표시를 켠 경우만 `+FLAGS \Seen`.
7. 끊기 (`LOGOUT`).

시간 한도: 연결 30초, 명령마다 60초, 첨부 하나 최대 50MB (넘으면 그 첨부를 건너뛰고 까닭을 남긴다).

## 7. 결과·기록

- 단계 키는 지금 프리셋과 같은 `PRESETn:imap`. 대시보드·웹의 '사이트 수집' 에 같은 줄로 보인다.
- 대상 메일 0건은 '완료(대상 없음)' - 토큰을 쓰지 않는다 (토큰 규칙 그대로).
- 로그: 받은 메일 수, 첨부 이름. 보낸 사람 주소는 앞 2글자만 (`ab***@…`), 제목은 30자까지. **본문·비밀번호는 싣지 않는다.**
- 실패 까닭은 사람 말로: "메일 서버에 연결하지 못했습니다 (주소·포트 확인)", "로그인을 거부했습니다 (비밀번호·IMAP 사용 설정·앱 비밀번호 확인)", "메일함 'xxx' 이 없습니다".

## 8. 설정 자리

- 프리셋 파일(`RPA_Presets.json`)에 `kind: "imap"` 과 규칙(4절). 기록(steps)은 없다.
- 서버 칸과 아이디는 사용자 설정 `Sites.PRESETn` 에 (`Action: ["imap"]`, `ImapHost`, `ImapPort`, `ImapSecurity`, `ID`, `PW`). 비밀번호는 지금처럼 DPAPI 로 잠근다 (`rpa_status.save_preset_sites`).
- 업체 프리셋 수(`policy.presets`)를 그대로 따른다 - 메일 프리셋도 한 칸을 쓴다.

## 9. 고칠 파일 (어림)

| 파일 | 일 |
|---|---|
| `mail_imap.py` (새로) | 연결·검색·머리글 풀기·규칙 거르기·첨부 받기·기억. 화면·Playwright 와 상관없는 순수 모듈 (파이썬 기본 `imaplib`·`email` - 새 패키지 없음) |

웹·에이전트·관리 화면은 바꾸지 않는다 (사이트 수집 줄을 그대로 쓴다).

## 10. 보안

- 비밀번호: DPAPI 로 잠가 저장, 로그·화면·대시보드에 싣지 않는다. 이 PC·이 윈도우 사용자만 푼다.
- 연결은 반드시 암호화. 인증서 검증을 끄는 칸은 두지 않는다.
- 본문은 저장하지 않는다. 첨부 중 확장자가 맞는 것만 받는다 (실행 파일·매크로 파일은 확장자 목록에 넣어도 거절: `exe, js, vbs, bat, cmd, ps1, scr, xlsm` - xlsm 은 13절).
- 메일 서버에서 바꾸는 것은 '읽음 표시'(켠 경우) 뿐. 지우기·옮기기 명령은 코드에 두지 않는다.

## 11. 시험

가짜 IMAP 서버로만 (실제 메일함에 접속하지 않는다).
1. 규칙: 보낸 사람·제목 시작·들어 있는 말·빼는 말·기간 경계(어제 23:59 / 오늘 00:00)·안 읽음.
2. 한글 머리글: encoded-word (UTF-8·EUC-KR), RFC 2231 파일 이름, 이름 없는 첨부.
3. 기억: 두 번 돌려도 한 번만 받음, 첨부 하나 실패하면 기억 안 함, 90일 지난 것 지움.
4. 읽음 표시: 끔이면 서버 플래그가 그대로, 켬이면 받은 메일만 `\Seen`.
5. 실패 까닭: 연결 거부·로그인 거부·없는 메일함·시간 넘김.
6. 로그에 비밀번호·본문·전체 주소가 없다.
7. 규칙이 비면 저장 거절, 위험 확장자 거절.

## 12. 순서 (보류 해제 뒤)

1. 13절 질문에 답을 받는다 (특히 업체 메일 서비스).
2. `mail_imap.py` + 가짜 서버 + 시험 (화면 없이).
3. ACTOR 연결 (`ACTIONS["imap"]`).
4. 옵저버 화면.
5. 실제 업체 메일 하나로 [찾아보기] → 실행.

## 13. 보류 해제 때 정할 것

- 업체들이 실제로 쓰는 메일 서비스와 IMAP 사용 가능 여부. 사내 자체 메일망이면 IMAP 이 열려 있는지, 인증서가 사설(회사 자체 발급)인지 - 사설이면 그 인증서를 업체마다 넣는 칸이 필요하다.
- IMAP 이 막힌 메일이 있으면: 웹메일 화면 방식(옵저버 '메일 고르기' 단계)을 따로 설계할지.
- OAuth 가 필요한 메일(Microsoft 365, 회사 Google Workspace 일부)을 지원할지.
- 받은 뒤 읽음 표시 기본값, '안 읽은 것만' 규칙에서 사람이 먼저 연 메일을 받을지 (5절).
- 압축(zip) 첨부를 풀지, 매크로 엑셀(xlsm)을 받을지.
- 한 메일에 엑셀이 여럿일 때 모두 받을지 / 이름 조건으로 하나만.

## 14. 구현 때 정한 것 (2026-10-22, 사용자 결정 외에는 구현자 판단)

- **담는 자리 (3·8절과 다름):** 프리셋 `kind` 칸·Sites `Action: ["imap"]`·`ImapHost` 대신 **기록 안에 `imap` 단계 하나**로 담는다
  (`{kind: "imap", host, port, security, rules}`, `rpa_status.imap_step`). Sites 칸은 기록 프리셋과 같다 (`Action: ["replay"]`,
  `URL: imap://<서버>`, `ID`·잠근 `PW`). 그래서 프리셋 옮기기·파일 내보내기·대시보드 켬/끔·사이트코드·업체 프리셋 수가 손대지 않고 돈다.
  ACTOR 는 `web_runner.action_replay` 가 imap 단계를 보면 브라우저 재생 대신 `mail_imap.fetch` (`_run_imap`).
- **옵저버 화면:** '주문 수집용 엑셀파일 경로' 에 세 번째 **'메일 서버'**. 고르면 기록한 단계 목록 자리에 서버·조건 칸, [찾아보기],
  [받은 메일 기억 지우기]. 기록 시작·미리보기는 잠긴다. 기록이 있는 칸에서 바꾸면 묻는다 (저장하면 기록이 메일 받기로 바뀐다).
  아이디가 잘 알려진 메일 주소면 서버 칸을 채운다 (`mail_imap.KNOWN_SERVERS` - 네이버·다음·Gmail·네이트, 실제 접속 확인 전).
- **읽음 상태 기본값 '모두'** (4절의 '안 읽은 것만' 과 다름): 사람이 먼저 연 메일도 받는다. 중복은 기억으로 막는다 -
  웹메일 쪽 사용자 결정 (2026-10-20 "기록 중 연 메일도 나중에 수집, 중복은 프로그램이 막는다") 과 같은 방향.
- **첨부 받기:** 머리글로 먼저 거른 뒤, 고른 메일만 통째로(`BODY.PEEK[]`) 받아 파이썬 `email` 로 첨부를 꺼낸다 (BODYSTRUCTURE 를 풀지 않는다).
  50MB 한도는 첨부 하나가 아니라 **메일 하나** 기준.
- **기억 파일:** `data\메일기억\PRESETn.imap.json` (웹메일 기억과 모양이 달라 따로). 프리셋 번호가 당겨지면 같이 옮긴다.
- 13절의 나머지: OAuth·사설 인증서 칸·zip·xlsm 은 안 한다. 한 메일의 맞는 첨부는 모두 받는다.

### 14-1. 바뀐 결정 (2026-10-23, BugBuster)

- **기본 첨부 종류 xlsx·xls 만** (csv 뺌, I6): 엑셀 업로드가 xlsx·xls 만 올리고 ERPia 가 csv 를 받는지 미확인. 사람이 csv 를 넣으면
  거절하지 않고 `check_rules` 가 `warn` 으로 '받기만 하고 업로드되지 않습니다' 를 돌려주고 받기 로그에 남긴다.
- **기간 (I8):** `days` 는 첫 실행만. 그 뒤는 기억 파일의 `_last_run`(마지막 실행 날)부터, 최대 30일 - 자정 전 메일·PC 를 끈 날의 메일이
  빠지지 않게. 중복은 기억이 막는다. 대상 메일을 모두 처리했을 때만 `_last_run` 을 옮긴다 (한 번에 최대를 넘었거나 하나라도 실패하면 그대로).
- **저장 순서 (I7):** 오래된 메일부터 저장하고 파일 시각을 메일 시각(INTERNALDATE)으로 - 같은 사이트코드면 업로드가 가장 늦은 파일을 고른다.
  INTERNALDATE 가 규격에 안 맞으면 Date 머리글, 그것도 없으면 그 메일은 건너뛰고 로그 (K16).
- **50MB 넘는 메일 (M15):** 기억한다 (다시 받지 않음). ACTOR 는 그 까닭뿐이면 실패가 아니라 건너뜀 + 경고 로그.
- **받을 첨부 없는 메일 (I9):** 기억하는 것은 그대로, 결과는 '대상 없음' 대신 '메일 n통 - 받을 첨부 없음'.
- **보낸 사람 (I10):** 조건에 @ 가 있으면 주소로만 비교 (표시 이름은 흉내 낼 수 있다). 이름만 쓴 조건은 전과 같다.
- **한글 이름 (M16):** `ks_c_5601-1987`·`ks_c_5601`·`ksc5601` 은 cp949 로 푼다 (똠·뷁 같은 확장 글자).
- **안내 글:** 인증서 검증 실패는 '주소·포트' 가 아니라 인증서 탓으로 (K14), 읽음 표시를 켠 채 읽기 전용 메일함이면 그 까닭으로 (L11).
- **ACTOR (M10):** 업체 프리셋 수 한도 밖 칸은 로그만 남기고 건너뛰고 나머지는 실행. `--site` 로 콕 집으면 전처럼 거부.
