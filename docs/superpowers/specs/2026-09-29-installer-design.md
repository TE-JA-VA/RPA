# 배포판 구조 설계 - 2부: 설치 마법사

**날짜:** 2026-09-29
**상태:** 구현됨 (2026-09-29, 첫 판 2026.09.29-6 - 샌드박스 24/24). 설계는 같은 날 사용자 승인 (질문 다섯 개와 요약을 보고 "프로그램을 만들자"). 구현·검토하며 바뀐 것은 해당 절에 날짜와 함께 적었다
**이 문서는 결정 기록이다.** 무엇을 왜 그렇게 정했는지 남긴다. 구현하며 바뀌면 여기에 날짜와 함께 고쳐 적는다.

| 부 | 하는 일 | 문서 |
|---|---|---|
| 1부 판 구조 | 파일을 프로그램·설정·기록으로 나누고, 판 번호·판 목록, 두 exe 를 Nuitka 로 | `2026-09-29-release-layout-design.md` (구현됨) |
| **2부 설치 마법사** | 새 PC 에 1부 구조대로 설치하고 설정을 입력받는다. 에이전트를 윈도우 로그인 때 창 없이 켜고, 죽으면 다시 켠다. 옛 구조 PC 를 옮긴다 | 이 문서 |
| 3부 자동 업데이트 | 에이전트가 새 판을 받아 프로그램 파일만 바꾼다 | 나중에 |

## 0. 왜 하나

- 지금은 새 PC 마다 담당자가 직접 설치한다: 압축 풀기, `RPA_UserConfig.json` 을 메모장으로 채우기, `에이전트_시작.bat` 첫 실행, 관리자 권한 요청 누르기. 담당자가 없으면 설치가 멈춘다.
- 에이전트는 검은 창으로 떠 있다. 누가 창을 닫거나 PC 를 다시 켜면, 누군가 다시 띄우고 관리자 권한 요청에 "예" 를 누를 때까지 멈춘다. 에이전트가 오류로 죽어도 다시 켜 주는 것이 없다 ("다시 붙는다" 는 켜져 있는 동안의 연결 이야기다).
- 1부가 정한 새 자리(`Program Files`·`ProgramData`)로 실제로 옮기는 단계가 없다. 새 자리의 `config` 폴더는 "설치 마법사만 만든다" 고 1부에 적어 두었다.

## 1. 확정한 결정

**사용자가 고른 것** (2026-09-29)

| 질문 | 답 |
|---|---|
| 누가 설치하나 | 고객 업체 직원과 우리 쪽 사람 **둘 다**. 그래서 칸마다 짧은 설명을 달고, 틀리면 무엇이 틀렸는지 바로 알려 준다 |
| 설치 뒤 설정은 어디서 바꾸나 | **설치 때와 같은 설정 창.** 시작 메뉴 "RPA 설정". 비밀번호는 PC 밖으로 나가지 않는다 |
| 이미 쓰는 PC | **설치 마법사가 옛 폴더의 설정을 가져온다.** 옛 에이전트가 돌고 있으면 닫을 때까지 진행하지 않는다 |
| 무엇으로 만드나 | **Inno Setup + 파이썬 설정 창.** 상업용 라이선스 구매는 "요청" 일 뿐 의무가 아니다 (라이선스 본문: 상업용 포함 누구나 사용 가능). 사지 않는다 |
| 자동 시작 에이전트 | **창 없이 뒤에서 돈다.** 사람이 입력해야 하는 멈춤(비밀번호 바뀜 등)은 다시 켜지 않고, "RPA 설정" 에서 고치면 다시 켜진다 |
| 자동 로그인 | 걱정하지 않는다. RPA PC 는 늘 로그온 상태를 유지하라고 안내한다 |
| 그 전에 정한 것 | 윈도우 표준 위치 (1부), 손으로 파일 넘기기는 대비책으로 남김, 자동 업데이트는 3부 |

**요약으로 보여 드리고 그대로 가기로 한 것**
- 설정 창 칸: 업체코드·PC코드·기계 계정 비밀번호(저장 전에 실제 로그인), ERPia 관리자코드·아이디·비밀번호·위치(자동으로 찾고 없으면 고르기), 메일 사이트 아이디·비밀번호, 프린터(목록에서). 실행 모듈·물류 세부값은 묻지 않는다 (처음엔 로그인만 켬, 모듈은 관리자가 웹에서)
- 자동 시작: 작업 스케줄러, 그 윈도우 계정으로 로그인할 때, 가장 높은 권한. 죽으면 잠시 뒤 다시 켬
- 시작 메뉴 바로 가기: "RPA 설정", "RPA 대시보드"
- 제거: "앱 및 기능" 에서. 설정·기록은 "같이 지울까요?" 묻고 기본은 남김
- 설치하는 윈도우 계정이 관리자가 아니면 멈추고 알림
- `tools/build_release.py` 가 zip 에 더해 `setup.exe` 를 만든다. zip 은 대비책으로 남긴다
- `setup.exe` 는 손으로 넘긴다 (공개 주소에 올리지 않는다). 처음 실행 때 뜨는 "Windows의 PC 보호" 경고는 안내문에 적는다
- 이 개발 PC 에는 설치하지 않는다. 실제 설치 시험은 윈도우 샌드박스, ERPia 까지는 노트북을 옮길 때

**고르지 않은 것**
- 웹에서 설정 바꾸기: ERPia·사이트 비밀번호가 인터넷을 거쳐 PC 로 가야 한다. "비밀번호는 PC 밖으로 안 나간다" 원칙이 깨진다.
- 파이썬만으로 설치까지: 제거 프로그램이 자기 자신과 폴더를 지우는 일, "앱 및 기능" 등록을 직접 짜야 한다. 설정 창은 어차피 파이썬이라 설치·제거만 도구에 맡기는 것이 코드가 가장 적다.
- NSIS: 구조는 같고 완전 무료지만 스크립트가 번거롭다. 회사 규정이 유료 라이선스를 요구하게 되면 구조를 그대로 두고 옮길 수 있다.
- 에이전트 창 띄우기: 창을 닫으면 다음 로그인까지 꺼진다.
- 작업 스케줄러의 "실패하면 다시 시작": 작업이 켜지지 못했을 때만 다시 시도한다. 켜진 프로그램이 오류 코드로 끝난 것은 실패로 보지 않는다. 그래서 감독 프로그램을 따로 둔다 (5절).
- 윈도우 서비스로 돌리기: 서비스는 화면이 없는 세션(0번)에서 돈다. ERPia 화면을 다룰 수 없다.

## 3. 설치 파일 (Inno Setup 6.7.3)

- **자리 고정:** `{commonpf64}\AFTER MARKET\RPA` (= 1부의 `Program Files\AFTER MARKET\RPA`). 폴더 고르기 화면은 없다. 관리자 권한, 64비트, 한국어(`Korean.isl` 은 공식 번역에 들어 있다), lzma2 한 덩어리 압축.
- **넣는 것:** 판 폴더 전부. 단 빈 틀 `RPA_UserConfig.json` 은 `RPA_UserConfig.template.json` 이름으로 넣는다 (프로그램 폴더에 진짜 설정처럼 보이는 파일을 두지 않는다. 새 구조에서는 어차피 안 읽는다). 안내 문서 두 개는 넣지 않는다 (설치하는 사람에게 따로 준다).
- **새 자리 폴더:** `{commonappdata}\AFTER MARKET\RPA\config`·`data` 를 만든다. 이 `config` 폴더가 생기는 순간 그 PC 는 새 구조다 (1부 3절). 제거할 때 자동으로 지우지 않는다 (묻는다).
- **권한:** `icacls "{commonappdata}\AFTER MARKET\RPA" /inheritance:r /grant:r *S-1-5-32-544:(OI)(CI)F *S-1-5-18:(OI)(CI)F` - 상속을 끊고 Administrators·SYSTEM 만 남긴다. 한글 윈도우의 그룹 이름 차이에 흔들리지 않게 SID 로 적는다. 아래 폴더는 새 권한을 물려받는다 (샌드박스에서 확인).
- **바로 가기 (시작 메뉴 `AFTER MARKET RPA`):** "RPA 설정" = `{app}\python\pythonw.exe "{app}\rpa_settings.py"`, "RPA 대시보드" = `https://rpa-test-f02e0.web.app` 로 가는 `.url`.
- **설치 마지막:** 설정 창을 `--after-install` 로 띄우고 닫힐 때까지 기다린다. 조용한 설치(`/VERYSILENT`)에서는 띄우지 않는다 (기다리며 멈춘다). 그때는 나중에 "RPA 설정" 으로 마친다.
- **판을 올릴 때 (설치된 PC 에 새 setup.exe):** 파일을 덮기 전에 설치돼 있던 `rpa_settings.py --stop` 을 부른다. 종료 코드 5 → "RPA 가 돌고 있습니다. 끝난 뒤 다시 설치하세요" 로 멈춘다 (도는 exe 는 덮어쓸 수 없다). 6 → "에이전트를 멈추지 못했습니다. 에이전트 창이 열려 있으면 닫고 다시 설치하세요". 처음 설치면 그 파일이 없어 건너뛴다.
- **판을 올릴 때 (덧붙임, 2026-09-29 검토):** `--stop` 이 0 도 -1(처음 설치)도 아닌 뜻밖의 코드(설정 창이 오류로 죽음 등)면 6 처럼 묻는다 - 멈췄다고 믿고 도는 파일을 덮으면 잠김 오류가 난다.
- **권한 (덧붙임, 2026-09-29 검토):** 설치 전에 누가 이 폴더를 미리 만들어 두었어도 막히게, `/setowner *S-1-5-32-544 /T` 로 주인을 Administrators 로 바꾸고 아래 폴더·파일은 `…\RPA\* /reset /T` 로 따로 붙은 권한을 지워 위의 것을 물려받게 한다.
- **제거:** 시작할 때 `--check-rpa` (확인만 - RPA 가 돌면 5 로 안내하고 제거를 취소. 여기서 멈추면 사람이 제거를 그만뒀을 때 에이전트가 꺼진 채 남는다, 2026-09-29 검토), 파일을 지우기 직전 `--remove-task` (멈추기 + 작업 지우기, 멈추다 오류가 나도 작업은 지운다), 끝에 "설정과 기록도 지울까요?" (기본 아니요, 조용한 제거면 남김). 프로그램 폴더는 통째로 지운다 (파이썬이 만든 `__pycache__` 가 남지 않게).
- **판 번호:** `AppVersion` = 판 번호 (`2026.09.29-5`), 파일 속성용 `VersionInfoVersion` = `2026.9.29.5`.
- **파일 이름:** `AFTER_MARKET_RPA_Setup_<판>.exe` - 메신저·메일로 보낼 때 한글 이름이 깨지지 않게 영문.
- **서명 없음:** 인터넷으로 받은 파일은 처음 실행 때 SmartScreen "Windows의 PC 보호" 가 뜬다 → "추가 정보 → 실행". USB 로 넘기면 뜨지 않는다. 안내문에 적는다.

## 4. 설정 창 `rpa_settings.py`

설치된 PC 에서만 돈다: `{app}\python\pythonw.exe {app}\rpa_settings.py [--after-install | --stop | --remove-task]`. 내장 파이썬의 tkinter 로 그린다 (6절).

### 시작 점검 (창을 띄우는 모드)
1. **관리자 권한이 아니면** 관리자 권한으로 자기를 다시 띄우고 끝난다 (시작 메뉴에서 누른 경우. UAC 요청이 한 번 뜬다).
2. **이 PC 에 로그인한 윈도우 계정 = 이 창을 돌리는 계정** 이어야 한다. 표준 사용자가 다른 관리자 계정의 비밀번호로 권한만 올리면 창은 그 관리자 계정으로 돈다. 그대로 가면 작업은 관리자 계정의 로그인에 걸리고 비밀번호도 그 계정으로 잠겨서, 실제로 쓰는 계정에서는 에이전트가 영영 켜지지 않는다. 그래서 멈추고 "RPA 를 돌릴 윈도우 계정을 관리자로 바꾼 뒤 그 계정으로 설치하세요" 라고 알린다.
3. **새 구조인가** (`install_root()\config` 가 있나). 아니면 "설치 마법사로 설치한 PC 가 아닙니다" 로 멈춘다 (옛 배포 폴더에서 이 파일을 눌렀을 때). **이 창이 설치 폴더(`Program Files\AFTER MARKET\RPA`)의 것인가** 도 본다 (2026-09-29 검토) - 설치한 PC 에서 손으로 넘긴 압축 폴더의 사본을 열어 저장하면 자동 시작 작업이 그 사본을 가리키는데, `D:\` 같은 곳의 폴더는 누구나 고칠 수 있어 그 파일이 관리자 권한으로 돌게 된다.
4. **옛 에이전트가 돌고 있으면** 폴더를 보여 주며 "그 창을 닫고 [다시 확인]". python 프로세스의 명령줄에 `agent.py` 가 있는데 설치 폴더의 `agent.py` 절대 경로가 아니면 옛 것이다 (옛 `에이전트_시작.bat` 은 `python agent.py` 로 상대 경로를 쓴다). 설치 폴더의 `에이전트_시작.bat` 으로 띄운 창도 여기 걸린다 - 그것도 겹치는 것이라 닫는 게 맞다.

| ERPia 비밀번호 | `LogIn.PW` | 처음. 아니면 비워 두면 그대로 | 잠가서 저장 |
| ERPia 위치 | `ERPia.ExePath` | 아니요 (못 찾으면 경고만 - ERPia 를 나중에 설치해도 에이전트가 기본 자리에서 찾는다) | 이름이 `ERPiaMain.exe` 인 실제 파일 |
| 메일 아이디·비밀번호 | `Sites` 에서 `Action` 에 `mail_download` 가 든 첫 사이트의 `ID`·`PW` | 아니요 (프리페어로 메일 첨부파일을 받을 때만) | 비밀번호는 잠가서 |
| 프린터 | `Logistic.Printer` | 아니요 (운송장 출력을 쓸 때만) | 이 PC 의 프린터 목록에서 고른다 |

메일 칸은 그런 사이트가 없으면 쓸 수 없게 둔다. 나머지(실행 모듈 `Routine`, 물류 세부값, 다른 사이트, 주석)는 보여 주지 않고 그대로 둔다. `RPA_UserConfig.json` 이 없으면 빈 틀(`RPA_UserConfig.template.json`, 로그인만 Y)에서 시작한다.

### 저장
1. 칸을 모두 확인한다. 틀린 칸은 저장 단추 옆 빨간 글씨로 무엇이 틀렸는지 알린다 (웹 로그인 화면과 같은 방식).
2. 기계 계정이 바뀌었으면 (비밀번호를 넣었거나 코드를 바꿨으면) 실제로 로그인해 보고, 되면 `agent_config.json` 을 쓴다. 로그인은 창이 굳지 않게 따로 돌리고 "확인 중…" 을 보인다. 인터넷이 안 되면 저장하지 않는다 (확인 못 한 비밀번호로 에이전트가 켜지면 결국 멈춘다).
3. `RPA_UserConfig.json` 을 쓴다 (`rpa_status.write_user_config` - 비밀번호를 잠근 뒤 쓴다. 평문이 디스크에 닿지 않는다).
4. 작업을 등록한다 (언제나, 같은 이름이면 덮어쓴다 - 판을 올리며 작업 설정이 바뀌어도 맞춰진다).
5. 에이전트가 꺼져 있거나 `agent_config.json` 이 바뀌었으면 다시 켠다 (멈추기 → 잠금이 풀릴 때까지 기다림 → 켜기). 멈추기는 에이전트가 꺼져 보여도 한다 - 감독이 다시 켜기를 기다리는 중(최대 300초)이면 작업이 도는 중이라 켜기가 무시된다 (2026-09-29 검토). 기계 계정 로그인 전에는 urllib 연결 도구도 새로 만든다 (처음 만든 도구에 그때의 인증서 목록이 담겨 있다). ERPia·메일 비밀번호, 프린터만 바꿨으면 다시 켜지 않는다 - RPA 는 실행할 때마다 설정 파일을 새로 읽는다.
6. "저장했습니다" 를 보인다. `--after-install` 이면 창을 닫는다.

**뜻밖의 오류 (2026-09-29 구현하며 더함):** 설정 창은 `pythonw` 라 오류가 나면 아무것도 안 보이고 죽는다 ("RPA 설정 을 눌렀는데 안 뜬다"). 그래서 시작부터 창이 뜨기까지의 오류는 `data\설정창_오류.txt` 에 추적을 남기고 알림 창으로 알리며 (창 없는 모드는 알림 없이 1), 창이 뜬 뒤 단추 처리 중 오류는 창을 두고 빨간 글씨로 알린다.

비밀번호는 창의 다른 곳·기록·오류 글에 싣지 않는다. 저장하지 않고 닫으면 "설정을 마치지 않으면 에이전트가 켜지지 않습니다. 시작 메뉴의 'RPA 설정' 에서 이어서 할 수 있습니다" 를 묻는다.

**맨 위 상태 줄:** 버전 (`check_install`), 에이전트 돌고 있음 / 꺼져 있음 (잠금이 있나). 감독이 다시 켜지 않고 끝났으면 그 까닭(`data\에이전트_멈춤.json`, 감독이 쓰고 켤 때 지운다)을 노란 글씨로 보이고, 로그인 거부(3)였으면 기계 계정 비밀번호 칸을 "새 비밀번호를 넣으세요" 로 필수로 바꾼다 - 그대로 저장해 켜면 몇 초 뒤 또 멈추는데 "켰습니다" 로 보이지 않게 (2026-09-29 검토). 막 켰으면 "켜는 중". ERPia 를 못 찾으면 위치 칸 옆과 저장 글에 알린다.

### 기존 폴더에서 가져오기
1. 폴더를 고른다 (옛 배포 폴더 - `Run_All.bat` 이 있는 곳. 없으면 옛 배포 폴더가 아니라고 알리고 가져오지도, 이름을 바꾸자고도 않는다 - 바탕화면 같은 곳의 이름을 바꾸면 안 되니까).
2. `<폴더>\RPA_UserConfig.json` 과 `<폴더>\firebase\agent\agent_config.json` 중 있는 것을 `config\` 로 복사한다. 둘 다 없으면 "설정 파일을 찾지 못했습니다". `config\` 에 이미 있으면 바꿀지 묻는다.
3. 칸을 다시 채운다. 잠긴 비밀번호는 같은 PC·같은 윈도우 계정이면 풀린다. 못 푸는 것(다른 PC·계정에서 잠근 값)은 그 칸을 필수로 바꾸고 다시 넣으라고 알린다.
4. 저장이 끝나면 **옛 폴더 이름을 바꿀지** 묻는다 (`<이름>_옮김`, 기본 예). 옛 바로 가기나 `에이전트_시작.bat` 으로 옛 에이전트가 다시 켜지면 두 에이전트가 같은 자동 실행 예약(바탕화면 `RPA_STATUS\settings.json`)으로 같은 시각에 RPA 를 띄우려 한다. 옛 코드에는 5절의 잠금이 없어서 새 에이전트가 막을 수 없다. 이름을 바꾸면 옛 바로 가기가 끊긴다. 파일은 그대로 남는다.

### 창 없는 모드
- `--after-install`: 두 설정 파일이 다 있고 읽히면 (잠긴 기계 계정 비밀번호까지 풀리면 - 판 올림) 창 없이 작업 등록·에이전트 켜기만 한다. 아니면 창을 띄운다 (처음 설치).
- `--stop`: RPA exe(`ERPia_RPA.exe`·`Prepare_RPA.exe`)가 돌면 5. 작업을 끝내고 잠금이 풀릴 때까지 15초 기다린다. 안 풀리면 6 (설치 폴더의 `에이전트_시작.bat` 창처럼 작업 밖에서 띄운 에이전트). 아니면 0.
- `--remove-task`: `--stop` 뒤 작업을 지운다.

## 5. 자동 시작과 감독

### 작업 `\AFTER MARKET\RPA Agent`
설정 창이 XML 로 등록한다 (`schtasks /Create /XML … /F`). 기본값을 믿지 않고 모두 적는다.

| 항목 | 값 | 기본값을 쓰면 |
|---|---|---|
| 트리거 | 그 윈도우 계정의 로그온 | |
| 계정 | 그 계정, 로그온했을 때만 (비밀번호 저장 안 함), 가장 높은 권한 | |
| 이미 돌고 있으면 | 새로 띄우지 않음 | |
| 배터리 | 배터리여도 켜고, 배터리로 바뀌어도 멈추지 않음 | 노트북에서 전원을 빼면 멈춘다 |
| 실행 시간 제한 | 없음 | 3일 뒤 멈춘다 |
| 우선순위 | 5 (보통) | 7 (낮음) - RPA 도 물려받아 느려진다 |
| 동작 | `{app}\python\pythonw.exe "{app}\firebase\agent\background.py"`, 시작 폴더 `{app}\firebase\agent` | |

### 감독 `background.py`
- `pythonw` 로 떠서 창이 없다. 에이전트는 `python.exe` + 창 없음(`CREATE_NO_WINDOW`) 으로 띄운다. 입력은 곧바로 닫는 파이프 (`isatty()` 가 거짓이라 에이전트가 사람에게 묻지 않는다. **`DEVNULL` 은 안 된다** - 윈도우의 NUL 은 문자 장치라 `isatty()` 가 참이 되어, 에이전트가 ERPia 고르기 창 같은 것을 보이지 않게 띄우고 멈춘다. 2026-09-29 시험에서 잡음), 출력은 UTF-8(`PYTHONUTF8=1` - 파일로 돌리면 CP949 로 찍다 못 찍는 글자에서 죽는다), 오류 출력은 `data\에이전트_오류.txt` 에 덧붙인다 (죽은 까닭을 남긴다).
- 에이전트를 감독 자신의 잡(job)에 넣는다 (`KILL_ON_JOB_CLOSE`): 감독이 죽으면 (작업 끝내기 포함) 에이전트도 같이 죽는다. 작업 스케줄러의 "끝내기" 는 자기가 띄운 프로세스만 끝내므로 이게 없으면 에이전트가 떠돈다.
- 에이전트가 띄운 RPA 는 잡에서 빠진다 (`SILENT_BREAKAWAY_OK`): 에이전트를 다시 켜도 도는 RPA 는 끝까지 간다. 새 에이전트는 RPA 상태 파일로 도는 것을 알아서 두 번 띄우지 않는다 (`rpa_dashboard.launch` 의 기존 검사).
- **확인 (2026-09-29, 이 PC, 관리자 권한 없는 시험 작업):** 작업 스케줄러는 작업을 자기 잡에 넣고(`IsProcessInJob` 참), 그 안에 우리 잡을 겹쳐 넣을 수 있다. "끝내기" 뒤 - 우리 잡이 없으면 감독만 죽고 에이전트는 떠돈다 / `KILL_ON_JOB_CLOSE` 만 있으면 에이전트와 RPA(새 콘솔로 띄운 손자) 모두 죽는다 / 둘 다 있으면 에이전트는 죽고 RPA 는 산다. 그래서 둘 다 쓴다.
- 종료 코드별:

| 코드 | 뜻 | 감독 |
|---|---|---|
| 0 | 정상 끝 | 같이 끝난다 |
| 2 | 설정 문제 (설정 파일 없음·깨짐) | 같이 끝난다 - "RPA 설정에서 설정을 마치세요" |
| 3 | 인증 멈춤 (비밀번호 바뀜·계정 막힘·시도 초과) | 같이 끝난다 - 틀린 비밀번호로 되풀이하면 계정이 잠긴다 |
| 4 | 이미 다른 에이전트가 돈다 | 같이 끝난다 |
| 그 밖 | 오류·강제 종료 | 10·30·60·120·300초 뒤 다시 켠다. 10분 넘게 돌았으면 10초부터 다시 |

- 감독이 끝나면 다음 윈도우 로그인이나 "RPA 설정" 저장 때 다시 켜진다.
- **윈도우 루트 인증서 (2026-09-29 샌드박스에서 찾음):** 갓 설치한 윈도우는 루트 인증서를 다 갖고 있지 않고(샌드박스 16개), 윈도우 자신의 통신(schannel)이 필요할 때 받아 온다. 파이썬(OpenSSL)은 저장소에 이미 있는 것만 봐서 Firebase 에 `CERTIFICATE_VERIFY_FAILED` 로 못 붙고, urllib 은 처음 읽은 인증서를 다시 안 읽어서(3.12+) 켜진 에이전트는 끝까지 못 붙는다. 그래서 감독은 에이전트를 켜기 전에, 설정 창은 기계 계정 로그인 전에 PowerShell `Invoke-WebRequest` 로 Firebase 주소(identitytoolkit·securetoken·firestore·RTDB)를 한 번씩 찔러 윈도우가 받아 오게 한다 (샌드박스에서 16 → 18개, 그 뒤 파이썬도 붙음). 인증서 오류는 "인터넷에 연결하지 못해" 가 아니라 "보안 인증서를 확인하지 못했습니다" 로 알린다.
- 기록: `data\에이전트_기록.txt` 에 `감독:` 으로 시작하는 줄 (에이전트와 같은 파일, 감독은 에이전트 코드를 불러오지 않는다 - 에이전트 파일이 깨져도 감독은 살아서 까닭을 남긴다).

### 에이전트 하나만
`agent.py` 가 켤 때 이름 있는 잠금(뮤텍스) `Local\AFTER_MARKET_RPA_AGENT` 을 잡는다. 이미 있으면 "이 PC 에서 에이전트가 이미 돌고 있습니다" 를 찍고 4 로 끝난다. 다른 권한으로 만든 잠금이라 열 수 없다(접근 거부)도 "있다" 로 본다. 시험은 `RPA_AGENT_MUTEX` 로 다른 이름을 쓴다 (개발 PC 에서 도는 진짜 에이전트와 부딪히지 않게). 설정 창의 "돌고 있음" 표시도 이 잠금을 본다.

## 6. 빌드

- **판에 넣는 파일:** `PROGRAM_FILES` 에 `rpa_settings.py`, `firebase/agent/background.py` 를 더한다 (판 목록 지문).
- **내장 파이썬 tkinter:** `D:\AX\runtime\python\Lib\tkinter` 가 빠져 있다 (`ensurepip`·`idlelib`·`site-packages` 와 함께 뺀 채 복사됐다). 같은 3.14.7 의 `Lib\tkinter` (0.7MB) 를 한 번 넣는다. Tcl/Tk 9 는 DLL 안에 들어 있어(zipfs) 더 넣을 것이 없다 (2026-09-29 확인: 임시 사본에서 `tkinter.Tk()` 가 떴다). 빌드는 모은 판 폴더의 내장 파이썬으로 `import tkinter` 를 해 보고 안 되면 멈춘다.
- **setup.exe:** Inno Setup 의 `ISCC.exe` 로 `release/installer.iss` 를 판 폴더에 대고 컴파일한다 (`/DAppVersion=… /DNumVersion=… /DSourceDir=…`). 찾는 자리: `%LOCALAPPDATA%\Programs\Inno Setup 6` (이 PC, 사용자 설치), `Program Files (x86)\Inno Setup 6`. 없으면 멈추고 안내한다. `--no-setup` 으로 건너뛸 수 있다.
- **`--exes-from <판 폴더>`:** 두 exe 를 새로 만들지 않고 그 폴더에서 가져온다 (exe 소스가 바뀌지 않은 판, 개발 중 빠른 반복 - Nuitka 두 개에 30분쯤 걸린다). 판 목록의 `builder` 칸은 그 폴더 판 목록의 값을 쓴다.
- zip 은 지금 그대로 만든다 (손으로 넘기는 대비책).
- `installer.iss` 는 BOM 있는 UTF-8 (Inno Setup 이 한글 글자를 그렇게 읽는다).

## 7. 옛 구조 PC 옮기기 (노트북 pc_a)

순서: `setup.exe` → 설치 → 설정 창 → (옛 에이전트 창이 켜져 있으면 닫으라고 함) → [기존 폴더에서 가져오기] → 확인·저장 → 옛 폴더 이름 바꾸기 → 대시보드에서 연결과 "버전 …" 확인.

- 잠근 비밀번호는 같은 PC·같은 윈도우 계정이면 옮겨도 풀린다. 아니면 그 칸만 다시 넣는다.
- 옛 폴더의 기록(큐·로그)은 가져오지 않는다. 옛 에이전트가 닫히기 전에 연결돼 있었다면 올리지 못한 기록은 없다.
- 개발 PC 는 옮기지 않는다 (진짜 `ProgramData\AFTER MARKET\RPA\config` 가 생기면 새 구조로 넘어간다).

## 8. 안전

- **비밀번호:** 설정 창에서 받은 값은 잠근 뒤 쓴다. 창의 다른 곳·기록·오류 글에 싣지 않는다. 설치 파일에는 빈 틀만 들어간다 - `setup.exe` 는 `verify_zip` 을 통과한 판 폴더로만 만든다.
- **권한:** `config`·`data` 는 관리자·SYSTEM 만 (세션 쿠키 평문, ERPia 위치 바꿔치기 막기 - 1부 2절). `Program Files` 는 원래 관리자만 쓴다.
- **계정:** 관리자가 아니거나 다른 계정으로 권한만 올린 설치는 멈춘다.
- **기계 계정:** 설치 파일이 만들지 않는다. 서비스 계정 키는 고객 PC 에 가지 않는다. 우리 PC 에서 `setup.js` 로 먼저 만들고 (비밀번호가 찍히니 사람이 직접), 설치하는 사람은 업체코드·PC코드·비밀번호를 받아 넣는다.

## 10. 하지 않는 것

자동 업데이트와 서명 (3부), 웹에서 설정 바꾸기, 코드 서명 인증서, 업체 정책(Hold=off)이 에이전트 시작 때 반영되지 않는 문제, 설정 창에서 실행 모듈 고르기 (웹이 한다), 옛 형식(`ERPIA_AI.txt` 만 있는) 폴더 가져오기 (그런 PC 는 에이전트가 켤 때 이미 `RPA_UserConfig.json` 으로 옮겼다), 옛 폴더 기록 옮기기.

## 11. 위험과 대비

| 위험 | 대비 |
|---|---|
| 다른 계정으로 권한만 올려 설치 | 설정 창이 멈추고 알린다 (4절 2) |
| 옛 에이전트와 새 에이전트가 같이 돎 | 설정 창이 옛 것을 닫게 하고, 옛 폴더 이름을 바꾸고, 새 코드끼리는 잠금 |
| 틀린 비밀번호로 끝없이 다시 켜 계정이 잠김 | 3 이면 감독도 끝난다 |
| 판을 올리는 중 RPA 가 돌아 파일이 잠김 | `--stop` 이 5, 설치가 안내하고 멈춘다 |
| 작업 기본값 (3일 제한·배터리·낮은 우선순위) | XML 로 모두 적고 시험이 본다 |
| 에이전트를 다시 켤 때 도는 RPA 가 죽음 | RPA 는 잡에서 빠진다 (5절, 실제 작업으로 확인함) |
| 내장 파이썬에 tkinter 가 없음 | 빌드가 `import tkinter` 로 확인하고 멈춘다 |
| 조용한 설치에서 설정 창이 기다리며 멈춤 | 조용한 설치에서는 띄우지 않는다 |
| SmartScreen 경고에 설치하는 사람이 놀람 | 안내문 |
