# 사이트 엑셀 업로드 (옵저버 다운로드/업로드) - 설계

2026-11-06 사용자와 정함. **코드는 들어가 있고 `rpa_status.EXCEL_UPLOAD_ON = False` 로 숨겨 둔 상태**다.
운송장번호 전송 메뉴를 고칠 때 이 문서의 "켜는 순서" 를 따른다.

## 1. 왜

ERPia [전송요청] 으로 운송장이 안 가는 사이트가 있다. 그런 사이트는 ERPia 에서 받은 운송장 엑셀을 쇼핑몰 관리자 화면에 사람이 올린다.
옵저버는 지금까지 "로그인 → 조작 → 엑셀 다운로드" 만 기록했는데, 반대 방향 "로그인 → 조작 → 엑셀 업로드" 도 기록하고 ACTOR 가 따라 하게 한다.

## 2. 흐름

1. **PROCESS (아직 안 만듦):** 운송장번호 전송 화면 → 옵저버의 사이트코드와 맞는 사이트만 검색 → 조회 → 전체 선택 → 엑셀 다운로드 →
   이름을 지어 `바탕화면\ERPIA_AI\ERPIA_AI_EXCEL\운송장` 에 넣는다 (2026-11-09 사용자 - 처음엔 `ERPIA_AI_UPLOAD`). 설정으로 전송요청만 / 엑셀만 / 둘 다를 고른다 ('사이트 엑셀 전송 옵션', 가칭).
   PROCESS 의 일은 **폴더에 넣는 데서 끝**이다.
2. **옵저버:** 프리셋 칸 하나를 써서 업로드 조작을 기록한다. 스위치로 다운로드/업로드를 고른다.
3. **ACTOR:** 기록을 따라 해 그 파일을 사이트에 올린다.

## 3. 약속 (PROCESS 를 만들 때 지킬 것)

- **파일 이름:** `(사이트코드)아무이름.xls(x)` - ACTOR 는 앞의 `(nnn)` 으로 프리셋을 찾는다.
- **폴더:** `ERPIA_AI_EXCEL\운송장` (2026-11-09 사용자, `rpa_status.UPLOAD_DIR_NAME`). `ERPIA_AI_EXCEL` 바로 아래에 넣으면 안 된다 - 거기 파일은 PROCESS 가 주문 엑셀로 ERPia 에 올린다.
- 같은 코드 파일이 여럿이면 가장 새 것을 쓰고 나머지는 `오류` 폴더로 간다 (ERPia 엑셀 업로드와 같은 규칙).

## 4. 언제 도나

예약기(`Scheduler.tick_upload`)가 본다. 설정이 따로 없다 - 폴더에 파일이 있는지만 본다. PROCESS 쪽 옵션이 꺼져 있으면 파일이 안 생겨 안 돈다.

- 조건: PROCESS 가 끝났고, 실행 중인 것이 없는 상태가 1분(`UPLOAD_WAIT_SEC`) 이어지고, 폴더에 파일이 있고, 이번 PROCESS 몫을 아직 시도하지 않았다.
- 전체 실행·단독 실행·반복 시간대를 나누지 않는다. 자동 실행을 꺼 둔 PC 에서도 돈다.
- **PROCESS 가 끝날 때마다 한 번만 시도한다.** 로그인 실패로 파일이 남아도 1분마다 다시 로그인하지 않는다 (사이트 계정 잠금).
- ERPia 는 PROCESS 가 끝나도 열려 있지만 ACTOR 는 Edge 에서 돌아 지장 없다.

실행: `Prepare_RPA.exe --all --upload --no-keep-open`. 보통 ACTOR 실행은 업로드 프리셋을 빼고, `--upload` 는 올릴 파일이 있는 업로드 프리셋만 돈다.

## 5. 성공 판단과 파일 정리

사이트마다 화면이 달라 **파일을 올리는 조작이 끝까지 가면 성공**으로 본다. 표의 칸 값 같은 것은 보지 않는다 (사용자 지시, 예시를 코드로 만들지 말 것).

| 상황 | 파일 |
|---|---|
| 끝까지 감 | `완료\YYYYMMDD` |
| 파일을 넣기 전에 멈춤 (로그인 실패 등) | 그대로 - 다음 PROCESS 뒤 다시 |
| 파일을 넣은 뒤 멈춤 | `오류` - 반영됐는지 몰라 사람이 본다 |

## 6. 옵저버 화면

- 스위치는 프리셋 칸 맨 위 줄. 끄면 `엑셀 다운로드`, 켜면 초록 `엑셀 업로드`. 업로드는 쇼핑몰 기록만.
- 업로드 프리셋 탭은 초록 둥근 바탕, 다운로드는 평소 모양.
- 업로드일 때 '주문 수집용 엑셀파일 경로' 줄 자리에 올릴 파일 안내가 나온다.
- 같은 사이트의 다운로드·업로드 프리셋은 사이트코드가 같아도 된다 (코드는 방향마다 하나).
- 기록에 파일을 넣는 단계가 없으면 저장을 막는다.
- **미리보기는 파일을 올리지 않는다.** 파일 단계에서 멈춘다 - 실제 사이트에 시험 파일이 올라가면 안 된다.

## 7. 기록·재생

- 기록: 파일 칸의 change 이벤트를 `file` 단계로 남긴다. 파일 이름만 (경로는 브라우저도 안 준다).
- 재생: 사이트의 [파일 선택] 을 눌러도 윈도우 파일 창이 안 뜨게 `filechooser` 를 받아 두고, `file` 단계가 파일 칸에 직접 넣는다. 숨긴 칸도 된다.
- **한계:** 문서에 붙이지 않고 스크립트로 만든 파일 칸은 change 가 문서까지 안 올라와 기록이 안 된다. 그런 사이트는 저장 때 막힌다.
  끌어다 놓기로만 올리는 사이트도 안 된다. 실제 사이트로는 아직 시험하지 않았다.

## 8. 토큰

따로 빼지 않는다 - 운송장번호 전송에 포함. 값은 관리 화면 토큰 배율로 올린다 (업체별 가능). 업로드 실행은 제목(`UPLOAD_TITLE`)으로 가려 `agent.usage` 가 세지 않는다.

## 9. 켜는 순서

1. PROCESS 운송장번호 전송 메뉴를 고친다 (3절 약속대로).
2. `rpa_status.EXCEL_UPLOAD_ON = True`.
3. 업로드 기록에 새 기록 버전을 준다 (`MAIL_RECORD_VERSION` 처럼) - 옛 ACTOR 가 `file` 단계를 잘못 따라 하지 않게.
4. `tests/test_excel_upload.py` 의 "출고 기본값은 꺼짐" 을 바꾼다.
5. 실제 사이트 한 곳에서 기록 → 업로드 확인. 7절 한계를 본다.
