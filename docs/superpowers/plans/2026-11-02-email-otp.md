# 메일 2차인증 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 옵저버로 기록한 쇼핑몰 프리셋이, 메일로 오는 2차인증(번호 복사·붙여넣기 또는 메일 속 링크)을 새 탭의 메일함에서 처리하게 한다.

**Architecture:** 휴대폰 문자 인증(설계 13절)의 `otp`/`otpSend`/다시 시도 틀을 넓힌다. 기록기 JS 가 copy·paste 를 적고, `finalize` 가
메일 인증 단계(`mailOpen`·`copyCode`·`otp source=copy`·`mailLink`·`MAIL_ID/MAIL_PW`)로 다듬는다. 재생기는 그 단계들을 '새 메일 찾기 →
번호 뽑기 → 넣기' 로 돌고, 실패하면 A 의 '인증 메일 보내기'부터 다시 (3번). 메일 계정은 `Sites.PRESETn` 에 `MailID`·`MailPW`(봉인).

**Tech Stack:** Python 3.14, Playwright(깔린 Edge), tkinter(옵저버). 시험은 `.venv\Scripts\python.exe tests\X.py` (assert 모음 스크립트).

**Spec:** `docs/superpowers/specs/2026-11-02-email-otp-design.md` (사용자 승인·화면 글 검수 2026-11-02)

## Global Constraints

- 화면 글은 설계서 6절 **글자 그대로**. 휴대폰과 같은 글이라고 한 거절 문구는 지금 코드의 글 `사이트에서 인증번호가 {OTP_TRIES}번 거절되었습니다.` 를 그대로 쓴다.
- 다시 시도는 모두 `OTP_TRIES` (=3)번, 메일 기다리기는 시도마다 최대 `OTP_WAIT` 와 같은 2분.
- 복사한 번호·메일 계정 아이디/비밀번호는 기록 파일·로그(`hide_values` 와 상관없이)·대시보드·서버·프리셋 내보내기에 없다.
- 실제 윈도우 클립보드를 읽거나 쓰지 않는다. 재생 때 번호는 `Replayer.mail_code` 에만.
- 메일 계정은 `rpa_status.seal/unseal` 로 봉인, `Sites.PRESETn` 의 `MailID`·`MailPW`. 계정은 메일함 호스트(`MAIL_PW` 단계의 `host`)에만 넣는다.
- 프리셋 하나에 메일 인증 하나·메일 계정 한 벌.
- 비밀번호·토큰·계정 값은 시험 출력에도 찍지 않는다. 실제 쇼핑몰·메일함은 두드리지 않는다 (시험은 가짜 사이트).
- 글은 `docs/ui-wording.md` 업무 서식. 코드 주석은 주변처럼 한국어 짧게.

## Review Focus

1. 메일 제목에 번호가 든 메일함 ("인증번호 [482913] 안내") - 줄 모양에서 숫자를 빼므로 매 실행 같은 줄로 찾아야 한다. → Task 3 시험 `subject_with_code`.
2. 줄에 받은 시각이 안 보이는 메일함 + 목록 맨 위에 옛 인증 메일 (첫 실행이라 기억이 비었음) - 옛 번호로 거절당한 뒤 다시 시도에서 새 메일을 열어 통과해야 한다. → Task 3 시험 `old_mail_no_time`.
3. 붙여넣기를 마우스 오른쪽 메뉴로 한 경우 - `paste` 이벤트로 알아보므로 Ctrl+V 와 똑같이 `otp source=copy` 가 되어야 한다. → Task 2 시험 (paste 이벤트만 쓰는지 assert).
4. A 의 로그인 자체가 팝업 창(page 1)에서 일어나는 쇼핑몰 - '첫 비밀번호 창 = A' 규칙이므로 A 계정이 `PW`, 메일함만 `MAIL_PW` 여야 한다. → Task 1 시험 `a_login_in_popup`.
5. 병렬 수집으로 메일 인증 프리셋 둘이 동시에 - 번호는 재생기마다 따로여야 한다. → Task 3 시험 `two_replayers` (Replayer 둘을 번갈아 돌려 서로의 `mail_code` 가 섞이지 않음).
