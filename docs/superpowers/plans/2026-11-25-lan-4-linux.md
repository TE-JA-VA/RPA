# 사내 서버 ④ 리눅스에 싣기 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사내 서버를 리눅스 서버에 설치 파일 하나로 깔아 systemd 서비스로 돌린다 - 내장 파이썬, 서버 입구와 관리 명령(`autopilot-server`), 서버 라이선스와 자리 증명서, 폴더 권한, 기록 파일, 백업과 복구, `install.sh`, 그리고 NT 첫 설치.

**Architecture:** 서버 코드는 ①~③ 의 `local_server`·`local_web`·`lan_*` 그대로이고, 리눅스에서 켜는 입구 `server_main.py` 가 경로(`/etc`·`/var/lib`·`/var/log/autopilot`)와 라이선스·인증서·등록부를 모아 `lan_server.make_lan_servers` 로 두 포트를 연다. 윈도우 전용 자리(`icacls`, 창 없는 깃발, 주소 다시 쓰기)는 `os.name` 으로 가른다. 설치 파일은 `tools/build_server.py` 가 내장 파이썬(python-build-standalone)과 서버 파일, 웹 파일, 서명된 버전 목록, `install.sh`, systemd 단위로 묶는다. 휴대폰 포트(8782)는 ⑧ 에서 연다 - 이번에는 열지 않는다.

**Tech Stack:** 파이썬 3.14 표준 라이브러리, POSIX sh(`install.sh`), systemd, openssl 명령(서버의 것), 시험은 plain python + WSL(Ubuntu, Python 3.14.4, OpenSSL 3.5.5) + NT(Ubuntu 24.04.5, Python 3.12.3, OpenSSL 3.0.13 - 서버는 내장 파이썬으로 돈다).

**Spec:** `docs/superpowers/specs/2026-11-24-standalone-linux-server-design.md` 4.3, 6.2, 6.3 (방화벽·인증서 ①②), 6.8, 8절 ①②, 9절, 10절 NT 줄, 13절 9, 14절 ④. 목록 `docs/superpowers/plans/2026-11-24-lan-index.md` 에서 ④ 로 넘긴 것: M-8, 보류 1, ②-T2, ②-T8, ②검-3·4·5·6·7·9·10, ②보-1·2, ③-1, ③검-1·8·9, ③보-1·2.

## Global Constraints

- 작업 폴더 `D:\AX\RPA_StandAlone`, 브랜치 `StandAlone`. 파이썬 `D:\AX\RPA\.venv\Scripts\python.exe`, cwd 작업 폴더, `$env:PYTHONUTF8="1"`. `D:\AX\RPA` 의 파일은 절대 고치지 않는다 (PowerShell 에서 .NET 메서드에 상대 경로 금지 - 그 폴더로 풀린다).
- 단독(나)은 그대로: `local_server.main()`·`make_server` 의 응답·상수·파일이 지금과 같고 `run_standalone_suite.py all` 이 '실패한 파일: 0'.
- 서버 코드는 표준 라이브러리만, 바깥 연결을 여는 코드 없음, 이름 풀이 없음 (설계 8절). openssl 은 자식 프로세스·인자 목록·30초 제한.
- 경로 (설계 6.2): 프로그램 `/opt/autopilot/releases/<버전>/` + 링크 `/opt/autopilot/current` (root, 서비스는 읽기만), 설정 `/etc/autopilot/` (`server.json`, `license.json` - 서비스 읽기만, `ca/` 인증 기관 열쇠 - root 만 700, 인증 기관 **공개** 인증서는 설치가 `/var/lib/autopilot/tls/` 에 사본으로), 자료 `/var/lib/autopilot/` (서비스 계정만, 폴더 700·파일 600), 기록 `/var/log/autopilot/` (`server.log`, `audit.log`, 10MB 다섯 개), root 설정 백업 `/var/backups/autopilot/` (root 600).
- **서비스 계정 이름은 `autopilotd`** (Codex 검토 14, 사용자 2026-11-25 - 설계의 `autopilot` 은 NT 의 사람 로그인 계정과 겹친다). 같은 이름의 계정이 이미 있는데 시스템 계정(nologin)이 아니면 설치를 멈춘다.
- **서비스 잠금**: 서비스는 켜져 있는 동안 `/var/lib/autopilot/.service.lock` 을 `fcntl.flock` 으로 쥔다. 복구·`admin-reset` 은 이 잠금을 잡아 서비스가 멈췄는지 확인하고(포트 연결 여부로 판단하지 않는다), 작업 동안 쥐고 있어 그 사이 서비스가 켜지면 서비스가 잠금을 못 잡고 종료 코드 4 로 끝난다 (Codex 검토 6·10).
- **자료 형식 번호**: `/var/lib/autopilot/FORMAT` (지금 1). 서비스는 자기가 아는 것보다 큰 번호면 4 로 멈추고, 설치는 형식 번호가 낮은 옛 버전으로 되돌리기를 거절한다 (Codex 검토 5).
- 종료 코드: 0 정상, 2 라이선스 (systemd 가 다시 켜지 않음), 3 포트를 못 엶, 4 설정·자료가 깨짐·잠금을 못 잡음 (다시 켜지 않음).
- **처음 설치 파일 믿기** (Codex 검토 1, 사용자 2026-11-25): 설치 파일의 SHA-256 을 우리가 **다른 길(메일과 전화 등)** 로 업체에 알리고, 업체는 리눅스에 원래 있는 `sha256sum -c` 로 먼저 맞춘다. `install.sh` 는 `--expect-sha256 <값>` 을 받아 자기 묶음 파일과 견주고 다르면 아무것도 하지 않는다. 업그레이드는 **이미 깔린** `autopilot-server upgrade` 가 새 파일의 서명을 실린 공개 열쇠로 먼저 확인한 뒤에만 풀고 실행한다.
- 기록·응답에 열쇠, 비밀번호, 세션 토큰, 인증번호, 2단계 비밀 값, 자리 서명 열쇠를 싣지 않는다.
- 서명 열쇠(업데이트·라이선스)는 Claude 가 읽지 않는다 - 도구에 경로만 넘긴다. 시험은 임시 열쇠를 만들어 쓴다.
- 바깥 사이트에서 받는 것(내장 파이썬)은 사용자 허락 뒤에만 받고, 받은 파일의 SHA-256 을 `tools/linux_runtime.json` 에 적어 고정한다.
- NT 에서 root 가 필요한 일(설치, 방화벽, 재부팅, 스냅숏)은 Claude 가 하지 않는다 - 명령을 적어 VM 세션('세션 ID 요청')에 보내고, VM 세션이 사용자 확인을 받아 실행한다. Claude 는 `autopilot` 계정 SSH(열쇠 `%USERPROFILE%\.ssh\nt_autopilot`)로 읽기와 일반 명령만.
- 화면·기록 글은 한국어 업무 말투 ('버전', '페어링', '묶음' 금지). 리눅스 관리자용 파일 이름과 명령은 영문.
- 커밋은 작업마다 `git commit -F <새 이름의 메시지 파일>`, BOM 없이, 끝줄 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. push 는 사용자 말이 있을 때만. 끝나면 `graphify update .`.

1. 설치나 업그레이드가 어느 단계에서 끊겨도(서명 틀림, 링크를 바꾼 직후 디스크 부족, systemctl 실패, 스크립트 중단) 반쯤 깔린 상태가 남지 않고 `current` 는 이전 버전을, 서비스는 이전 버전 프로세스를 돌린다 - Task 8 `test_install_fails_clean`, `test_interrupt_after_link`.
2. 업그레이드 뒤 **실제로 도는 프로세스가 알리는 버전**(`run.json`)이 30초 안에 새 버전이 아니면 `current` 를 되돌리고 옛 버전을 다시 켠다 - Task 8 `test_upgrade_rollback`, `test_upgrade_restarts`.
3. `pcs.json` 이나 `store.json` 이 깨진 채 켜지면 PC 번호를 pc_01 부터 다시 매기지 않고 종료 코드 4 로 멈춘다 (M-8) - Task 3 `test_broken_registry_refuses`.
4. 백업은 등록부·저장소·계정·두 DB 가 **같은 시점**이고(복구 뒤 등록부에 없는 PC 의 명령이 없다), 복구 중에는 서비스가 켜지지 않는다 - Task 5 `test_backup_consistent_snapshot`, `test_restore_holds_lock`.
