# 사내 서버 ⑤ PC 쪽 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 스탠드얼론 윈도우 PC 가 '사내 서버 등록' 으로 사내 서버에 붙어 돌게 한다 - 등록, 연결 방식 판정, 자리 증명서로 켜기(ap_guard), 감독이 로컬 서버를 띄우지 않음, 사용 중지·지워짐 처리, 설치 파일.

**Architecture:** 연결 방식은 화면 스위치가 아니라 파일로 정한다. PC 번호 라이선스(`license.json`)가 있으면 단독, 사내 서버 연결 파일(`standalone\server_link.json` - 서버가 준 자리 증명서·서버 라이선스 사본·열쇠 둘·주소·인증 기관)이 있으면 사내 서버, 둘 다 있으면 켜지지 않는다. 확인은 `license_check` 한 곳(컴파일 조각)이 하고 ap_guard·secret·감독·설정 창이 그 결과를 쓴다. 단독(나)은 지금 동작 그대로다.

**Tech Stack:** 파이썬 3.14 표준 라이브러리, 저장소의 `update_sign`(Ed25519)·`local_store`·`pc_registry`, tkinter 설정 창, Inno Setup.

**Spec:** `docs/superpowers/specs/2026-11-24-standalone-linux-server-design.md` (6.1·6.3 ②·6.4·6.8·8 PC·9 끝·13절 10), 목록 `docs/superpowers/plans/2026-11-24-lan-index.md` ⑤ 줄.

## Global Constraints

- 단독(나)의 동작·화면 글·종료 코드는 한 글자도 바뀌지 않는다. 연결 파일이 없으면 지금 길 그대로 (6.1 "단독의 배치 설정 값은 지금 동작과 한 글자도 다르지 않아야"). `tests/run_standalone_suite.py sa`·`cloud` 가 지금처럼 통과해야 한다.
- 일반(클라우드) 버전 경로는 새 코드를 불러오지 않는다 (`edition.is_standalone()` 이 거짓이면 지금과 같다).
- 둘 다 있거나 연결 파일이 맞지 않으면 켜지지 않는다 (fail-closed, 6.1).
- PC 는 서버에 묻지 않고 PC 안에서 확인한다 - 서버가 꺼져 있어도 PROCESS·ACTOR·옵저버가 켜진다 (6.8).
- 사설 대역이 아닌 서버 주소로는 등록하지 않는다 (8절 PC) - `local_store._lan_tls` 가 이미 막는다, 바꾸지 않는다.
- 열쇠·토큰·증명·인증 기관 열쇠는 기록·화면·오류 글에 싣지 않는다. 연결 파일은 관리자·SYSTEM 만 읽는다 (6.4-5, `local_server.lock_key_files`).
- 사람에게 보이는 글은 업무 서식 한국어 ('~하여 주십시오'), '버전'·'페어링' (판·짝짓기 금지).
- 시험은 저장소 방식 그대로 - 스크립트 파일 하나가 `check(이름, 조건)` 로 번호를 찍고 실패 수로 끝난다. 돌리는 파이썬은 `D:\AX\RPA\.venv\Scripts\python.exe`.
- 서버 쪽 코드는 Task 4 의 등록 글 `web` 칸 하나만 바꾼다 (그래서 NT 실기 전에 서버 빌드 -6 이 필요하다).

## Review Focus

1. 등록 글이 만료(10분)됐거나, 이미 쓴 글을 다시 넣거나, 자리가 찼다 → 설정 창이 서버 거절 코드(`expired`·`unknown`·`duplicate`·`seats`)를 사람 말로 보이고 아무 파일도 쓰지 않는다 (Task 6 시험).
2. 서버가 꺼진 채 PC 를 켰다 → exe 셋은 켜지고(로컬 확인만), 에이전트는 연결 오류로 기다렸다 다시 붙는다 - 사용 중지 멈춤으로 잘못 끝나지 않는다 (Task 2·5 시험).
3. 단독 라이선스와 연결 파일이 함께 있다 (단독 PC 에 등록을 시도했거나 파일을 복사해 넣음) → 모든 exe 가 같은 까닭으로 막히고 설정 창은 등록을 거절한다 (Task 1·6 시험).
4. 다른 PC 에서 복사한 연결 파일 → 자리 증명서의 PC 번호(MachineGuid)가 달라 막힌다 (Task 1 시험).
5. 등록 응답이 끊기거나 서명이 틀리거나 자리 증명서가 빠졌다 → 연결 파일을 쓰지 않고 있던 상태가 남는다 (Task 3·6 시험).
