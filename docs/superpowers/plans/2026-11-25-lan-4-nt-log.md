## 4. 개발 PC 에서 확인 - 끝

### 4-1. TLS 와 Host 규칙 (`nt_test.py check` 에 옮긴 확인)

- 두 포트 모두 TLS 1.3 (TLS_AES_256_GCM_SHA384).
- 인증서는 CN=AUTOPILOT LAN Server, 발급자 AUTOPILOT LAN CA, SAN IP 192.168.1.230, 용도 serverAuth, 기간 2026-11-25 ~ 2027-12-28.
- `GET /` 에 Host `192.168.1.230:8443` 을 주면 200 로그인 화면. 포트 없는 Host(`192.168.1.230`)와 엉뚱한 Host 는 403
  ('서버 주소로 접속하여 주십시오').
- 응답 머리글에 HSTS, CSP, `X-Frame-Options: DENY` 가 있다.

## 8. nginx 앞에 세우기 - 끝

개발 PC(192.168.1.33)의 확인 스크립트가 443 으로 두 단계 로그인을 하면서 `X-Forwarded-For: 10.9.9.9` 를 일부러 넣고,
`/api/logins/me` 의 최근 주소가 개발 PC 인지 본다. 현황 구독을 연 채 1분마다 에이전트(8444 직접) 표식을 보내 3초 안에 오는지 센다.

| 모양 | 설정 | 결과 |
|---|---|---|
| (ㄱ) 443 TLS → 8443 TLS | `trusted_proxies: ["192.168.1.230"]`, `public_web: ["192.168.1.230"]` | `proxy_ssl_verify on` + `proxy_ssl_name 192.168.1.230` 은 502 (`upstream SSL certificate does not match "192.168.1.230"`). nginx 1.24 가 IP SAN 과 대조하지 못한다. 같은 장비라 `off` 로 바꿔 이어 감 |
| (ㄱ) | 위 + `proxy_ssl_verify off` | 8/8: 443 TLS 1.3, 포트 없는 Host 200, 엉뚱한 Host 403, 두 단계 로그인, 로그인 이력 = 192.168.1.33 (위조 주소·nginx 주소 아님), 6분 구독 6/6, 8443 직접 열림 |
| (ㄱ) + `proxy_only` | 위 + `proxy_only: true` | 8/8, 2분 구독 2/2, 8443 직접은 TLS 전에 닫힘 (호스트 PC 에서도 curl 35) |
| (ㄴ) 같은 장비 평문 | `web_plain`, `trusted_proxies: ["127.0.0.1"]`, `proxy_secret` 64자 | 8/8, 5분 구독 5/5, 8443 은 127.0.0.1 에만 열려 밖에서 닿지 않음 |
| (ㄴ) 다른 계정의 프록시 행세 | 사람 계정 `autopilot` 으로 127.0.0.1:8443 평문, 비밀 머리글 없음·틀림·머리글 없음 × `GET /`·`POST /api/login` | 6/6 403 '프록시를 거쳐 접속하여 주십시오.' |
| 되돌린 뒤 | nginx 멈춤·끔, `server.json` 원본(지문이 설치 때와 같음), ufw 443 규칙 지움 | 재확인 9/9 |

알게 된 것 (끝 검토와 ⑩ 안내서로):
- nginx 와 서버가 다른 장비면 인증서에 DNS 이름이 있어야 `proxy_ssl_verify on` 을 쓸 수 있다. 인증 기관의 이름 제한은 설치 때의 `names` 로 걸리므로
  설치 뒤 `names` 에 이름을 더해도 소용없다 - 처음 설치 때 `--names` 로 넣어야 한다.
- (ㄱ) 같은 장비의 `trusted_proxies` 는 127.0.0.1 이 아니라 서버의 listen 주소다 (nginx 가 그 주소로 붙는다). `nginx-example.conf` 주석을 고친다.
- `proxy_secret` 을 `sudo VAR=값 명령` 으로 넘기면 sudo 의 argv 와 기록에 남는다. VM 세션은 root python 안에서 만들어 두 파일에 바로 썼다.
  안내서나 관리 명령이 이렇게 만들게 한다.
- `nginx -s reload` 직후 바로 확인하면 옛 작업 프로세스가 받아 한 번 더 502 가 날 수 있다 (2초 뒤 200). 확인 단계에 짧은 대기를 둔다.

## NT 로 확인하지 못한 것

- `/var/tmp` 와 `/opt` 가 다른 파일 시스템일 때의 이동 (NT 는 디스크 하나).
- 허용 대역 밖에서 붙어 보기 (NT 는 사무실 망 하나) - 다른 망의 PC 로 사람이 한 번 보거나 업체 환경에서.
- SELinux enforcing 배포판 (NT 는 AppArmor 만).
